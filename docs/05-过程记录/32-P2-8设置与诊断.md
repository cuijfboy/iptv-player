## 3. 设置页骨架（派单项 1）

**入口**：浏览页页头第三个按钮「设置」（`@id/open_settings`）→ `SettingsContract.ACTION_SETTINGS`（action + `setPackage`，`:feature:channels` 不依赖 `:feature:settings`，docs/02 §3.2）。

**分组与行**（`SettingsCatalog.build`，顺序即遥控器的焦点路径）：

| 组 | 行 | 目的地 | 说明 |
|---|---|---|---|
| 源 | 订阅源管理 | `SourceManagementActivity`（P2-6） | **不重复实现**，直接进入既有页 |
| 源 | 最近刷新 | 值 | 来自 `SourceManagementPort.lastFetchAtMs/entryCount` |
| 播放 | 播放避让（P2-5 定时刷新） | 值 | 报告冻结策略（在播时最多顺延 3 次 / 30 min） |
| 刷新 | 每日定时刷新 | 值 | `RefreshScheduleSettings`（默认 `06:00`） |
| 诊断 | 诊断面板 | `DiagnosticsActivity`（本轮） | |
| 诊断 | 日志与设备 | `core:log` 的 `LogConsoleActivity`（P0-6 + P1-8） | **不重复实现**，直接进入既有页 |
| 诊断 | 记录级别（LogBus） | 动作 | INFO → DEBUG → VERBOSE 轮换（与 P0-6 控制台同一旋钮、同一循环） |
| 诊断 | 写入日志文件 | 动作 | `FileSink.enabled`（docs/03 §14） |
| 关于 | 应用版本 / 设备 | 值 | `DeviceInfo.appVersion/deviceSummary` |

**遥控与焦点（§8.2）**：每行是独立 `focusable` 的 `LinearLayout`，焦点态 = 描边 + 底色（`settings_row_background.xml`，非系统高亮）；组标题 `focusable="false"`，UP/DOWN 只落在行上；首次渲染把焦点放到第一行（不是最后一行的回退），重渲染按 `tag=行 id` 还原焦点（开关切完焦点不丢）。

**返回层级（§8.1）**：`SettingsHierarchy.parentOf` 把层级写成可断言的数据——`设置 → 浏览页`、`诊断 → 设置页`；设置页用同一张表决定页头提示（截图即证据），Activity 侧 BACK 就是 `finish()`（诊断由设置打开，天然回到设置）。

## 4. 诊断面板（派单项 2 / L4·L5）

### 4.1 运行概览（§7.1）

面板左栏，`DiagOverview.build(input)` 产出的 blocks，**字段清单**（= 导出包 `overview.txt` 的内容）：

| 区块 | 字段 |
|---|---|
| 设备 | 机型、ABI、Android SDK、内存（已用/上限 MB）、存储（可用/共）、网络（Wi-Fi/有线/蜂窝/VPN + 已验证） |
| 应用 | 版本、日志级别、文件日志开关、内存环（size/capacity）、日志文件（份数/字节/活跃文件/异常原因） |
| 数据 | 频道、分组、流、隐藏/收藏 |
| 源健康 | 订阅（共/启用）、结果（成功/失败/未取回）、最近刷新、每源一行（启用状态 + 上次成功条数 / 上次失败 / 尚未取回） |
| 播放 | 起播次数/出画次数、最近起播耗时 `costMs`、故障转移次数、最近失败码（含 `errCategory`） |

**数据来源（不另造通道）**：`ChannelRepository.observe(...).first()`、`SourceManagementPort.list()`、`PlaybackAvoidancePolicy` 冻结值、`RefreshScheduleSettings`、注入的同一个 `MemoryRingSink`/`LogBus`/`FileSink` 单例、`DeviceInfo` + `StatFs`/`ConnectivityManager`。播放块是**从日志环里读** `PLAY_PREPARE_START` / `PLAY_FIRST_FRAME` / `PLAY_PREPARE_FAIL` / `PLAY_FAILOVER`（§3.3.1 要求播放路径必打的码），因此没有新增表、没有新增缓冲。

### 4.2 实时日志（§7.2）

右栏 = `MemoryRingSink.tail`（**复用同一个环，不新开缓冲**）→ `DiagLogFilter.apply`：

- **级别**：`VERBOSE→…→FATAL` 全环轮换（视图过滤，不改记录级别）；
- **分类**：`全部` + 11 个 `LogCategory` 轮换；
- **搜索**：事件码 / 文案 / 分类名 / `fields` 键与值（大小写不敏感）；
- **按会话**：`DiagLogQuery.sessionId` 折叠一次刷新/播放（UI 上由搜索框输入 `refresh-…`/`play-…` 命中）；
- **暂停/继续 + 自动滚屏**、**复制日志到剪贴板**（§7.3）、**清理内存环**（§7.3）；每行显示 `elapsedMs/级别/分类/码/文案/字段/sessionId`。
- 显示上限 200 行（尾部）：2000 条的环不会每秒整环渲染。

**记录级别 vs 显示级别**：面板页头同时打印 `显示 <过滤条件>｜记录级别 <LogBus.minLevel>`，避免「为什么 DEBUG 看不到」这类误判——把记录级别调高在设置页那一行（同一个 `LogBus` 旋钮）。

## 5. 一键导出诊断包（派单项 3 / L8）

**落点**：`files/export/iptv-diag-<yyyyMMdd-HHmmss>.zip`（app 自己的外部目录，无需存储权限）。

```
iptv-diag-20260922-080102.zip
├── meta.json       版本 / 构建类型 / 设备(机型·ABI·SDK) / 内存 / 存储 / 网络 / 导出时间 / 设置快照(日志级别·文件开关·刷新时间·内存环)
├── stats.json      运行概览的机器可读形式（频道·分组·流·隐藏·收藏 / 各源 label·url·enabled·entries·lastFetchAt·lastResult / 播放汇总 / 日志文件计数）
├── overview.txt    上面 §4.1 的人读版本
├── logs/iptv-*.log 日志目录里的全部文件，逐行再脱敏
└── README.txt      包内容 + 脱敏规则 + 两种取包方式
```

**脱敏（docs/03 §11，W7 边界）**：打包前对**每一条字符串**再跑一次生产 `Redactor`——文本/日志行逐行 `redact`，JSON 值经 `DiagJson.encode(value, redactor)`。本轮同时补齐了 §11 规则 2：

| 规则 | 输入 | 导出包里的样子 |
|---|---|---|
| 账号口令（userinfo） | `rtsp://user:pw@host:554/live` | `rtsp://***@host:554/b82f9d7d`（路径 hash） |
| 查询参数（`token`/`key`/`pwd`/`pass`/`sign`/`auth`/`secret`/`expire`） | 取回值 | 掩成 `***` |
| **路径（本轮新增）** | `https://portal.example.com/live/user/secretkey/1.m3u8` | `https://portal.example.com/fc4bd64e` |
| 非敏感参数（§11 未列） | `…&user=qa` | 保留（仍有排查价值） |

`Redactor` 现在是**幂等**的（`/[0-9a-f]{8}` 形态不再二次哈希），所以「库内已脱敏的日志行」与「导入包里的行」完全一致——单测 `redaction is idempotent, so the package matches what the console showed` 断言了这一点。

**过程与失败**：导出在 `Dispatchers.IO` 上跑，`DiagPackageWriter.write(..., onProgress)` 逐段回调（写入 meta → 汇总统计 → 打包日志 → 完成），面板显示 `ProgressBar` + 页头进度文案，期间导出按钮禁用（防重入）。失败**返回 `DiagPackageResult.Failed(可读原因)`**（不抛异常），面板弹「导出失败：<原因>」并把原因写进日志。

**取包方式**（成功后弹窗 + `README.txt` 同时给出）：`adb pull /sdcard/Android/data/ilab.iptv.player/files/export ./tv-diag`；电视上直接看 `内部存储/Android/data/ilab.iptv.player/files/export`。

**导出前先 flush**：`logger.flush(2000)`，保证刚触发的这几条事件已经落盘进包，而不是还在派发队列里。
