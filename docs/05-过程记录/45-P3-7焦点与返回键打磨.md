## 2. BACK 行为对照表

### 2.1 逐页对照（含实现点位与结论）

层级用语：**框架层** = 独立窗口的对话框（Android 先于 Activity 消费 BACK）；**页内层** = 本页自己的状态机先吃一次 BACK；**屏幕层** = 由返回栈/`finish` 完成。

| 页面 | BACK 应有行为 | 实现点位 | 本轮结论 |
|---|---|---|---|
| **首启向导**（P2-9，本轮未实现） | 顶层：退出向导 | —（`worker-dev-a-28` 并行） | **未做**（表内留位，见 §8） |
| **主页壳（`MainActivity`）** | 顶层：退出 App | 框架默认（`activity_main.xml` 两个按钮可聚焦） | 一致；**不在 §8.1 冻结导航图内**（P0 占位壳，正式入口是浏览页） |
| **浏览页 · 列表** | 屏幕层 → **系统（App 根）** | 框架默认 `finish()`；`BackHierarchy.parentOf(BROWSE) = null` | 一致（新增单测钉住） |
| **浏览页 · 管理模式** | 页内层：退出管理模式，留在浏览页 | `BrowseBackPolicy.decide(manageActive)` → `viewModel.toggleManage()`；`OnBackPressedCallback` 只在管理模式拦截 | 一致（规则提取为纯函数 + 单测） |
| **浏览页 · 任一对话框**（导入选择/单频道动作/改名/频道号/批量动作/移动分组/EPG 绑定） | 框架层：关对话框，焦点回原行 | `AlertDialog` 独立窗口 | 一致（框架先消费；焦点由窗口归还） |

| **播放页 · 信息条已收（含失败卡片可见）** | 屏幕层：回浏览页 | `BackAction.ExitPlayer` → `finishWithResult()`（`RESULT_OK` + `channelId`） | **本轮更正**：旧注释声称「失败卡片也是一个层级」，代码从未武装它；按 §8.2 冻结原文「信息条可见 → 先收起信息条；再按 → 回浏览页」，卡片不可关、**不消耗 BACK**，注释与实测对齐并加单测 |

## 3. 焦点态统一

审前「焦点态」在五个地方是五套视觉：浏览行描边 `#FF6FC3FF`、搜索键盘/结果 `#FFFFB84D`（琥珀）、设置行 `#FF7AC7FF`、播放页控件白描边 + 琥珀填充，EPG 网格又是自绘的另一组（`#FF1E2833` 行高亮 + `#FFFFD166` 选中描边）。

**统一口径（三选一里的「描边 + 高亮」组合，缩放只保留已有实现）**：一个强调色描边 + 一档高亮填充，宽度 2 dp；视频之上的控件保留**暖色填充**（唯一的书面例外，理由写进 token 文件本身）。

| 屏 | 审前焦点 | 审后焦点 | 变化 |
|---|---|---|---|
| 浏览页行 | `#FF2A3550` + `#FF6FC3FF` 2dp | `@color/focus_fill` + `@color/focus_stroke` 2dp | 描边换统一强调色 |
| 搜索键盘 / 结果行 | `#FF2A2A38` + `#FFFFB84D` 2dp | 同上 | **琥珀 → 统一强调色**（全 App 唯一一处异色焦点消失） |
| 设置页行 | `#FF2B2B3C` + `#FF7AC7FF` 2dp | 同上（token 取自此处原值） | 保持，改为引用 token |
| 播放页控件（视频之上） | 琥珀填充 + **白色** 3dp 描边 | `@color/focus_fill_over_video` + `@color/focus_stroke` 2dp | 描边统一；填充保留暖色（书面例外） |
| EPG 网格（自绘） | 行高亮 `#FF1E2833`、选中块描边 `#FFFFD166` | `TvFocus.FILL` / `TvFocus.STROKE` | 网格焦点与 View 焦点同色 |

**token 的单一事实源**：`:core:design` 新增 `values/colors.xml` + `values/dimens.xml`（View 侧读资源）与 `TvFocus.kt`（纯 Kotlin 常量；EPG 渲染器是纯 Kotlin 且不能读资源）。两者必须相同，由 `TvFocusTokenTest` 读回 XML 逐值比对——「统一」是可核对的，而不是一句声明。

系统默认高亮（`android:defaultFocusHighlightEnabled`）无需逐屏关闭：它只在「背景不含 `state_focused`」时才绘制，而本轮所有行/键/按钮的背景都是含 `state_focused` 的 selector，默认高亮本来就不会叠加；EPG 网格是画布自绘、无 selector，已显式关闭（API 26+）。此点写入 §9 供 arch 复核定稿。

## 4. 信息条复核（淡出时机 × 按键交互）

**P1-5 修过的两处竞态仍在位且正确**（复读 `PlayerActivity.showInfoBar/hideInfoBar`）：

1. 淡出中按键必须能重新唤醒：`showInfoBar()` 判 `visibility != VISIBLE || alpha < 1f` 就 cancel 动画并重新淡入，淡出动画的 end action 只在 `!visibility.visible` 时才 `GONE`——晚到的回调不会把刚唤醒的信息条按下去；
2. 定时器一次性：`InfoBarVisibility.tick()` 只在越过 `hideAtMs` 的那一次返回 true，`hideRunnable` 每次 `show` 都重排（`removeCallbacks` + `postDelayed`），不会重复淡出。

**本轮新增复核（三个交错序列，全部进单测）**：按键在淡出中 → 计时重置且下一次 BACK 是「收信息条」；自动淡出后 BACK 直接退出（不吞一级）；信息条收起后 BACK 退出（即使失败卡片仍在）。

**本轮唯一更正的「不一致」**：`PlayerBackPolicy` 的 KDoc 称「失败弹层同样是一个层级」，而 `PlayerActivity` 从未在弹层出现时武装该层级（只有信息条会武装）。按 §8.2 冻结原文（层级只写「信息条可见」），**卡片是页面状态、不是可关闭层**：卡片在、信息条已收时按 BACK 直接退出播放。已改注释 + 加 `PlayerBackPolicyTest` 一条钉住，不改任何键位。

**「信息条与其他页面不打架」**：播放页、EPG 网格、搜索、频道管理器、设置/诊断各自是独立 Activity（各自一个窗口），信息条只存在于播放页且 `onPause` 即收（`hideInfoBar()` + `PlaybackService` 继续）。因此「信息条遮挡 EPG 网格/搜索/频道管理器」在结构上不可能发生；唯一叠层是**同一页内的对话框**（轨道/画幅/过扫描菜单、失败路径的重试卡片），前者是独立窗口、后者在信息条之上且已通过 `root.nextFocusLeft/RightId` 与信息条串联，不构成遮挡冲突。

## 5. 无焦点死角（静态自测 + 代码再武装）

**自测脚本**：`tools/ci/tv-focus-audit.sh`（静态，不依赖设备；已接入 `.github/workflows/ci.yml`，与脱敏守护同层、不需要 JDK）。它逐屏检查「布局里有可聚焦控件，或（搜索页这种行由代码构建的屏）Activity 里有 `requestFocus`」，并打印每屏的 BACK 机制。实测输出：

```
layout                                     焦点控件 BACK 机制                    Activity
------------------------------------------ ---------- ------------------------------ --------
activity_main                              4          框架默认（返回栈/根） MainActivity.kt
activity_log_console                       10         框架默认（返回栈/根） LogConsoleActivity.kt
activity_browse                            8          显式策略/回调            BrowseActivity.kt
activity_search                            0 代码构建 显式策略/回调            SearchActivity.kt
activity_epg_grid                          1          显式策略/回调            EpgGridActivity.kt
activity_player                            6          显式策略/回调            PlayerActivity.kt
activity_diagnostics                       18         框架默认（返回栈/根） DiagnosticsActivity.kt
activity_settings                          0 代码构建 框架默认（返回栈/根） SettingsActivity.kt
activity_source_management                 2          框架默认（返回栈/根） SourceManagementActivity.kt
tv-focus-audit: OK — 9 screen layouts, every one can take focus
```

**代码侧再武装（五处）**——「有可聚焦控件」不等于「此刻一定有焦点」：

| # | 位置 | 修的是什么 |
|---|---|---|
| 1 | `BrowseActivity.onResume` | 浏览页是枢纽（播放页/网格/搜索/设置都回到它），后台期间目录可能重新发射导致列表重建；现在**仅当整窗无焦点**时才把焦点放回「上次聚焦的频道 → 首个频道行」 |
| 2 | `BrowseActivity.restoreFocusOrFirstRow` | `post` → `doOnLayout`：`scrollToPosition` 之后行才存在，裸 `post` 在窗口重建时可能找不到 holder 而把遥控留在空处 |
| 3 | `BrowseActivity` 焦点落点 | 提取 `ChannelFocusTarget`（preferred → 首个**频道行**，跳过不可聚焦的分组标题）；纯函数 + 5 条单测 |
| 4 | `EpgGridActivity` | 详情弹层关闭后显式 `grid.requestFocus()`（原行/原节目） |
| 5 | `DiagnosticsActivity` / `LogConsoleActivity` | `onResume` 仅在整窗无焦点时把焦点交给首个控件（从日志控制台/导出弹窗回来后不留空） |

播放页新增 `PlayerFocusTarget`（纯函数 + 7 条单测）：失败卡片出现 → 焦点给「重试」；卡片消失 → 焦点**回视频根**（`View.GONE` 不能持有焦点，此前会任框架随便挑一个）；信息条在自己持有焦点时收起 → 回根。信息条可见期间不抢焦点，避免打断左右键在四个控件间的行走。
