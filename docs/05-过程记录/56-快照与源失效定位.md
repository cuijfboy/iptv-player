## 0. 结论（先给答案）

| 卡 | 结论 |
|---|---|
| **PLAYBACK-DEAD-1** | **不是播放器缺陷，也不是电视断网**：出厂带的频道表是**合成占位符**（658 个频道全部指向 `p12.demo.invalid`），而电视又**拉不到**那 18 个内置聚合源（全在 `raw.githubusercontent.com`）⇒ 用户看到的就是「所有源都无效」。归因见 §2 |
| **SNAPSHOT-1** | **已交付并真机验证**：189 个**在电视上实测能起播**的频道打进 `app/src/main/assets/snapshot/channels.m3u`，空表时首启播种；`pm clear` 后**不做任何导入**即可播放（抽 10 条，全部 ≤3 s） |

一句话因果链：**电视拿不到源（网络路径）→ 频道表只剩占位符（出厂数据）→ 播放报 `NET_UNREACHABLE` → 用户说「所有源都无效」**。

## 1. 方法与工具（可复现）

1. **逐 URL 电视实测**：用仓库自带的 `spike` 夹具 `ilab.iptv.spike.PlaybackSpikeActivity`（与应用**同一引擎族**：Media3 `ExoPlayer` + `media3-exoplayer-hls`，**在电视本机**解码），一次喂一批 URL：

   ```bash
   adb shell am start -n ilab.iptv.player.spike/ilab.iptv.spike.PlaybackSpikeActivity \
     -e mode s1 -e tag <tag> -e timeoutMs <ms> -e gapMs 250 -e urls '<url1,url2,...>'
   # 结果落在 /sdcard/Android/data/ilab.iptv.player.spike/files/s1_<tag>.json，并打 SPIKE 标签日志
   ```

   > 为什么不直接点开应用逐台点：应用日志只记 `channelId`/`streamId`（URL 已脱敏成 host+hash），无法把结果回连到具体 URL。spike 的 `urls` 入口让「测哪条 URL → 得什么结果」是可断言的。
2. **Mac 侧对照**：同一批 URL 用 `curl -m 6 -L --range 0-1500 -A okhttp/4.12.0` 取状态码，用来把「电视独有失败」与「源本身就坏」分开。
3. **应用级取证**：受控清单（单分组 + `tvg-chno=1..N`）导入后，浏览列表顺序=文件顺序，于是「点第 k 行」就等于「测第 k 条 URL」，应用自己的 `PLAY_*` 事件就是判据。

## 2. PLAYBACK-DEAD-1 归因

### 2.1 真因链（三步，全部为电视侧实测）

| # | 观测 | 证据 |
|---|---|---|
| 1 | `pm clear` 后走向导第 1 步主按钮（= 内置源刷新）：**12 条 `SRC_FETCH_FAIL`，`failure=TIMEOUT`、`costMs≈30 s`**；失败的 provider 例：`fanmingming.itv` / `guovin.result` / `yang.gather`（18 个内置源全在 `raw.githubusercontent.com`）。**同一台电视的 4 个 EPG 源（`epg.pw.*` / `epgshare01.hk`）全部 200** ⇒ 不是断网，是**该域名的网络路径不通** | `evidence/RC`、日志 `SRC_FETCH_FAIL`/`EPG_FETCH_OK` |
| 2 | 因为没有真表，频道表 = **内置合成夹具**：`SRC_PARSE_OK{message="fixture seeded into Room", provider="p1-2-fixture", channels=658}`，538 个频道全部指向 `http://p12.demo.invalid/…` | 同上 |
| 3 | 播第 1 台：`PLAY_PREPARE_FAIL{failure=NET_UNREACHABLE, detail=ERROR_CODE_IO_NETWORK_CONNECTION_FAILED}` + `UnknownHostException: Unable to resolve host "p12.demo.invalid"` → `PLAY_FAILOVER{action=switch}` → 再失败 → `give_up`；**向导还写着「658 个频道，其中 658 个可播放」**（应用无法预知占位符不可达） | 同上（截图 `13-play-fixture-fail.png`） |

⇒ **「所有源都无效」= 出厂数据是占位符，叠加「电视拉不到聚合源」。** 与播放器实现无关（同一台电视用同样的引擎，播真源是好的，见 §3）。

### 2.2 三类归因（240 个 URL 电视实测 + Mac 对照）

候选池：`dsh/iptv-repo/out/validated.m3u`（571 频道 / 658 流）中 Mac 侧 `curl` 返回 200/206 的 **454** 条，按 host 轮转取 **240** 条做电视实测（第一轮 200 条超时 5 s、补充轮 40 条超时 8 s）。

| 归因 | 判据 | 样本 | 说明 |
|---|---|---|---|
| **源侧坏** | 电视与 Mac 都拿不到正常响应；或电视拿到源站的错误状态码 | miguvideo `:8080` **105 条**（Mac 605 = `msisdn` 令牌过期；电视 4/4 抽测 `HTTP_SERVER`）；Mac 403/404 的条目电视侧 `HTTP_CLIENT` | 与播放器无关 |
| **TV 网络路径不可达** | **Mac `curl` 200、电视超时** | 境外 CDN（`*.cloudfront.net` / `*.amagi.tv` / `*.akamaized.net` 等）+ `raw.githubusercontent.com`（同 §2.1） | 电视所在网络的出口问题，非应用问题 |
| **App 侧** | 应用自身抛错/状态机错误 | **0 条** | 每条失败都带 `httpStatus`/Media3 IO 码，没有一条是应用自身错误 |
| （另注）**慢源** | 5 s 测不出、12 s 能出画面 | 第一轮失败的 42 条用 12 s 复测 → **33 条出画面**，首帧 0.7–10.0 s | 「慢」不等于「死」；这类不进快照（见 §3.2） |

### 2.3 应用级抽样（跨 host，≥20）

受控清单 24 条（覆盖 ~20 个 host：miguvideo、境外 CDN、`*.github.io`、`cgtn.com`、`cztv.com`、多个 `:9901` 地方台…），逐台起播，结果取应用日志：

| 结果 | 条数 | 明细 |
|---|---|---|
| **出首帧** | **15** | 首帧 269–5546 ms（中位 **651 ms**；17 次出帧含一次故障转移到备胎后成功） |
| 失败 | 6 | 4 条 miguvideo `HTTP_SERVER`、2 条源侧 `HTTP_CLIENT`（Mac 同 URL 403/404） |
| 不确定 | 1 | Mac 侧本就超时的 `:9901` 条目，10 s 观测窗内无事件（属「慢/死」，非应用错误） |

（第 23/24 台因按键未落焦未实际起播，不计入。）

**结论**：应用把每一条失败都归到「源站状态码」或「网络 IO」，**没有一条 App 侧缺陷**；真源在电视上正常出画面。

### 3.2 快照怎么筛出来的

1. 起点 = `validated.m3u` 去重后的 573 个频道；
2. Mac 侧 `curl` 只留 200/206（454 条），按 host 轮转取 240 条；
3. **电视实测出画面**且 **首帧 ≤ 5000 ms** 才收（191 条入选）。

| 项 | 值 |
|---|---|
| 频道数 | **189** |
| 分组 | 央视 33 · 卫视 27 · 体育/赛事 2 · 港澳台 3 · 地方/其他 124 |
| 每行属性 | `tvg-id` / `tvg-name` / `tvg-chno`（1..189）/ `group-title` / 显示名 |
| 电视侧首帧 | 中位 ~0.9 s、p90 ~4.0 s（240 条实测口径） |

慢源（首帧 > 5 s）**刻意不收**：对用户来说 5–10 s 才出画面与「坏了」体感相同。

## 5. 未验证 / 已知限制（不要当已验证）

1. **快照会过期**：这些是地方台直链，源站改动/令牌过期会让条目失效——建议后续轮次**复用本记录的 spike 流程**重跑并刷新快照。
2. **每条流的首帧只测了 1 次**（未取多次中位）；长稳、夜间时段、并发多台未测。
3. **换网络后可用性会变**：境外 CDN 类在别的出口可能反而可用。
4. **合规**：本快照把第三方直播流 URL 打进**公开仓库与 APK**（人工 2026-09-22 明确要求「在 App 里内置一份快照」，卡 `SNAPSHOT-1`）；对再分发口径有顾虑时请在发布前复核。
5. 快照中 3 条 URL 带源站自有令牌 `txSecret=` / `wsSecret=`（源站公开聚合清单里的原值；脱敏守护按「键名须独立成词」的规则**不拦**，本记录不复制这些 URL）。
