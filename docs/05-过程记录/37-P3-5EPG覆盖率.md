## 5. 口径：什么叫"主流频道"（docs/01–04 未定义）

`docs/04` 的 P3-5 出口写作 **≥60%（主流频道）**，但四份设计文档都没给"主流"的定义。本轮的取法与理由：

- **口径 A（本轮采用）**：`ChannelGroup.CCTV + SATELLITE + HK_MO_TW`（央视 + 卫视 + 港澳台）＝ **156 台**。这是观众口中的"主流频道"，也是打开 App 先找的那批台。
- **口径 B（同时上报）**：全量 658 台（含 500 个合成地方台）。

两个数都写进同一条 `EPG_COVERAGE` 事件（`mainstreamRatio` / `ratio`），所以**无论最后定哪个口径，都能从同一条事件读出**，不必重跑。请 arch 在 `docs/04` 回写定义（本轮不改 `docs/04`）。

### 5.1 各杠杆的贡献（离线镜像，同一夹具 + 同一批 guide）

为把"归一化 / 别名 / 新源"的贡献分开，用一个 JavaScript 镜像复刻了同一套算法（同一 `EpgNameKey`、同一 `EpgNameVariants`、同先到先得索引、同别名解析），并用**实测端点校准**：镜像 R0 = 135/658、主流 79/156，与改动前实测**逐台一致**；镜像 R4 = 209/658、主流 153/156，与改动后实测**逐台一致**。

| 配置 | 全量 | 主流 |
| --- | --- | --- |
| R0 出厂链 + 出厂源（= 基线） | 135/658 | 79/156 = 50.6% |
| R1 加归一化（tier 3） | 188/658 | 132/156 = 84.6% |
| R2 加新别名（tier 4） | 155/658 | 99/156 = 63.5% |
| R3 归一化 + 新别名 | 208/658 | 152/156 = 97.4% |
| R4 再加 2 个新源（**本次交付**） | 209/658 | 153/156 = 98.1% |

要点：**归一化是主力（+53 台）**，别名补语义等价（+20 台），新源补 1 台（`明珠台`）并提高抗单点故障能力。任一单项都能过 60%，但只有"归一化 + 别名"才能把央视/卫视做到 100%。镜像脚本不入仓（一次性核对工具），端点一致即说明表可信。

### 5.2 为什么不做"前缀/包含模糊"（§6.3 tier ③）

镜像里加上保守前缀匹配（唯一候选才命中）后，全量只从 209 → **213**（+4 台，全部落在合成地方台：`贵州影视` 配 `贵州影视文艺`、`西藏影视` 配 `西藏影视文化`、`河北少儿` 配 `河北少儿科教`、`北京体育` 配 `北京体育休闲`），主流**一台不涨**。代价是在两万多频道的 guide 上引入"猜"的风险，而 §6.3 明确"错配比不匹配更糟"。**故本轮仍不做**，留给 P3-4 的"手动绑定"与后续迭代。

## 6. 匹配链与别名维护规则

### 6.1 四级链（`EpgMatcher`）

| 级 | 判据 | 说明 |
| --- | --- | --- |
| 1 `TVG_ID` | `tvg-id` 等于 XMLTV `<channel id>` | 唯一"构造即精确"的级，先试 |
| 2 `NAME_EXACT` | `EpgNameKey.key(name)` 与 guide `<display-name>` 的键相等 | 全角/空格/大小写已折叠 |
| 3 `NAME_FUZZY` | 归一化后相等：去标点、`+` 与 `plus` 折叠、去 feed 标记（高清/标清/超清/蓝光/HD/FHD） | **两侧都折叠**，仍是等式，不是"猜" |
| 4 `ALIAS` | 别名表（键 = 源侧名字的归一化键；值 = guide 频道 **id** 或 **名字**） | 语义等价（`央视新闻` 就是 `CCTV-13 新闻`），别名查询同样跑第 3 级的 variant |
| 5 `MANUAL` | 用户绑定，**永不覆盖**（进 `EpgMatchReport.preserved`） | 仍计覆盖率 |

安全不变式（有单测钉死）：**质量标记里"区分频道"的部分一律不折叠** —— `CCTV4K` 不等于 `CCTV4`、`CCTV5+` 不等于 `CCTV5`、`CCTV8K` 不等于 `CCTV8`。实现上：`+` 先折叠成 `plus`（而不是删掉），`4k`/`8k`/`uhd`/`sd`/`plus` 不在去尾表里。

### 6.2 别名表维护规则（写进 `EpgAliases` 的 KDoc，5 条）

1. **一条 = 一次真实未命中**：只能来自真实采样（`-Piptv.epgSample=1` 会打印最终未覆盖清单），不许凭想象编。
2. **机械的归规则，语义的归别名**：标点/feed 标记/`+` 的差别写进 `EpgNameVariants`（两侧都跑）；别名只放"拼写之外的同台"（`央视新闻` 是 CCTV-13）。
3. **绝不跨频道**：`CCTV5`/`CCTV5+`/`CCTV4K` 是不同频道，写错一次就是串台，比不匹配更糟。
4. **值优先写 guide 名字**：公共 guide 的 id 是逐源的数字（`539631`），会随重抓变化；名字形态目标还能经第 3 级折叠（`凤凰中文` 兼容 `凤凰中文 高清`）。
5. **保持小**：表变大说明缺规则（`X 高清`、`X-Plus` 这类要加规则而不是加条目）。当前 **29 条**，`EpgMatcherTest` 把上限钉在 40、下限钉在 20。
