## 4. 真机自证（5 项）

### 4.1 从列表进播放 → 出画面 ✅

```bash
adb shell am start -n ilab.iptv.player/ilab.iptv.player.feature.channels.BrowseActivity
adb shell input keyevent 20 && adb shell input keyevent 19   # 焦点落到第 1 行
adb shell input keyevent 23                                  # OK/Enter = 打开播放
```

- 列表与焦点：`01-browse.png`（临时夹具的 4 台）、`03-focus.png`（焦点三重反馈：缩放 + 描边 + 高亮，列表头同步显示"焦点：2 CGTN"）。
- OK 之后 `mResumedActivity` = `ilab.iptv.player/.feature.player.PlayerActivity`，随即出画：`30-picture-bar.png`。
- 日志（真机实测）：

```
I IPTV/PLAYER: PLAY_PREPARE_START prepare start {channelId=3, streamId=3, engine=media3, attempt=1, timeoutMs=12000, preferPassthrough=true} session=app-b93d thread=main
I IPTV/PLAYER: PLAY_FIRST_FRAME first frame {costMs=440, engine=media3, vcodec=video/avc, acodec=audio/mp4a-latm, w=1920, h=1080, audioPath=PCM_DECODED} session=app-b93d thread=playback-engine
```

首帧 **440 ms**（另一轮 459 ms），`PLAY_FIRST_FRAME` 由会话（控制器）唯一发射，`costMs = 首帧 − 起播开始`（§7.3）。

### 4.2 信息条显示 / 5 s 淡出 ✅

- 打开后 3 s：`30-picture-bar.png` —— 台标占位（"C"）+ 频道名 CCTV13 + `1080p avc mp4a-latm` + now-next 占位（`节目单（now-next）待接入 · P2-7`）+ `画幅：适应`。
- 打开后 8 s（无任何按键）：`31-bar-faded.png` —— 信息条**完全消失**，画面铺满。
- 5 s 这个数字是常量 `InfoBarVisibility.INFO_BAR_TIMEOUT_MS = 5000L`，并有单测钉边界（4999/5000 ms）。

### 4.3 宽高比四档切换 ✅

信息条上的 `画幅` 是 P1-4 唯一可聚焦控件；`OK` 循环 `适应 → 拉伸 → 裁剪 → 4:3 → 适应`。

| FIT 适应 | `画幅：适应` | `30-picture-bar.png` |
| FILL 拉伸 | `画幅：拉伸` | `33-aspect-fill.png` |

## 5. 与引擎/其它卡的边界

- **不做**故障转移（P1-6，`core:domain` playback 包未碰）、**不做** MediaSession/音频焦点/前台服务（P1-7）、**不做** EPG 真实数据（P2-7，now-next 是占位）、**不做**换台键位与 `PLAY_SWITCH_CHANNEL` 埋点（P1-5）。
- 引擎实例的生命周期按 §7.2 P3/P5：进出播放页只 `attach(surface)` / `attach(null)`，**不**创建或释放引擎；退出播放页只 `stop()`（S5 的复用结论），`release()` 留给会话真正结束（P1-7 的前台服务会接管）。
- `PlaybackSession` 不是 §4.3 的 domain 端口 `PlaybackController` 本身：那个端口还要带故障转移与音频焦点。P1-6 落地时应当是**包一层**，引擎管道、`PLAY_*` 埋点与状态机都不变。

## 6. 设备上发现并修掉的两个缺陷

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| **D1** | `PLAY_FIRST_FRAME` 日志里 `vcodec=null acodec=null w=0 h=0 audioPath=NONE`，但画面正常 | 首帧**早于** ready 回调到达：会话当时只用 `PlaybackEvent.Prepared` 填快照，而 Prepared 在 `onReady()` 才发 | 改为优先读引擎自己的缓存 `Media3Engine.snapshot()`（在 `onTracksChanged` 就刷新，且文档说明可跨线程读），Prepared 作为兜底。修后日志即 `video/avc … 1920×1080` |
| **D2** | 失败卡片出现后，按 DOWN 焦点到"画幅"就**回不到"重试"**（`画幅` 的 up 指向自己） | 焦点路由只在"信息条内部"闭环，没有考虑它上方还有失败卡片 | 失败态下显式 `retryButton.nextFocusDown → 画幅`、`画幅.nextFocusUp → 重试`；无失败时恢复自环。用 `uiautomator dump` 的 `focused="true"` 复核 |

## 7. 未做项 / 开放项

1. **`UI_SCREEN_OPEN` 默认看不到**：它是 DEBUG 级，`LogBus` 默认 `minLevel=INFO`（docs/03 §14），所以 `adb logcat -s 'IPTV/UI:V'` 里没有它 —— 这是设计行为，不是丢失。要看它需先在 app 内日志控制台切 DEBUG。本轮"打开播放页"的证据用 `dumpsys activity activities` + 截图 + `PLAY_*`。
2. **真机取证的夹具依赖**：`core:data` 目前只读内置 asset，所以每次真机验收都要"临时换 asset → 重打包 → 还原"。建议把"导入本地播放列表/切夹具"作为 P2 源管理的显式出口，或给 QA 一条 debug 变体的夹具开关（本轮没做，属 P2）。
3. **`check` 的 Hilt/lint 竞态**：`--offline check` 偶发在 `:app:lintAnalyzeDebugUnitTest` 报 Hilt 生成源缺失，原样重跑即绿（本轮出现 1 次，2 次复跑均通过）。不是代码问题，但 CI 上会误红，建议 god 决定是否给该任务加重跑或串行约束。
4. **未测**：10 min 长稳/内存增量（§8.4 预算，属 P1-8/长稳）、音轨切换 UI（P3-3）、`播放`/`暂停` 遥控键（P1-7 的 MediaSession）、换台（P1-5）、双屏/多窗口（非目标）。
5. **共享电视**：与 `worker-qa-5` 的 spike 运行撞了两次前台；建议 P1 剩余真机卡排期串行，或各自用独立包名（`:app` 与 spike 已分开，但前台只有一个）。
