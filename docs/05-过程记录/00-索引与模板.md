## 0. 怎么用

本文件干两件事：**给 `docs/05-过程记录/` 建目录**（§1），以及**给四个必须留痕的关卡各发一张可直接照填的模板**（§2–§5）。字段不是新发明——每一张都和仓库里已写好的记录对齐（模板出处见各节「对齐既有」一行），照填即可，不必自造格式。

| 角色 | 用法 |
|---|---|
| PM | 维护 §1 索引；阶段末按 `01-WBS与排期.md` §13 更新估时/风险/里程碑 |
| arch | 设计评审走 §2；CodeReview 走 §3；冻结接口变更须回 §2 的「回写清单」 |
| dev-A / dev-B | 被评审时按 §3 提供变更清单；报缺陷按 §4 补齐四项证据 |
| QA | 缺陷登记走 §4（台账正文在 `04-缺陷台账.md`）；阶段出口走 §5 并出证据 |
| god | 在 §2/§5 的签字栏签字；把关卡卡状态写入 `hive/tasks.json` |

**编号口径**（沿用 `01-WBS与排期.md` §1）：`F1–F12` 需求、`S1–S6` Spike 判据、`L1–L8` 日志验收、`P0–P3`/`G0–G8` 阶段与关卡。角色代号 `god / PM / arch / dev-A / dev-B / QA`。

## 6. 通用规则

1. **单点归属**：每份记录一个责任人（§1 表）；结论变更走对应关卡（设计变更回 G1，排期变更回 G2），不在记录里私下改。
2. **脱敏**：`docs/05-过程记录/` 属公开仓库内容，设备地址一律占位符（`<TV-LAN-IP>`），**不写**内网 IP、MAC、序列号、口令；证据原始文件不入库，只留文件名与结论（`docs/03` §11、`docs/01` §4.3 R8）。
3. **判据要落数**：凡结论必须落到事件码或指标数字，禁止"很快/正常/大致没问题"。
4. **提交**：规范 `feat/fix/docs/refactor/test/chore(scope): subject`；每阶段至少一次提交；分支内提交，**不 push 远端**（god 为唯一集成者）。
5. **看板**：`hive/tasks.json` 由 god 维护；temp/agent 只**提案**卡状态，不直接改。
