### 3.1 单测覆盖的规则（选择性列举）

- **解析**：声明 / DOCTYPE / 注释 / CDATA / 自闭合 / 未知元素；实体 `&amp;` `&lt;` `&#NN;` `&#xNN;`；标题空白裁剪；超长文本按 `MAX_TEXT_LENGTH=4096` 截断；**畸形**（无 `start` / 无 `channel` / 无 `title` / `stop` 早于 `start` / 文档在标签中途结束）分别计入 skipped 或标记 `malformed`，且已产出的行照常交给 sink。
- **时区 / 夏令时**：`+0800`、`Z`、`+08:00`、省略秒、无偏移（按 UTC，理由见 §7.6）、负偏移、跨零点；**DST 折叠对**（同一当地时间 `+0200` 与 `+0100` 必须相差 3600 s）；非法值（13 月、25 时、2 月 31 日、越界年份、非法偏移）一律 `null` 而不是猜。
- **匹配三级**：`tvg-id` 精确 → 归一化名精确（全角/空格折叠；`tvg-id` 失效仍能命中）→ 别名表（目标是 id 或名字两种形态）；**失配**记录 `nameKey` 与被试 `tvg-id`；**MANUAL 永不被覆盖**（进 `preserved`，不参与匹配）；空 guide 不产生任何"命中"。
- **时间窗查询**：`now` 取覆盖该时刻的槽位（不是"最近开始的"）；`next` 取之后最近一条；无绑定 → `NowNext(null,null)`；**频道不存在 → `null`**（两种答案必须可区分）；网格窗口按频道上限裁剪。
- **修剪**：`[now-6h, now+48h]` 之外的删除（过期 + 过早各一例）。
- **幂等**：同一 `(epg_channel_id, start_ms)` 写两次 → 1 行、内容更新；`replaceAll` 丢弃不属于该频道的行。

## 4. 流式解析的实测证据

### 4.1 大文件单测（默认 `check` 内运行，无需网络）

`XmltvPullParserStreamingTest` 用**过程生成**的 guide（不是夹具文件）驱动解析，并断言两件事：

- Reader **拒绝 `mark`/`reset`**（流式解析器不该回退），测试断言 `rewound == false`；
- Reader **统计已产出的字符**，因此可以问"第一行是什么时候出来的"：断言首行在 **≤2 个读缓冲（64 KB）** 内产出，且 `firstEmissionAt < 总字符 / 50` —— 即"边读边出"，而不是"读完再走"。

样本规模：40,000 行（>4 MB）断言 `programmes == 40000`；另有一例 5,000 行 × 长标题，断言末尾行仍正确。

## 7. 与文档的偏差、需要 god/arch 裁决的点

### 7.1 `XmltvStream` 落在 `:core:epg`（且多一个 `body` 字段）

§4.2 把它列在领域模型里，字段是 `(sourceId, bytes)`，却称其为"**流式句柄**"。两个字段无法承载 body，句柄必须带着流走。本轮：`sourceId` / `bytes` 与文档一致（`bytes` = 服务端声明长度，chunked 时为 `null`），另加 `body: InputStream`（gzip 已解）。类型只被 `:core:epg` 使用，因此就近放在 E4 provider 所在模块。**若 arch 要求它回 `:core:model`，需要把 IO 类型引入纯 Kotlin 模块，请裁决。**

### 7.2 `LoadEpgUseCase` 落在 `:core:data`（§4.3 把它列在 `:core:domain`）

编排同时需要 `EpgProvider`（`:core:epg`，§4.4）与 `EpgRepository`（`:core:domain`），而 §3.2 矩阵**不给 `:core:domain` 的 `epg` 列**。唯一同时可见两者的层是 `:core:data`（`data` 行有 domain / epg / source / database / network）。与 P1-5 把协调器放 `:feature:player` 是同一类裁决（"机制 = core，策略 = domain，协调 = 能同时看见两者的层"）。**端口保持文档位置，只有装配 / 编排搬层。**

### 7.3 `:core:network` 新增 `StreamingHttpFetcher`（additive）

现有 `HttpFetcher.fetch` 返回 `HttpResponse`，body 是**封顶 `maxBytes`（默认 8 MB）的 `ByteArray`** —— 对播放列表正确，对"几十 MB 的 XMLTV"在内存上就不成立。因此**新增**一个接口（`HttpBody{status, contentType, contentLength, stream}`）由同一个 `OkHttpFetcher` 实现，`HttpFetcher` 的既有签名与所有 fake **未改动**。`open()` 只重试"打开"（5xx / 超时），交给调用方后**不**关闭 response（所有权随 `stream` 转移）。**属于对共享模块 `:core:network` 的接口扩张，请 arch 确认口径。**

### 7.4 `EpgRepository.prune` 用全表删除而不是"按 `epg_channel_id` 批量删除"

§5.1 的括注是"窗口修剪按 `epg_channel_id` 批量删除"，`ProgrammeDao.pruneWindow(ids, …)` 也在。本轮实现用的是 `deleteAllEndedBefore(from)` + `deleteAllStartingAfter(to)`：**保留窗是时间的属性，不是频道的属性**，全表删除语义与逐频道一致，且避免每次刷新都构造 1k 个 id 的 `IN (...)`。**若 arch 要求严格按频道批次，请说一声（改一处实现即可，端口不变）。**

### 7.5 内置 EPG 源地址更换

实测 **`https://iptv-org.github.io/epg/guides/cn.xml` → 404**（iptv-org 的 guide 托管已下线），因此没有把文档 F6 蕴含的该地址写进内置目录（内置目录是"这个地址能用"的承诺）。改为两个 2026-09-22 实测可达、且来自**不同项目**的公共源：`epg.pw` (CN) 与 `epgshare01` (HK)。两者都返回 gzip，正好覆盖 `GzipSniffer` 的真实路径（按魔数嗅探，不看扩展名 / `Content-Encoding`）。

### 7.6 无偏移时间戳按 UTC 解释

XMLTV 规范里没有偏移的时间是"该源的本地时间"。**猜观众所在时区会静默平移整份节目单**（最难查的故障）；按 UTC 解释是"可预测地错"，且解析器把它计数 / 可观测。有偏移时（绝大多数公共源）DST 已在偏移里，无需推断。

### 7.7 `EpgCoverage.byGroup` 的口径

按 `ChannelGrouping.classify(group_key)` 归到 §4.2 的五值枚举（与诊断面板一致）。`matched` 计"该频道有 `epg_channel_id`"（含 `MANUAL`），而不是"该频道有节目行" —— 匹配链的成果才是覆盖率要回答的问题。

## 9. 已知遗留（交给 god 排卡）

- 别名表与模糊匹配（P3-5）、EPG 网格（P3-1）、手动绑定 UI（P3-4）、设置页源管理（P2-6）。
- `LoadEpgUseCase` 一次调用抓**全部启用源**且串行；多源并发抓取（受 `PipelineLimits` 约束）与失败退避策略未做。
- `EpgRepository.observeWindow` 在频道绑定变化后不会自动重发（绑定解析发生在收集点）；网格页需要"绑定变了就重查"时应补 `flatMapLatest` 或观察通道，属 P3-1 落地时处理。
- 信息条 now/next 只在起播 / 换台时查询一次；节目跨界（30 分钟档）不会自动刷新下一行 —— P2-5 的定时刷新接入点。
