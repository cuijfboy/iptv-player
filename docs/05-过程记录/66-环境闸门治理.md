## 0. 结论（先给答案）

**把「环境闸门」从「源质量问题」里拆出来：这类响应只做当轮切换/退避，不再被永久记账。**

| 项 | 结果 |
|---|---|
| 复现（要求 1） | ✅ 单测 + 本机 HTTP stub（OkHttp interceptor，无 socket）：改前 `418/451` 落 `FailureClass.HTTP_CLIENT`→§4.6 行 = `SwitchTo(next)` + **`StreamDemotion.PERMANENT` 永久降权**；`403/404/410` 同样永久降权（**负向对照**：改动后 403/404/410 **行为逐字不变**） |
| 改法（要求 2） | ✅ 新增**独立字段** `FailureOrigin { SOURCE, ENV_GATED }`（`AppError.origin`，**带默认值 `SOURCE`，纯增量**）；`EnvGate.HTTP_STATUSES = {418,451,511,605}`；策略上 `ENV_GATED` **当轮走 §4.6 recipe（切换/退避），但不写 `permanentlyDemoted`**；刷新侧 `ENV_GATED` **不写长期 score、不记 `failCount`、不清除健康戳** |
| 冻结接口 | ✅ **未改 `FailureClass` 枚举、未改评分输入（`ScoreInput`/`StreamOutcome`）** ⇒ 派工单「若涉及冻结接口先发提案」的条件**未触发**，无需等批准 |
| 可观测（要求 3） | ✅ 只加字段不加码：`PLAY_PREPARE_FAIL.origin`、`NET_REQ_FAIL.origin`、`VAL_SHALLOW_FAIL` / `VAL_DEEP_FAIL` 的 `evidence.origin` |
| 测试（要求 4） | ✅ ①`418/605` 不写长期 score、不进永久降权、第二轮仍可被选中；②`403/404` 仍永久降权；③混合序列（先 605 后 404）语义正确 |
| 质量门（要求 5） | ✅ `./gradlew --offline check` 绿 + 三道静态守卫绿（见 §5） |

**一句话**：一个 HTTP 状态码是「源自己说没了」还是「网段/源站的闸门把我们拦了」，现在在**分类层**就分开，并且**只加字段、不加码、不碰冻结枚举**；`403/404/410` 该怎么死还怎么死。

## 1. 复现（要求 1）

### 1.1 改前事实（从代码读出，不是猜）

| 码 | 落点 | §4.6 动作 | 后果 |
|---|---|---|---|
| `418` / `451` | `PlaybackErrorMapper.httpError`：`status < 500 && 非 429/408` ⇒ `FailureClass.HTTP_CLIENT` | `SwitchTo(next)`，`demotion = StreamDemotion.PERMANENT` | **当轮切换 + 永久降权**（会话内不再选它） |
| `511` / `605` | `httpError`：`status >= 500` ⇒ `FailureClass.HTTP_SERVER` | `Backoff(1s) → RetrySame → SwitchTo(next)`，`demotion = NONE` | 当轮退避/切换，**本就没有永久降权** |
| `403` / `404` / `410` | `httpError` ⇒ `HTTP_CLIENT`（`404` 也走 `AppError.http(404)`） | 同 `418` | **当轮切换 + 永久降权**（这是**正确**语义，保持不动） |

> **对派工单前提的一点更正（事实）**：派工单写「`418`（以及 `451/511/605`）被映射为 `HTTP_CLIENT` → 永久降权」。按代码，**只有 `418/451` 是 `HTTP_CLIENT`**；`511/605` 是 `5xx`，落 `HTTP_SERVER`，**没有**永久降权。所以：
> - 对 `418/451`，本次是**行为修复**（去掉误加的永久降权）；
> - 对 `511/605`，行为本就无永久降权，本次补齐的是**可观测语义**（打 `ENV_GATED` 标记）与**刷新侧不写长期 score**。
> 两个子集都在 `EnvGate` 集合里统一口径，互不冲突。

### 1.2 复现证据（单测 + 本机 stub）

1. **单测（分类）**：`core/player PlaybackErrorMapperTest` —— `418/451` → `HTTP_CLIENT` + `origin=ENV_GATED` + `retryable=true`；`511/605` → `HTTP_SERVER` + `origin=ENV_GATED`；`403/404/410` → `origin=SOURCE`（负向对照）。
2. **本机 stub（传输层）**：`core/network OkHttpFetcherTest` 用一个**进程内 OkHttp interceptor 当本机 HTTP stub**（无 socket、无网络），断言 `418/451/511/605` 的 `AppResult.Err.error` 为 `origin=ENV_GATED` 且 `retryable=true`；`403` 保持 `origin=SOURCE`、`retryable=false`。
3. **负向对照（改前会怎样）**：`core/domain DefaultFailoverPolicyTest` 中「`403/404/410` 仍永久降权」与「`418/451` 不永久降权」并列——前者就是后者在改前的行为。

## 2. 改法（要求 2）

### 2.1 独立分类（不碰冻结枚举）

`core/common` 新增（纯增量，带默认值）：

```kotlin
enum class FailureOrigin { SOURCE, ENV_GATED }           // 默认 SOURCE：所有旧构造点语义不变
object EnvGate { val HTTP_STATUSES = setOf(418, 451, 511, 605); fun isGated(status: Int?) = ... }
data class AppError(..., val origin: FailureOrigin = FailureOrigin.SOURCE)
```

- `AppError.http(status, …)` 与 `PlaybackErrorMapper.httpError(status, …)` 都按 `EnvGate` 置 `origin`；`ENV_GATED` 一律 `retryable = true`（保留重试入口，docs/05 §50 §4.1）。
- **`FailureClass` 枚举与 §4.6 动作表逐字未动**，`ScoreInput`/`StreamOutcome` 也未动 ⇒ 冻结接口安全。

### 2.2 策略：当轮切换/退避，但不落永久降权

`core/domain DefaultFailoverPolicy.decideFailure` 唯一改动——永久降权加一个「来源」前缀：

```kotlin
if (plan.demotion == StreamDemotion.PERMANENT && failure.origin != FailureOrigin.ENV_GATED) {
    input.activeStreamId?.let(permanentlyDemoted::add)
}
```

- `ENV_GATED` 仍按它所属的 §4.6 recipe 走：`418/451`（`HTTP_CLIENT` 行）→ `SwitchTo(next)`；`511/605`（`HTTP_SERVER` 行）→ `Backoff → RetrySame → SwitchTo`。
- **不进 `permanentlyDemoted`** ⇒ 备胎失败后**仍可回切**（会话级、可回退、不除名，与 65 号 `startupFailed` 同口径）。
- `403/404/410`（`origin=SOURCE`）**永久降权逐字不变**。

### 2.3 刷新侧：不写长期 score、不记源失效

- `ShallowReachabilityValidator` / `DeepProbeValidator`：失败 evidence 增 `origin`（只加字段）。
- `RefreshSourcesUseCase`：
  - shallow 阶段对 `ENV_GATED` 的结果**不调用 `recordOutcome`**（不写 `play_history` 失败、不动 `failCount`），并从 `failedIds` 里挪出，单列为 `envGatedIds`；
  - 反半段新增 `VerificationKind.ENV_GATED`：该流**不深探**、**沿用存储的 score 与 health**，最终 upsert 只按既有 `verified` 刷新选择位——与「fresh（TTL）复用」同一写法。
- 语义：闸门拦截 = **「对源没有结论」**，而不是「源不行」。

### 2.4 改了什么文件

| 文件 | 改动 |
|---|---|
| `core/common/.../AppResult.kt` | `FailureOrigin`、`EnvGate`、`AppError.origin`、`AppError.http` 置 origin |
| `core/player/.../PlaybackErrorMapper.kt` | `httpError` 置 origin + `ENV_GATED` 可重试 |
| `core/player/.../PlaybackFailureText.kt` | `ENV_GATED` 文案「本网或源侧未放行（HTTP xxx）」+ 短标签「网关未放行」 |
| `core/player/.../PlaybackEventLogger.kt` | `PLAY_PREPARE_FAIL` 增字段 `origin` |
| `core/network/.../OkHttpFetcher.kt` | `NET_REQ_FAIL` 增字段 `origin` |
| `core/source/.../ShallowReachabilityValidator.kt` | 失败 evidence 增 `origin` |
| `core/source/.../DeepProbeValidator.kt` | 失败 evidence 增 `origin` |
| `core/domain/.../DefaultFailoverPolicy.kt` | 永久降权加 `origin != ENV_GATED` 前缀 |
| `core/data/.../RefreshSourcesUseCase.kt` | `envGatedIds` + `VerificationKind.ENV_GATED`（不写 score / 不记失效 / 不深探） |

2. `511/605`：行为不变（本就 `HTTP_SERVER`），新增 `origin=ENV_GATED` 标记与刷新侧不写长期 score。
3. `403/404/410`：**行为逐字不变**。
