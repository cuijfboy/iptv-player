## 1. 口径与约定

- **估时单位**：*有效工作日*（一个角色完整投入一天的量）。`0.25d` = 半天以内的小改；估时是**工作量**，不等于日历天数。
- **角色代号**：`god`（拆解/派工/集成/最终验收）· `PM` · `arch`（技术总监）· `dev-A`（工程基座 + 数据/源/刷新/诊断）· `dev-B`（播放引擎 + TV UI/交互 + EPG）· `QA`。
- **编号规则**：工作包编号**与 `docs/04` 的任务号一一对齐**（`P0-1…P0-8`、`S1…S6`、`P1-1…P1-8`、`P2-1…P2-9`、`P3-1…P3-7`），另加**关卡卡**（`G*`）。见 §7 的旧号迁移说明。
- **并发上限**：**4 个 temp**（`hive/tasks.json` 现状）；全场同时段最多 4 个角色在跑。
- **验收判据**：一律引用基线指标 —— 功能编号 `F1–F12`（docs/01 §1.2）、Spike 判据 `S1–S6`（docs/04 §2.2）、日志验收 `L1–L8`（docs/03 §13）、阶段出口见 docs/04 各章末。
- **纪律**（docs/04 首条）：`S1/S2` 未出结论前**不写播放器 UI**；每阶段末过一次出口验收并提交一次。
- **脱敏**：本文件及后续过程记录属于公开仓库内容，设备地址一律用占位符（`<TV-LAN-IP>`），**不写**内网 IP、MAC、序列号、口令（docs/01 §4.3 · R8）。

## 9. 关键路径与里程碑

### 9.1 关键路径（不能并行、必须串行的一段）

```
P0-1 → P0-2 → P0-3 → P0-4 → P0-5(装机) → S1 → P1-3 → P1-4 → P1-5 → P1-6
      → P2-1 → P2-7 → P3-1 → P3-5 → P3-G → G7-1 → G8-1
```

- 路径上的**唯一外部前提**是"电视在线 + ADB 可达"（P0-5、S1）：不满足则整条路径停摆（R1）。
- 路径外**最长的旁支**是 `P2-4`（本机源刷新，2.0d）与 `P2-8`（诊断面板，1.0d）：它们不挡主路径，但决定 P2 能否出口。
- **最短总长度 ≈ P0(1–2d) + P1(3–5d) + P2(5–8d) + P3(8–12d) ≈ 17–27 有效工作日（约 4–6 周）**，与 docs/04 §10 一致。
