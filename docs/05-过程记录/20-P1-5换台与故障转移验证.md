## 6. 本轮在真机上/构建里发现的真实缺陷

### 6.1 `main` 构建回归：`media3-exoplayer-hls` 目录项被集成吞掉（**阻断级**）

`main@1de2f81` 上 `./gradlew :core:player:compileDebugKotlin` **无法配置**：`Unresolved reference: hls`。原因是 `gradle/libs.versions.toml` 里 P1-3 加的 `media3-exoplayer-hls = …` 一行，在 P2-1 集成提交 `279a9d4` 中被顺手删掉（该提交同时正确地加了 room-testing/robolectric 等测试库），而 `core/player/build.gradle.kts` 仍在引用它。已在本轮恢复该行（附注释说明），恢复后 `check`/`assembleRelease` 全绿 → **请 god 复核这条集成回归**，并确认是否有其它模块也吃了同样的合并事故。

### 6.2 切换中的信息条状态被 re-prepare 清掉（真机发现）

首轮真机取证（截图 `09`）显示切换期间信息条**没有**状态行：`onFailoverRunning` 设的提示会被紧随其后的 `onWatchStarted`（换备胎也要 `watch`）用新建的 `infoBar` 覆盖掉。修法：`PlaybackUiStateMachine.onWatchStarted` 只在「相位为 `FAILOVER` 且频道未变」时**保留** `failoverHint`，其余情形（换台、失败后手动重试）清空；`PlayerActivity` 在提示变化时重新计时（新提示独占 5 s）。两处都补了单测（`PlaybackUiStateMachineTest`）。

### 6.3 淡出中按键会让信息条彻底消失（真机发现）

数字键取证第一轮（截图 `20`）拍到「按键后 1 s 信息条不见了」：按键落在信息条 5 s 自动淡出的那 300 ms 里，`showInfoBar()` 只在 `visibility != VISIBLE` 时才重新淡入，于是旧淡出的 `withEndAction { visibility = GONE }` 把刚唤出的信息条关掉。修法：`showInfoBar()` 在「不可见**或** alpha < 1」时都取消动画并重新淡入，淡出的 end action 改成先查逻辑状态（`if (!visibility.visible)`）再隐藏。修复后重测：截图 `22` 按键后信息条在（显示「跳台：5」），截图 `23` 跳到换台E。这条与 P1-4 的「任意遥控键唤出」直接相关，故一并修在本轮。

## 7. 语义与实现选择（下一位直接用）

- **策略调用序列**（真机 + 单测都按此）：`fail#1 → decide(attempt=1) → …`；`Backoff` **消耗一个 ordinal 但不 prepare**，所以 `HTTP_SERVER` 出来的是 `Backoff(1s) → (attempt=2) RetrySame(0) → prepare(attempt=3) → 失败后 decide(3) → SwitchTo`，与 P1-6 §5 的算例一致。
- **`attempt` 是「该流在本会话内的第几次失败」**：`RetrySame` 交给下一次 prepare 的 ordinal = 本次+1；任何 `SwitchTo` 重置为 1。
- **手动重试 = 重开该频道的新会话**（不是「同流再试一次」）：`FailoverPolicy` 的预算/永久降权都是会话级，用户按「重试」的语义是「这个频道再来一遍」。
- **暂停**：`PlaybackCommand.Pause` 对应 `coordinator.setPaused(true)`，暂停流永不判停滞（`PlaybackSample.isPaused`）。
- **换台边界夹紧**（同分组内到底不动），不做跨分组跳转；数字键走 §8.2 冻结的 2 s 窗口。
- **`ResolveFresh` 的诚实边界**：真·深度复检（单频道网络重探）属 P2-4b；本轮实现为「重读仓储取最新候选」，若仓储里出现了新的（或此前未选用的）候选就切过去，否则给明确提示。真机 5.3 走的是「无新候选 → give_up」。
