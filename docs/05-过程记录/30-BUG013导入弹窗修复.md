## 2. 根因（复核 AOSP，确认 QA 的判断）

`$ANDROID_HOME/sources/android-36.1/com/android/internal/app/AlertController.java`：

```java
protected void setupContent(ViewGroup contentPanel) {            // 第 772 行起
    mScrollView = (ScrollView) contentPanel.findViewById(R.id.scrollView);
    mMessageView = (TextView) contentPanel.findViewById(R.id.message);
    if (mMessageView == null) return;
    if (mMessage != null) {                                      // ← message 分支：只写文案
        mMessageView.setText(mMessage); ...
    } else {                                                     // ← 只有这里才挂列表
        mMessageView.setVisibility(View.GONE);
        mScrollView.removeView(mMessageView);
        if (mListView != null) { ... scrollParent.addView(mListView, ...); }
    }
}
```

即 `setMessage(...)` 与 `setItems(...)` 同时使用时，**item 列表被静默丢弃**——没有异常、没有空态，就是没有行。本仓有两处踩到同一个坑（QA 只报了浏览页那处）：

| 位置 | 旧写法 | 症状 |
|---|---|---|
| `feature/channels/…/BrowseActivity.openImportPicker()`（QA 报的） | `setMessage(hint).setItems(saf/drop)` | 弹窗只有标题 + 提示 + 取消，**两条路都不显示**，用户根本进不到候选列表 |
| `feature/settings/…/SourceManagementActivity.showImportDialog()`（同轮发现） | 同上 | 源管理页的「导入本地文件」同样点不动 |

## 3. 修法

**不让 message 与 list 同用**：提示改走 `setCustomTitle`（自定义标题视图，AOSP `setupTitle()` 用自定义视图替换单行标题模板），列表仍走框架 `setItems` —— 焦点、DPAD、`OnItemClickListener` 全部保持与**本来就能用**的对话框一致（`setupView()` 里非触摸模式下 `requestFocusForContent()` 会把焦点交给 `mListView`，所以遥控开箱即用）。

新增 `:core:ui/…/import/`（两个 feature 都声明 `:core:ui`，修一处即修两处，也避免以后复制粘贴复活旧写法）：

| 文件 | 职责 |
|---|---|
| `ImportPickerDialog.kt` | 唯一建弹窗的地方：`showList(title, hint?, rows, cancelLabel, onPick)`（提示进自定义标题）与 `showMessage(title, message, closeLabel)`（空目录/提示类）。KDoc 里写明 AOSP 那条 `setupContent` 规则 |
| `ImportPickerModel.kt` | 纯决策：`pickContent(candidates, emptyMessage, rowLabel)` → `Files(rows)` / `Empty(message)`；`ImportEntrance { SystemPicker, DropFolder }` 取代散落的 `if (which == 0)` |
| `ImportCandidateLabel.kt` | 候选行格式（`名字 · 12.3 KB · 09-22 08:15`），**从 `:feature:channels` 搬来**，源管理页从 `1234 KB` 改用同一格式 |
| `res/layout/dialog_import_title.xml` | 自定义标题：标题 + 多行提示（文字由代码设置，颜色取对话框主题） |

- `BrowseActivity.openImportPicker()` / `showDropPicker()`：改走上面两个 API；**`browse_import_empty` 空目录分支原样保留**（文案、路径、`adb push` 示例、`知道了` 都没动）。
- `SourceManagementActivity.showImportDialog()` / `showDropPicker()`：同样改造（该页的添加/编辑/删除弹窗未动）。
- 字符串资源**零改动**；`:core:ui` 首次带 `res/`（只有这一个布局）。

## 6. 同轮发现（都不在 BUG-013 边界内，未改，报 god / QA）

### 6.1 导入后界面「流」计数大于本条清单的流数（候选缺陷，编号待 QA 登记）

- 现象：8 频道 / 10 流的清单导入后，头行显示 **`流 22`**，单行显示 `CCTV1 · 3 路流`、`CCTV2 · 4 路流`（清单里 CCTV1 只有 1 条流、CCTV2 有 2 条）。截图 `10-real-import-toast.png`、`11-real-import-list.png`。
- 根因（代码级）：`core/data/…/store/RoomCatalogWriter` 按 `(name_key, group_key)` upsert 频道、按 `(channel_id, url_hash)` upsert 流，**只对「不在本次清单里的频道」做 prune + 级联删流**——所以上一条清单里**同名频道**留下的流会继续挂在这一行上。这是刷新管线的有意语义（保故障转移候选），但对「导入即替换」的语境会留下死源。
- 排除实验（`logcat-probe.txt`、`15-probe-import-list.png`）：换一份**频道名不与上一条清单重合**的 2 频道清单导入 → 头行 `频道 2 / 分组 1 / 流 2`，与清单完全一致 ⇒ 确认多出来的流只来自同名旧频道。
- 影响：**QA 复跑 P1-G 第 1 项时要注意**——先用 `pm clear` 拿到干净库，否则同名频道会带上一个夹具死源（`p12.demo.invalid`）当备胎，可能影响起播成功率与故障转移的读法。是否让「导入」清掉同名旧流，属 `:core:data` 写入口的语义变更，建议 god/arch 裁决后单开一卡。

### 6.2 SAF 路径在本机「无选择器」时的提示来自系统，不是本 App（可读、不崩，但没有走我们那条兜底文案）

- 现象：点「从文件选择（系统选择器）」→ 该电视没有可执行的 DocumentsUI，**系统**弹出「您没有可执行此操作的应用」；App 自己的 `browse_import_saf_unavailable`（「这台设备没有可用的文件选择器，请改用投放目录」）没有出现，也没有崩溃，回列表后投放目录那条路照常可用（截图 `17-saf-path.png`）。
- 原因：隐式 intent 找不到目标时，`Instrumentation.execStartActivity` 会接住 `ActivityNotFoundException` 并弹系统提示，异常根本到不了 `catch (ActivityNotFoundException)`，所以 P2-6 写的兜底是死代码（只有 `resolveActivity()==null` 预检才能在 App 侧给出自己的文案）。
- 归属：P2-6（`worker-dev-a-20`）遗留，S5 量级，不阻塞本卡；是否补预检请 god 排期。
