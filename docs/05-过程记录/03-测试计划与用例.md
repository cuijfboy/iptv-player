## 4. 用例规范

- **用例 ID**：`TC-<阶段>-<模块>-<序号>`；模块名取自 `docs/02` §3.1（BLD 构建、CI、LOG 日志、DEV 装机、SPIKE、PARSE 解析、DOM 策略、DATA 数据、PLAY 播放）。
- **优先级**：`P0` = 阶段出口必跑、不通过即阻塞；`P1` = 重要但可后置，不阻塞出口但需在阶段末给出结论。
- **证据编号**（用例表「证据」列引用）：
  - `E1` 版本三连：`versionName` + `versionCode` + `git rev-parse --short HEAD`（构建产物 SHA 也要）。
  - `E2` 事件码 + 原始日志：`logcat -v threadtime` 原文或 JSONL 会话（按 `sessionId` 折叠），含时间戳，未截断关键段。
  - `E3` 截图 / 录屏：故障现场必须截图；播放/无声/卡顿类必须录屏。
  - `E4` 指标数据：`costMs` / `fps` / PSS 等原始数值（不是"很快""正常"这类描述）。
  - `E5` 环境与复现信息：设备状态（`mWakefulness`、网络）、复现率、步骤原文。
- **判据纪律**：不以开发的口头结论为证据；每条结论必须能落到事件码或指标数字。

## 7. 缺陷分级与缺陷单

### 7.1 严重级

| 级别 | 名称 | 判据（满足任一） | 处理时限 |
|---|---|---|---|
| **S1** | 阻塞 | 装不上 / 起不来 / 崩溃循环 / 主流程完全不可用 / 数据丢失或被写坏；**任何脱敏泄露一律 S1** | 立即停线，当轮修 |
| **S2** | 严重 | 核心功能失效但有绕行：≥30% 频道起播失败、故障转移失效、日志/诊断不可用、构建或 CI 红 | 当轮修 |
| **S3** | 一般 | 单场景失败或体验明显受损：个别频道失败、EPG 缺项、焦点死角、卡顿未达阈值的明显退化 | 本轮修，可排后 |
| **S4** | 轻微 | 文案/对齐/图标/偶发问题，不影响使用 | 排期修 |
| **S5** | 建议 | 优化建议，不阻塞任何出口 | 记入待办 |

**自动升级规则**：崩溃/ANR → ≥S2；构建或安装失败 → S1；CI 红 → S2；同一用例重开 ≥2 次 → 升一级并回 G4 评审。

## 9. 真机验收清单

### 9.1 adb 命令序列（复制即用；`<TV_IP>` 用真实内网地址，文档与提交里不写实际值）

```bash
ADB=~/Library/Android/sdk/platform-tools/adb
QA=qa/evidence/<versionName>-<versionCode>; mkdir -p "$QA"

# 0) 探活与设备基线
$ADB start-server
$ADB connect <TV_IP>:5555
$ADB devices -l | grep -w device
$ADB shell getprop ro.product.model
$ADB shell getprop ro.build.version.sdk
$ADB shell getprop ro.product.cpu.abilist
$ADB shell df -h /data
$ADB shell dumpsys power | grep -i mWakefulness

# 1) 装机与版本核对
$ADB install -r app/build/outputs/apk/release/app-release.apk
$ADB shell dumpsys package ilab.iptv.player | grep -E 'versionName|versionCode'

# 2) 清日志并开始抓取（后台）
$ADB logcat -c
$ADB logcat -v threadtime -s 'IPTV/*:V' > "$QA/logcat-$(date +%s).txt" &

# 3) 冷启动（组件名以 §11 D2 冻结值为准）
$ADB shell am start -W -n ilab.iptv.player/<LAUNCH_ACTIVITY>

# 4) 现场证据
$ADB shell screencap -p /sdcard/qa-01.png && $ADB pull /sdcard/qa-01.png "$QA/"
$ADB shell dumpsys meminfo ilab.iptv.player | head -20 > "$QA/meminfo-before.txt"
$ADB shell dumpsys gfxinfo ilab.iptv.player framestats > "$QA/gfxinfo-$(date +%s).txt"
$ADB shell dumpsys activity services ilab.iptv.player | grep -i -A3 foreground

# 5) 取日志文件（Android 11+ 可能受限，见 §11 D3 的替代方案）
$ADB pull /sdcard/Android/data/ilab.iptv.player/files/logs "$QA/logs"
```

> 执行前提：会话必须能监听/连接 `127.0.0.1:5037`。QA 的 temp 会话不能（§2.3），请在有网络的会话或人工终端执行。

### 9.2 指标采集与判据

| 指标 | 采集方式 | 判据 | 来源 |
|---|---|---|---|
| 起播耗时 | JSONL：`PLAY_PREPARE_START` → `PLAY_FIRST_FRAME.costMs` | 平均 ≤3 s；给出 P50/P95 | docs/04 S1、P1 出口 |
| 起播成功率 | 成功首帧次数 / 尝试次数（20 台样本） | ≥90% | docs/04 S1 |

| 冷启动 | `am start -W` 的 TotalTime + `PERF_STARTUP.totalMs` | ≤5 s | docs/04 S6、P2 出口 |

| 稳定性 | logcat 中的 `CRASH` / `ANR` 计数 | 0 | docs/03 §9 |

### 9.3 证据归档

- 目录：`qa/evidence/<versionName>-<versionCode>-<yyyymmdd>/`，含 `logcat-*.txt`、`gfxinfo-*.txt`、`meminfo-*.txt`、截图/录屏、`stats` 摘要。
- **不入仓**：证据可能含内网地址与真实源 URL → 仓库为公开仓库，证据留在本地或私有存储，只在文档中引用文件名与结论。
- 每个阶段出口提交一份《阶段验收报告》（`docs/05-过程记录/06-阶段验收报告.md`），结论必须能追溯到本清单的用例 ID 与证据文件。

### 9.4 长稳流程（L5）

1. 起播一个稳定频道，确认前台服务与常亮已生效；
2. 每 15 min：`dumpsys meminfo` 采样 + 截图 + 检查 `CRASH/ANR`；
3. 期间触发 1 次后台刷新，记录 `SRC_REFRESH_START/DONE` 与是否被播放避让；
4. 2 h 后连续换台 5 次确认仍可用；
5. 判据：无 FATAL/ANR；PSS 增长 ≤10%；刷新完成；日志轮转与清理未报错。
