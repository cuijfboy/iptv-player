## 8. 与文档的差异 / 需要 god 裁决（4 条）

1. **`stream.width` / `stream.height` 是 `NOT NULL`**（§5.1 未标 NOT NULL）。冻结的领域类型是 `Stream.width: Int`（0 = 未知），所以实体跟随领域类型；若将来深检（P2-3）需要写 `NULL`，得先改领域类型或让列可空。
2. **D12 的“用户编辑 > tvg-chno > 自动编号”在 §5.1 里表达不了**：`channel_no` 只有一列、没有“来源标记”。本包取“首写者赢”（已存在则保留，为空才吃源值）；副作用是**源后来改台号不会被刷新**。要真做分层需要新列或用户编辑表 —— 属 P2-2 的输入。
3. **dispatch 里提到的 `subscription` / `settings` / `favorite` 三张表在 §5.1 中不存在**：订阅对应 `source`/`epg_source`，收藏是 `channel.favorite` 列，设置项 §5.1 没有表（P0 结论是走 DataStore）。本卡按 §5.1 实现，未造表。
4. **`play_history` / `metric` 无索引**（§5.1 如此）。因此“按频道查历史”“按名查指标”是扫描；本包**没有加 §5.1 之外的索引**，只把这两条冷路径写进测试与记录。另：频道名文本过滤（`instr(name_key, …)`）无索引可用，已在 `SchemaAndIndexTest` 里**断言它就是扫描**（≈1k 行；真要做搜索应是 P3-2 的 FTS）。
