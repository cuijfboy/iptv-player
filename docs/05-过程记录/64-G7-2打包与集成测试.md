## 6. 已知限制 / 观察项（均不阻断发布）

1. **内置 17 源在本网段对 `raw.githubusercontent.com` 全超时**（电视侧 `SRC_FETCH_FAIL{TIMEOUT, ≈30.3 s}`）——与 `56/57/59/63` 同因，属环境；因此真机「刷新有用」的取证依赖**自持局域网源**（本卡用本机 `http.server`）。
2. **本机 `http.server` 必须常驻**：第一次刷新订阅取源失败（`SRC_FETCH_FAIL provider=sub:-… failure=NET_UNREACHABLE 406 ms`），根因是**后台 `nohup` 起的 `http.server` 随会话退出被杀**、端口已无监听（电视能 ping 通本机、本机 `curl` 自身也 000）；改成常驻会话后同一 URL 一次成功（电视 `GET /lan-source.m3u 200`）。**教训**：真机取证的临时服务要确认「电视真取到」再算数（本机服务器日志是硬证据）。
3. **故障转移需人工夹具**：内置快照是单流频道，无自然主/备；本轮用 debug 包 + Room 造两流频道取证（§4.5），判据本身（失败→备胎出画 ≤5 s）成立。
4. **`PLAY_STALL` 阈值口径**：App 的 `PLAY_STALL` = `EngineTuning.stallThresholdMs = 8000`（比 `62` 号探针的 2 s 宽）；本轮全文 `PLAY_STALL` = 0。
5. **既有 S3 观察（不在本卡判据内）**：`63` §9 记的「播放器页内『上/下』换台到本组末位后不再前进」本轮**未复测**；本轮换台用的是播放器页内逐台前进（`121→130` 同组，正常）。
6. **未做**：定时刷新（`refresh-daily`/`SCHEDULED`）、长稳（连续小时级）、换网络/换出口后的可用性、AC3/EAC3 音频、多台并发。
