## 1. 用途

一张表回答三个问题：**现在有多少缺陷、卡在谁手里、能不能放行出口**。每条缺陷的字段与证据要求见 `03-测试计划与用例.md` §7；缺证据的单子由 QA 打回，不进修复队列。

---

## 2. 字段说明

| 字段 | 取值 / 格式 |
|---|---|
| ID | `BUG-<yyyymmdd>-<nnn>`，按发现日递增 |
| 版本 | `versionName` + `versionCode` + `git rev-parse --short HEAD`（+ APK SHA256 前 8 位） |
| 严重级 | S1 阻塞 / S2 严重 / S3 一般 / S4 轻微 / S5 建议（判据见 03 §7.1） |
| 复现率 | 必现 / 高（≥7/10）/ 中（3–6/10）/ 低（≤2/10）/ 单次 |
| 关联用例 | `TC-xxx-xx`，并写清对应需求 F* |
| 证据 | 事件码 + logcat 片段 / JSONL 会话、截图或录屏、指标数值；**四项必填** |
| 状态 | 新建 / 已确认 / 修复中 / 待验证 / 已关闭 / 重开 / 挂起 |
| 修复人 | 提交修复的作者（不是发现人） |
| 验证人 | QA（只有 QA 能写「已关闭」） |

## 5. 状态流转与规则

```
新建 ──确认──▶ 已确认 ──▶ 修复中 ──提交修复──▶ 待验证 ──QA 复测通过──▶ 已关闭
                                  ▲                 │
                                  └── 复测不通过 ── 重开（计数 +1）
                （S1/S2 停线优先修；挂起需 god 记录理由）
```

- **关闭权**：只有 QA 能关闭；关闭必须附新证据（重跑用例 + 版本三连）。
- **重开**：同一用例重开 ≥2 次 → 严重级升一级，并回 G4 做代码评审复盘。
- **挂起**：`wontfix` 或需人工决策时由 god 记录理由；S1/S2 不允许挂起。
- **脱敏泄露**：一律 S1，当轮修，且要复检导出包与历史日志。
- **与出口的关系**：G6/G7 放行要求 S1/S2 未关闭数为 0；S3 必须有明确排期（见 03 §10）。
