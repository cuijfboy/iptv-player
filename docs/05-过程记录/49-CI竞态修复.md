## 1. 结论摘要

- `CI-FLAKE-1` 的真因是**任务图缺口**，不是代码缺陷：AGP 只把 `lintAnalyze<Variant>` 挂到 `pre<Variant>Build`，**测试变体**（`lintAnalyze<Variant>UnitTest` / `...AndroidTest`）与本变体、被测变体的 **Hilt/KSP 生成任务之间没有任何顺序**；`org.gradle.parallel=true` 下二者并发，生成任务整目录替换 `build/generated/hilt/component_sources/<variant>` 等目录，lint 恰在替换窗口读到 Hilt 生成的 `.java` → `No such file or directory`。
- 修法：在 Hilt 约定插件里给每个 `lintAnalyze*` 任务**显式加上**对应变体与被测变体的 `ksp*Kotlin` / `hiltAggregateDeps*` / `hiltJavaCompile*` 依赖（只加顺序，不改规则）。
- 验证：`./gradlew --offline check` **10 次全绿**（先 5 次带缓存、再 5 次 `--no-build-cache` 且每轮移走 `app/build` 强制 lint 真执行）。
- `DOC-13`：`EpgCoverage` 的 KDoc 从「retention window」追平为「grid window（`EpgGridWindow`）」，**只改注释**。

## 2. 真因（`CI-FLAKE-1`）

### 2.1 缺失的那个文件是谁生成的

- 报错文件 `DaggerIptvApplication_HiltComponents_SingletonC.java` **不是 KSP 产物**。`:app` 的 `kspDebugKotlin` 只产出逐类文件（`Hilt_MainActivity.java`、`IptvApplication_MembersInjector.java` 等，共 30 个），没有 `*SingletonC.java`。
- 该文件由 **Hilt 的聚合 javac 任务** `hiltJavaCompileDebug` 写入 `app/build/generated/hilt/component_sources/debug/`。
  - `find app/build -name '*SingletonC.java'` 只命中 `component_sources/debug` 与 `component_sources/release` 两处。
  - 任务输出（用 init 脚本打印 `outputs.files`）：
    - `hiltJavaCompileDebug` → `build/generated/hilt/component_sources/debug`、`build/intermediates/hilt/component_classes/debug`、`build/tmp/hiltJavaCompileDebug/previous-compilation-data.bin`
    - `hiltAggregateDepsDebug` → `build/generated/hilt/component_trees/debug`
  - 这些目录每次执行都会被**整目录替换**（先删后写），所以读它们的任务一旦并发就是「时有时无」。

### 2.2 任务图缺口（硬证据）

1. **唯一依赖**：`:app:lintAnalyzeDebugUnitTest` 的 `dependsOn` 只有 `preDebugUnitTestBuild`；而 `preDebugUnitTestBuild` 只依赖 `preBuild`。`:app:lintAnalyzeDebug` 同样是 `preDebugBuild → preBuild`。顺序不是 AGP 在这些任务上建立的。
2. **输入集合对不上**：`:app:lintAnalyzeDebugUnitTest` 的 `inputs.files` 里过滤生成目录后**为空**（只剩 `hilt-android` 的 aar/jar）；对照组 `:app:lintAnalyzeDebug` 的输入里含 `build/generated/ksp/debug/java`、`build/generated/ksp/debug/kotlin`、`build/intermediates/hilt/component_classes/debug`、`build/generated/ap_generated_sources/debug/out`。即：测试变体的 lint 读生成源，却没把生成源登记成输入 → 拿不到 builtBy 推断出来的顺序。
3. **改前行序**（`./gradlew --offline check lint --dry-run`，行号为该次输出）：`lintAnalyzeDebugUnitTest` 在 **655**，`kspDebugUnitTestKotlin` **767**、`hiltAggregateDepsDebugUnitTest` **771**、`hiltJavaCompileDebugUnitTest` **772**——生成任务全在 lint 之后，且两段之间无边。

结论：`--parallel` 下 lint 与被测变体的 Hilt/KSP 生成任务并发；生成任务替换 `component_sources/debug`（及 `component_classes/debug`、`generated/ksp/debug/java`）的瞬间，lint 去读其中某个 `.java` → `No such file`。重跑时生成任务已 up-to-date / 命中缓存、文件稳定，故绿——**假红**，符合 docs/04 §8 记录的现象。

### 2.3 复现尝试（诚实记录）

- 症状本身受时序影响，**本机未稳定触发**：`:app:lintAnalyzeDebugUnitTest --rerun-tasks` 与 `--parallel`（同时带上 debug/release/UnitTest 四个 analyze）连跑 3 轮，全绿。
- 缺口是**可稳定复现**的，用下面两条只读命令即可（第 2.2 节的两条证据）：

```bash
# 1) 行序：生成任务排在 lint 之后、且无中间边（改前）
./gradlew --offline check lint --dry-run | rg -n ':app:(kspDebugUnitTestKotlin|hiltAggregateDepsDebugUnitTest|hiltJavaCompileDebugUnitTest|lintAnalyzeDebugUnitTest)'
# 2) 输入集合：测试变体 lint 无生成源输入（对照 debug 变体有）
./gradlew --offline :app:lintAnalyzeDebugUnitTest --dry-run   # 只出现在图里、不产生顺序约束
```

## 3. 修法

在 **Hilt 约定插件** `build-logic/src/main/kotlin/iptv.hilt.gradle.kts` 里加一段接线（一处改动覆盖所有应用 Hilt 的模块：`:app` 与全部 `:feature:*`、Android `:core:*`）：

```kotlin
tasks.matching { it.name.startsWith("lintAnalyze") }.configureEach {
    val analysed = name.removePrefix("lintAnalyze")          // "lintAnalyzeDebugUnitTest" -> "DebugUnitTest"
    val underTest = analysed.removeSuffix("UnitTest").removeSuffix("AndroidTest")  // -> "Debug"
    listOf(analysed, underTest).distinct().forEach { variant ->
        listOf("ksp${variant}Kotlin", "hiltAggregateDeps$variant", "hiltJavaCompile$variant")
            .forEach { tasks.findByName(it)?.let { t -> dependsOn(t) } }
    }
}
```

**为什么是最小修法**：只加任务顺序，不改 lint 规则、不改任何代码路径；不用「CI 里重跑一次」掩盖（真红仍然红，只是发生在源文件稳定之后）。

**接线生效证据**（改后 `./gradlew --offline :app:lintAnalyzeDebugUnitTest --dry-run`）：`kspDebugUnitTestKotlin`(572)、`hiltAggregateDepsDebugUnitTest`(577)、`hiltJavaCompileDebugUnitTest`(578) 现在都排在 `lintAnalyzeDebugUnitTest`(**609**) 之前。
