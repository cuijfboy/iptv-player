### 1.1 规则（3 条，都写成"对本仓库安静"）

| 规则 | 命中什么 | 为什么这样写（防误报） |
|---|---|---|
| `private-ip` | `192.168.x.x`、`10.x.x.x`、`172.16–31.x.x` | 三段式也要求**完整点分四段**，所以版本号 `1.10.2` 不会被当 IP；前导 `[^0-9A-Za-z.]` 保证 `10.0.0.9` 不会在更长的数字/点串里"顺带"命中；**`127.0.0.1` 不算**（环回不是内网资产） |

## 2. 项 2 · `DispatcherProvider` 的 Hilt 绑定

### 2.1 放在哪个模块，为什么

新增 `core/log/src/main/kotlin/ilab/iptv/player/core/log/di/DispatcherModule.kt`（`@Provides @Singleton DispatcherProvider = AndroidDispatcherProvider()`）与实现类 `AndroidDispatcherProvider.kt`。

选 `:core:log` 的理由（可回查）：它是**最低的 Android 模块**，且已经在 `LogModule` 里绑定 `:core:common` 的全部平台默认实现（`Clock`、`Redactor`、`SessionIdFactory`、`Logger`）；`DispatcherProvider` 是同一类东西——纯 Kotlin 冻结接口 + Android 平台默认值。**不新建 `:core:async` 模块**，因为那要动 docs/02 §3.2 的依赖矩阵（本轮边界：不改 docs/01–04）。

### 2.2 五个成员

| 成员 | 实现 | 说明 |
|---|---|---|
| `io` / `default` | `Dispatchers.IO` / `Dispatchers.Default` | §10 表格里"网络/解析"用的两个共享池 |
| `main` | `Dispatchers.Main.immediate` | 已在主线程时不重复派发（§10 UI 行） |
| `single` | 专属单线程 `iptv-single`（daemon） | 串行写者要的是**一个**线程；用共享池会让两个写者交错 |
| `engine` | Looper 支撑的单线程 `playback-engine` | 不是偏好而是**实测要求**：`PlayerEngineFactory.create` 必须跑在 Looper 上（P1-3 量过，纯 dispatcher 在 `buildPlayer` 就失败） |

`main` / `single` / `engine` 都是 `by lazy`：不碰就不建线程、不问 `Looper`——这也让这个类**能在纯 JVM 单测里构造**（§2.4）。

### 2.3 谁开始用注入的调度器（原来是硬编码 `Dispatchers.*`）

| 消费点 | 改动 | 出处 |
|---|---|---|
| `:core:data` `RefreshSourcesUseCase` | 构造注入 `dispatchers`，整条 flow `flowOn(dispatchers.io)` | P2-4a §6 第 3 条 TODO |
| `:core:data` `ChannelCatalogLoader` | `withContext(dispatchers.io)`（原来是 `Dispatchers.IO`） | P2-4a 同类问题 |
| `:core:data` `LocalPlaylistImportRepository` | 三处 `withContext(Dispatchers.IO)` → `dispatchers.io` | P1-8 / 19 报告 §6 第 5 条 |
| `:core:data` `RoomCatalogSeeder` | `withContext(dispatchers.io)` | §4.5 C6 |

**日志 Sink 没有接（明确记为未做，不是忘）**：`core/log` 里唯一的执行线程是 `LogBus` 的分发线程，它自称一个 **`queue.poll(timeout)` 的阻塞循环**（docs/03 §5 也明确要求"单后台线程 + 有界队列"）。把它换成 `provider.single.asExecutor()` 会让该线程被永久占用（`withContext(single)` 的其它调用者会饿死），并破坏它自己的 `InterruptedException` 退出语义——那是**引入 bug**而不是消掉 TODO。日志侧真正合适的接法是 P2-5 服务化时给 log 一个**专属** worker（或把 Executor 一并做成注入项），见 §7 开放项 3。

## 3. 项 3 · 导入后启动报告不更新（dev-a-13 第 ⑧ 条）

**改法**：把"最近一次发布的报告"放在**唯一的写入点**旁边，而不是让每个调用方去补报告。

- `ChannelCatalog`：新增 `@Volatile lastCommitted` + `fun lastReport()`；`commit()` 里**先写 store 再记报告**（读到新数字的人一定能读到对应的 store）。
- `ChannelCatalogLoader.report()`：返回 `catalog.lastReport()`（原来返回自己那次 `ensureLoaded` 的字段，导入走的是另一条路，所以永远停在夹具数字）。
- **`ensureLoaded()` 不动**：它的契约是"这次调用装载了什么、且只装一次"，让它返回导入后的数字会破坏幂等语义。

**单测**（`CatalogReportAfterImportTest`，2 条）：夹具启动 → 报告 1 频道；用**真实** `LocalPlaylistImportRepository` 导入 3 频道清单 → `loader.report()` 变 `local:three.m3u` / 3 频道 / 3 流，且 store 与报告一致；第二条钉住 `ensureLoaded()` 仍然返回**那次装载**（防止以后有人"顺手修错"）。
