## 2. P3-3：音轨 / 字幕 / 过扫描

### 2.1 音轨切换（卡号 1）

- 轨道列表来自 Media3 `Tracks`（引擎侧已在 P1-3/`AudioTracks` 事件里缓存），UI 侧的按钮与菜单由 `AudioTrackState` 决定：**只有 1 条轨时不给菜单**，按钮显示「音轨：1 条」并压暗，按下时在状态行说明「当前流只有一条音轨，无需切换」。
- **即时生效**：选择走 `PlaybackSession.selectAudioTrack(id)` → `Media3Engine.selectAudioTrack`，实现是 `trackSelectionParameters` 上的 `TrackSelectionOverride`，**不重新 `prepare`**（不换流、不出缓冲），与 §7.4「切换时序」不冲突。
- 选择结果由引擎的 `onTracksChanged` 回灌 `PlaybackUiState.audioTracks/selectedAudioTrackId`（C1：状态机仍是唯一写者），因此按钮文案与菜单高亮都跟着真实选中项。
- 菜单行有选中标记（`●`/`○`），DPAD 上下在轨道间移动并**环绕**（2–3 条轨，环绕比到底更省按键）；OK 应用。

### 2.2 字幕开关（卡号 2）

- 引擎新增文本轨能力：`Media3Engine.subtitleTracks()` / `selectSubtitleTrack(id)` / `setSubtitlesEnabled(enabled)`；实现分别是 `TrackSelectionOverride`（`C.TRACK_TYPE_TEXT`）与 `setTrackTypeDisabled(C.TRACK_TYPE_TEXT, !enabled)`，**不重新 prepare**。关闭时**保留 override**，再打开会回到上次选中的轨。
- 状态用 `PlaybackEvent.SubtitleTracks(tracks, selectedId, enabled)` 回灌。`enabled` 与 `tracks.isNotEmpty()` 是两个独立事实：菜单恒以「关闭」为首行（`SubtitleTrackState.options()`），流里没有文本轨时按钮压暗（alpha 0.45）并在按下时说明「当前流没有字幕轨，无法开启」——即卡面要求的「入口置灰并说明」。
- 入口仍可聚焦（压暗但不移除焦点），否则用户无法读到「为什么灰」。

### 2.3 过扫描微调（卡号 3）

- `OverscanPolicy`：7 档 94–106 %（步长 2 %，100 % 为默认，`DEFAULT_INDEX=3`），移动**钳位不环绕**，`scale()` 直接给 `View.setScaleX/Y`。
- 作用对象是**视频容器**（`player_frame`，即 §7.4 所说的「外层容器」），**不进引擎、不做第五种宽高比**；宽高比仍是左右键/「画幅」按钮的四档循环（`AspectRatioCycle` 未改）。
- **持久化**：`OverscanSettings`（`SharedPreferences` 文件 `player-display`，键 `overscan_level_index`），写入走 `apply()`（按键路径不阻塞 UI 线程），读取时钳位，因此手改偏好文件也不会把画面拉出量程。`PlayerViewModel.moveOverscan(±1)/resetOverscan()` 写库并镜像到 `overscanIndex`；屏幕在 `onCreate` 与每次变化时应用。
- 入口 = 信息条上的「过扫描」按钮 → 对话框三行：放大一档 / 缩小一档 / 恢复标准（100 %）。放信息条内、与左右键的宽高比路径分开，符合派单的键位约定。

### 2.4 键位与焦点（对 §8.2 的增量，已在 §7 报备）

- 上下键**仍是换台**（未动），信息条新增的三个控件靠**左右键**到达：`root ↔ 画幅 ↔ 音轨 ↔ 字幕 ↔ 过扫描 ↔ root` 成一条水平链，每个控件上下键自锁。失败卡片出现时 `root` 的左右目标仍是「重试」，与 P1-5 的既有行为一致。

## 3. P3-2：频道搜索

### 3.1 输入方案（遥控数字/方向键，无软键盘）

1. **数字键直输**（最快路径）：物理遥控 `0–9` 直接进查询缓冲，同时点亮屏幕上对应的数字格（让用户看见输入来源）。频道号是最短的查询。
2. **屏幕字母网格 + 方向键**：`SearchKeypad.ROWS` = 1 行数字（0–9）+ 4 行字母（A–Z，末行附 `删除`/`清空`）；方向键移动光标，**到边界钳位、不环绕**；进入更短的行时列号钳位，不会落到不存在的键上。
3. **BACK**：查询非空 → 先清空；已空 → 返回浏览页。

查询长度上限 20，接受 A–Z/0–9/CJK（`SearchInput`）。

### 3.2 索引与匹配口径

- **数据来源**：`ChannelRepository.observe(...)`（不隐藏的频道，与浏览页同序同号：`ChannelSorter` + `ChannelNumberAssigner`，D12）+ `EpgRepository.observeWindow(...)`。EPG 按 **64 台一页**取（§8.3 的单次 64 台上限），窗口 = `[now−1h, now+24h]`，一小时的回顾是为了「19:30 开播、20:05 仍在播」的节目仍能被找到。
- **键（key）**：每个频道最多 3 个键 —— 归一化名、拼音首字母、频道号；每个节目最多 2 个键 —— 归一化标题、拼音首字母。`(频道, 标题)` 去重，避免同一档节目占满结果。
- **归一化**：小写、全角→半角、**丢弃**空格/连字符/点/括号等分隔符，保留字母、数字与 CJK。因此 `cctv1` 是 `cctv1综合` 的前缀，`新闻` 是 `cctv1新闻综合` 的子串；大小写与全角不影响命中。
- **结构**：词条表（flat key table），每条键登记在**它含有的每个不同字符**的桶里；查询只读它首字符所在的桶——键若包含查询则必然包含查询首字符，所以这个桶**恰好**是候选集，不是近似。选它而不是 trie 的原因：遥控要的两种输入是「数字」与「CJK 子串」，后者不是前缀匹配，trie 得索引全部后缀；词条表一次线性打分即可，实测见 §4。
- **排序**：匹配质量（精确 0 / 前缀 1 / 子串 2）× 10 + 键类型加成（频道名 0 < 频道号 1 < 频道拼音 2 < 节目名 4 < 节目拼音 6），再按「正在播出」优先、频道号升序、节目开始时间升序、频道 id、标题。结果上限 60 条。
- **拼音首字母**：种子表约 170 字（央视/卫视/地方台 + 常见节目词），`initialsOf("湖南卫视")="hnws"`、`initialsOf("CCTV1 综合")="cctv1zh"`。**不是完整拼音表、也不区分多音字**（乐→y、重→c），表外汉字不贡献首字母，靠名称子串兜底；限制写在第 §5 节，不藏。

### 3.3 结果页与「跳到当前」

- 结果行两路混排：频道命中 → 打开该频道；节目命中 → 打开该节目所在频道（标题 + `HH:mm–HH:mm` + 频道名 + 「正在播出」标记）。
- 打开动作即 `PlayerContract.intent(channelId)`，与 P3-1 网格里节目行的入口**同一个**（`EpgGridActivity` 第 141 行），所以「命中节目可跳到该频道」是复用既有语义，没有第二套入口。
- 入口：浏览页页头新增「搜索」按钮（同模块直接 `startActivity`，跨 feature 的 action 契约只有 `:core:ui` 那一套）。

## 5. 未做项与限制（如实记录）

1. **真机验证待办（本轮不占电视）**：三个新控件的遥控手感与焦点链、字幕轨在真实 TS 流里的出现与切换、过扫描档位在不同宽高比下的观感、搜索页输入与结果焦点、索引构建在设备上的真实耗时（Room 查询，JVM 基准覆盖不到）。
2. **拼音首字母是种子表**：约 170 字、多音字取常用读音；表外汉字不产首字母。要覆盖全部频道名需要完整拼音表/分词（属 P3-5 数据侧工作）。
3. **索引构建时间未在设备上量**：JVM 侧只量了查询路径；建表要 11 次分页 EPG 查询（658 台 / 64），真机耗时进 §1 的真机待办。界面在索引完成前会明确显示「正在建立索引…」，不会把「还没索引」显示成「没有结果」。
4. **索引不含**：窗口外节目、隐藏频道、节目简介（卡面只要求频道名 + 节目名）。
5. **字幕关闭后重开**回到上次选中轨（override 保留），但若引擎在关闭期间重报了轨道列表（换台/换流），会退回引擎默认选择——真机专项里确认。
6. **事件码**：见 §7 第 1 条（复用 `PLAY_FIRST_FRAME` 并带 `reason=track-change`）。

## 7. 给 god / arch 的裁决点

1. **事件码（P3-3 卡号 1 要求「记事件码」）**：`docs/03 §3.3` 没有「用户换轨」的码，且本轮**不改 `docs/01–04`**（`EventCodes.ALL` 与 `EventCodesTest` 钉在 50 条）。已按派单「没有合适的就复用最贴近的」处理：音轨/字幕变化复用 **`PLAY_FIRST_FRAME`**，带 `reason=track-change`、`kind=audio|subtitle`、`track`、`trackLabel`、`trackEnabled`、`acodec`；理由是它本就是 §7.6「码流直通 HAL/音频路径」的载体，而换轨可能切换解码路径（AC3 直通 ↔ AAC PCM）。**建议登记 `PLAY_TRACK_SELECT`（50 → 51）**，届时把这条复用改掉。
2. **`core:model` 增量字段**：`PlaybackUiState` 增 `subtitleTracks`/`selectedSubtitleTrackId`/`subtitlesEnabled`（带默认值，构造处均用命名参数，兼容旧调用），并新增 `SubtitleTrackInfo` 与 `PlaybackEvent.SubtitleTracks`。属冻结模型 §4.2 的**增量**，请 arch 追认或给出收窄方案。
3. **`core:player` 未改冻结接口**：字幕能力走 `Media3Engine` + `PlaybackSession` 的窄桥（同 `setDucked`/`mediaSessionPlayer`/`snapshot` 的既有先例），`PlayerEngine` / `PlayerContract` / `core:domain` 均未加成员。
4. **信息条新增三个控件**（音轨/字幕/过扫描）与左右键焦点链：§8.1 UI 冻面与 §8.2 键位表的**增量**（上下键换台未变）。请 arch 回写。
5. **搜索页 BACK 两级语义**（非空先清空、再按退出）：§8.1 的返回层级表未覆盖带输入的页面，请 arch 定稿。
6. **`:core:player` 测试期新增 Robolectric 依赖**（`testImplementation`，为过扫描持久化做真读写，与 `:core:data` 的 Room 测试同形）；如需保持该模块零 Robolectric，可改为把 store 移到 `:core:data`，但那会要求 `:feature:player` 看见 `:core:data`（违反 §3.2 规则 2），故本轮选择加测试依赖。
7. **过扫描存储位置**：`OverscanSettings` 放 `:core:player`（不是 `:core:domain`/`:core:data`）。若 arch 认为显示偏好该进设置页（P2-8 的页面目前不持久化任何项），可把 store 提为通用设置端口。
8. **索引结构后续点**：当前结构是「每键登记到其每个字符的桶 + 单桶线性打分」。若 P3-5 把导引拉到百万级节目，或索引要覆盖全量历史，需要换成 trie/倒排；触发条件与规模按 §4 的数字判断（29 796 键、p95 84 ms 时无需换）。
