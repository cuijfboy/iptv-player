## 4. 用例矩阵

### 4.1 `§4.6` 逐行（现象 → 动作）

| `FailureClass`（§4.6 现象） | 配方（`FailureClassPlan.steps`） | 用例（`DefaultFailoverPolicyTest`） | 断言要点 |
|---|---|---|---|
| `HTTP_CLIENT`（403/404/410） | `SwitchTo` | `http client switches at once…` | 立即切；该流**永久降权**；再次决策不会选它 |
| `HTTP_SERVER`（429/5xx） | `Backoff(1s)` → `RetrySame` → `SwitchTo` | `http server backs off, retries once, then switches` | attempt1=`Backoff(1000)`、attempt2=`RetrySame(0)`、attempt3=切 |
| `TIMEOUT`（超时） | `RetrySame` → `SwitchTo` | `timeout retries the same stream once and then switches` | attempt1=重试、attempt2=切 |
| `NET_UNREACHABLE`（DNS/不可达） | `SwitchTo` | `network tls parse empty media and unknown switch without retrying` | 不重试，直接切 |
| `TLS` | `SwitchTo` | 同上 | 直接切 |
| `PARSE` | `SwitchTo` | 同上 | 直接切 |
| `DECODE_UNSUPPORTED` | `SwitchTo` + codec 记负权 | `unsupported codec switches and marks the codec combination` | 切；`demoteCodecCombination=true`；不永久降权 |
| `DECODE_CORRUPT` | `RetrySame` → `SwitchTo` | `corrupt decode retries once then switches` | 重试一次再切 |
| `EMPTY_MEDIA` | `SwitchTo` | 同 `network…` | 直接切 |
| `PLAYLIST_GONE`（候选全失效） | `ResolveFresh` → `GiveUp` | `playlist gone resolves fresh once and then gives up` | 先按需复检，再放弃（`userMessage`=「该频道暂时不可用」） |
| `NO_CAPABILITY`（设备不支持） | `RetrySame`（关透传）→ `SwitchTo` | `no capability retries without passthrough once, then switches` | `retryWithoutPassthrough=true`；重试一次再切 |
| `STORAGE` | 不切换、上报降级 | `storage and permission report instead of switching` | `GiveUp`、`emitsFailoverEvent=false`、`logCode=DB_FAIL` |
| `PERMISSION` | 引导授权、不重试 | 同上 | `GiveUp`、不发 `PLAY_FAILOVER`、有 `userMessage` |
| `CANCELLED` | 不算失败 | `cancellation is not a failure` | `GiveUp`、不发 `PLAY_FAILOVER`、`logCode=PLAY_END` |
| `UNKNOWN` | 记 ERROR + `SwitchTo` | 同 `network…` | 直接切 |

映射表本身另有 `FailureClassPolicyTest` 9 条：`every failure class has exactly one row`、`every row logs a registered event code`、`the retryable column matches the AppError factories`（逐类交叉核对 `AppError.retryable`）、`the recipes match the doc rows`、`only the doc's two rows ask for a special demotion`、`storage permission and cancellation never fail over`、`the no-backup path carries a user message` 等。

### 4.2 看门狗三类判定与误报边界（`PlaybackWatchdogTest`）

| 现象 | 触发线 | 用例 | 边界（必须不触发） |
|---|---|---|---|
| 起播超时 | `prepareTimeoutMs`（默认 12 s，= `PlaybackRequest.timeoutMs`） | `prepare timeout fires at the threshold and not before`、`the prepare clock restarts with the next stream` | 11 999 ms 不报；首帧到达后永不再报（`a first frame takes the start-up timeout off the table`）；准备期间的采样不清零计时（`samples during preparation do not clear the start-up timeout`） |
| 长时间无进度 | `progressThresholdMs`（默认 8 s，= `FailoverLimits.stallThresholdMs`） | `a frozen position is not a stall until the threshold` | 7 999 ms 不报；位置一旦前进就重置锚点（`progress resets the anchor so a short jitter never switches`）；暂停期间永不判（`a paused stream never stalls`） |
| 卡顿（缓冲停滞） | `bufferingThresholdMs`（默认 8 s） | `a buffering window that does not advance becomes a stall` | 缓冲中若位置仍在前进则重置窗口（`a buffering window restarts while the position still moves`）；离开缓冲回到进度口径（`leaving buffering returns to progress accounting`） |
| 无现象 | — | `an idle or stopped watchdog never reports`、`polling before the first sample reports nothing` | IDLE/STOPPED 恒 `Ok` |

调度契约（无 Looper/Handler）：`nextDeadlineMs()` 给出下次该被询问的时刻，`poll(nowMs)` 用最后一个采样重判，控制器用 `delay(nextDeadlineMs - clock.nowMs())` 驱动 —— 二者各有用例（`the next deadline follows the phase`、`poll re-judges the last sample without a fresh one`、`the injected clock supplies the default timestamps`）。

### 4.3 备胎选择 / 降权 / 无备胎路径

| 行为 | 用例 |
|---|---|
| 同频道备胎优先，排序键 = `score desc → priority asc → lastOkAt desc(null 最后) → id asc`（`§4.3` 冻结键） | `the best-scoring backup wins, ties break on priority, lastOkAt then id`、`a null lastOkAt sorts behind a known-good timestamp`、`candidates come from the same channel and are ranked without the active stream` |
| 不切回正在播的流 / 不放 `disabled` 流 | `never switch to the stream that is already playing`、`disabled streams are never a target` |
| 连续失败降权（冷却） | `a fresh failure streak drops the stream behind a healthy one`、`the session health view demotes a stream the persisted count does not know about`、`a single failure does not demote`、`tuning controls how long a streak has to be and how long it lasts` |
| 冷却窗口过期即恢复原排序 | `the demotion expires once the cooldown window closes` |
| 无备胎（`docs/01 F4` 常态，417/579） | `a single-stream channel retries, re-probes once, then gives up`（重试 → 按需复检 → `GiveUp`+提示，且复检预算只花一次） |
| 会话预算：`maxSwitchPerSession`、新会话/换台重置 | `the switch budget caps one session`、`a new playback session clears the demotions and the switch budget`、`switching channel resets the session automatically` |
| 看门狗路径（`§4.6` 尾注） | `a stall under the threshold holds the stream`、`a stall over the threshold backs off then switches`、`a stall with no backup resolves fresh instead of switching` |
| 零重试预算 | `a zero retry budget turns the retry row into an immediate switch`、`a zero retry budget skips the http server backoff too` |

## 5. 语义约定（控制器必须照此传参，否则行为不同）

| 参数 | 约定 | 依据 |
|---|---|---|
| `FailoverInput.attempt` | **同一条流在本会话内的第几次失败，从 1 开始**（1 = 首败，2 = 重试后仍失败…）；换源成功后由控制器重置为 1 | 冻结的 `FailoverLimits.maxRetrySame`（默认 1 = 同流最多重试一次）与 `§4.6` 的 `RetrySame(≤1)` 需要它 |
| `FailoverAction.RetrySame.delayMs` | 立即重试时为 0；`§4.6` 只给超时/损坏流写 `RetrySame`（无等待），1 s 等待只出现在 429/5xx 的 `Backoff` 与停滞路径 | `§4.6` 三行原文 |
| `FailoverAction.Backoff.delayMs` | 「等一会儿再问我」，**永不自己切源**；`0` 表示「保持当前流」（用于阈值以下的抖动） | `§4.6`/`§6.2` |
| `ResolveFresh` 预算 | 每个播放会话、每个频道**至多一次**（`RefreshTrigger.ON_DEMAND_SINGLE_CHANNEL`）；`FailoverLimits.allowFreshResolve=false` 时直接跳过 | `docs/01 F4` 无备胎组口径 |
| 冷却降权输入 | 失败连击取 `max(StreamHealth.consecutiveFails, Stream.failCount)`，新鲜度取 `max(StreamHealth.lastOkAtMs, Stream.lastCheckAtMs)`；两个阈值在 `FailoverTuning`（`cooldownMs=60 s`、`demoteAfterConsecutiveFails=2`） | 本包实现，`§4.3` 未冻结该阈值（见 §7） |
