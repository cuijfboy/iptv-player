## 2. 设计要点与取值出处

| 项 | 实现 | 出处 |
|---|---|---|
| 路径 | `/sdcard/Android/data/ilab.iptv.player/files/logs/`（`getExternalFilesDir(null)/logs`，无存储权限，adb 可 pull） | §6 |
| 文件命名 | `iptv-yyyyMMdd.log`（当天）；段文件 `iptv-yyyyMMdd.N.log`（N 从 1 起，取当天最大段号 +1，不覆盖） | §5/§6 |
| 轮转 | **按天 + 单文件 2 MB 双阈值**：跨天切到新日期文件；超过 2 MB 把当前文件改名为段文件、基础文件名重新开始（最新数据始终在基础文件） | §6 |
| 判断依据 | 以**磁盘上的真实文件大小**为准（每次写前 stat 一次）；不是只看内存计数——脚本/上一会话写大的文件也会被轮转 | 本卡（加固） |
| 保留/清理 | 保留 **7 天** / **总量 50 MB** / **份数上限 12**；删除优先级 **过期 → 更早日期 → 当天段文件（最后才动）**；**活跃 base 文件与当天 base 文件永不删**；**当天段文件不受份数上限约束，只受总量 50 MB 约束**（超总量按最旧先删） | §6 + god 裁决 2026-09-22（BUG-011，细见 §9.2） |
| 清理时机 | 启动后首次写入 + 每次轮转后；`FileSink.cleanupNow()` 供「立即清理」按钮与将来的「每次刷新结束」调用 | §6/§7.3 |
| 写入线程 | 只跑在 `LogBus` 单后台线程（append 一次 = 开/写/关，无用户态缓冲，进程被杀不丢已写行） | §5 |
| flush 契约 | `Logger.flush()` → `FileSink.flush()` → `FileOutputStream(fd).sync()` 强制落盘；文件不存在时不建空文件（仅记 `syncFailures`） | §5 |
| 写失败降级 | 捕获一切异常：计数 + 记原因 + **退避 60 s 内不再尝试**（不崩、不空转、不死循环），窗口过后自动重试并自愈 | §5（sink 不许抛） |
| 开关与级别 | 文件开关 `FileSink.enabled`（默认开，设备页可切）；级别沿用 `LogBus.minLevel`（默认 INFO，可切 DEBUG/VERBOSE）→ 落盘量随之变化 | §3.1/§14 |
| 脱敏（**分级口径**，BUG-010 修正） | **已覆盖**：URL 查询参数（`token`/`key`/`pwd`/`pass`/`sign`/`auth`/`secret`/`expire` → `***`）与 URL userinfo（`user:pass@` → `***@`）；message/fields 统一走 `LogBus` 的 `Redactor`，`FileSink` 再对 `Redactor` 未覆盖的部分（error 的 type/message/stack）补一次。**未覆盖**：URL 路径 hash 化（`scheme://host` + 路径 8 位 hash）与精确内网 IP → `<redacted>`——即 `docs/03` §11 的五类规则中**已实现 2 类**。**何时覆盖**：随导出包（§8 / L6）与 **L8** 一并做（`docs/03` §13 记 L8「未开始」） | §11 + §13（细见 §9.1） |
| 行格式 | JSONL，键顺序 `seq, ts, level, category, code, message, fields, sessionId`，随后追加 `elapsedMs, thread`（+仅在存在时 `screen`、`error{type,message,stack}`） | §4 |

> **行格式说明**：§4 的示例是那 8 个键；这里在示例之后**追加** `elapsedMs/thread/screen/error`。理由是落盘副本要承担「事后回溯」（§1 的多出口定位），`elapsedMs` 是卡顿定位字段（§4）、`thread` 是线程归因、`error` 是崩溃/失败堆栈（§11 明确保留堆栈）。追加键不破坏 JSONL 读取（`jq`），若评审要求严格等于示例，删掉这 4 处 append 即可。

## 6. 未做项与需要 god 裁的口径

1. **份数上限 12 是默认值，不是文档写死的**：§6 只写了「2 MB / 7 天 / 50 MB」。取值理由：12 × 2 MB = 24 MB，给单个话痨日一个硬上限，且永远不与 50 MB 预算打架。**（已定，2026-09-22）**：DOC-4 把 12 写进 `docs/03` §6；BUG-011 修复包进一步把它限定为「只删更早日期」，当天段文件改由 50 MB 封顶——见 §9.2。
2. **默认级别口径冲突**：§3.1 的「默认落盘」列是 INFO+，§6 的开关行写「默认开，WARN+」。本实现按 §3.1（INFO+，因为级别表是系统性表述），文件出口不再自带级别过滤，而是接收 `LogBus` 放行的事件。建议文档批次统一为 INFO+。
3. **「每次刷新结束」清理钩子未接**：刷新管线是 P2-4，尚未存在；`FileSink.cleanupNow()` 已就绪（设备页「清理旧日志」按钮即用它）。
4. **开关/级别未持久化**：§14 要求存 DataStore，设置页是 P2-8；当前是进程内开关（设备页可切），冷启动回到默认值。
5. **`CrashSink`（L4）与导出包二次 `Redactor`（L8/P3）未做**：本次只到 L3；崩溃文件命名/保留 5 份见 §5/§9 的后续卡片。
6. **计数是进程内计数**：设备页的「写入/轮转/删除/写失败」在冷启动后归零；跨进程的真相是磁盘上的文件（清单与大小）。
7. **`elapsedMs/thread/screen/error` 是 §4 示例之外追加的键**（见 §2 说明），需要评审确认。

### 9.2 BUG-011 · 保留策略：当天数据受保护（已改代码）

god 裁决的三条规则，逐条落在 `LogFilePolicy.cleanupPlan()`：

1. **当前活跃的 base 文件永不被删**：既有的「活跃文件不进候选」保留，并**加固**——当天 base 文件名（`iptv-<今天>.log`）**始终**受保护，这样设备页在没有打开文件时点「清理」也不会删掉当天文件。
2. **删除优先级 = 过期文件 → 更早日期 → 当天段文件（最后才动）**：候选按 `(日期, 段号, 文件名)` 排序后分三趟处理——① 先删超过 `retentionDays` 的过期文件；② 再看**份数上限**（只从**更早日期**里删，最旧先）；③ 最后看**总量 50 MB**（从全体候选按最旧先删，因此更早日期先于当天段文件）。
3. **当天段文件不受份数上限约束，只受总量 50 MB 约束**：`maxFileCount` 只在「更早日期」的候选上生效；当天段文件只会在超 50 MB 时按最旧的先删。即话痨日可以突破 12 份，但封顶在 50 MB。

设备页「清理」按钮（`LogConsoleActivity` → `FileSink.cleanupNow()` → 同一个 `cleanupPlan`）**行为一致**，无需另改：新增单测 `the manual cleanup keeps today's segments and reaps an earlier day instead` 钉住。

边界用例（新增 7 条，逐条对 QA 场景）：

| 用例 | 场景 | 期望 |
|---|---|---|
| `the copy ceiling never reaps the day's own segment files` | 当天 base + 5 个当天段，上限 3 | 计划为空（当天一概不删） |
| `the copy ceiling still reaps earlier days while today is chatty` | 当天 5 份 + 更早 3 天，上限 3 | 只删那 3 个更早日期，最旧先 |
| `over the byte budget earlier days go before the day's own segments` | 4 份各 100 B，预算 250 B | 先删昨天，再删当天最旧段，到 200 B 即停 |
| `today's base file is never deleted even when it alone blows the budgets` | 当天 base 900 B、预算 50 B（活跃/未活跃两种入参） | 计划为空 |
| `deletion order is expired, then earlier days, then the day's own segments` | 过期件 + 昨天 + 当天段，上限 3 + 预算 260 B | 顺序：过期件 → 昨天；当天段不动 |
| `the manual cleanup keeps today's segments and reaps an earlier day instead`（`FileSinkTest`） | 真实 sink + 假 FS，设备页「清理」路径 | 删 1 个更早日期，当天段全留 |
| `a chatty day keeps all of its rotated segments on a real filesystem`（`FileSinkPipelineTest`） | 真实 `LogBus` + 真实文件系统 | 只删更早日期，当天 base 与 4 个段全留 |
