## 2. 设计要点与取值出处

| 项 | 实现 | 出处 |
|---|---|---|
| 路径 | `/sdcard/Android/data/ilab.iptv.player/files/logs/`（`getExternalFilesDir(null)/logs`，无存储权限，adb 可 pull） | §6 |
| 文件命名 | `iptv-yyyyMMdd.log`（当天）；段文件 `iptv-yyyyMMdd.N.log`（N 从 1 起，取当天最大段号 +1，不覆盖） | §5/§6 |
| 轮转 | **按天 + 单文件 2 MB 双阈值**：跨天切到新日期文件；超过 2 MB 把当前文件改名为段文件、基础文件名重新开始（最新数据始终在基础文件） | §6 |
| 判断依据 | 以**磁盘上的真实文件大小**为准（每次写前 stat 一次）；不是只看内存计数——脚本/上一会话写大的文件也会被轮转 | 本卡（加固） |
| 保留/清理 | 保留 **7 天** 或 **总量 50 MB**，先删最旧；另加**份数上限 12**（见 §6 未写死项） | §6 |
| 清理时机 | 启动后首次写入 + 每次轮转后；`FileSink.cleanupNow()` 供「立即清理」按钮与将来的「每次刷新结束」调用 | §6/§7.3 |
| 写入线程 | 只跑在 `LogBus` 单后台线程（append 一次 = 开/写/关，无用户态缓冲，进程被杀不丢已写行） | §5 |
| flush 契约 | `Logger.flush()` → `FileSink.flush()` → `FileOutputStream(fd).sync()` 强制落盘；文件不存在时不建空文件（仅记 `syncFailures`） | §5 |
| 写失败降级 | 捕获一切异常：计数 + 记原因 + **退避 60 s 内不再尝试**（不崩、不空转、不死循环），窗口过后自动重试并自愈 | §5（sink 不许抛） |
| 开关与级别 | 文件开关 `FileSink.enabled`（默认开，设备页可切）；级别沿用 `LogBus.minLevel`（默认 INFO，可切 DEBUG/VERBOSE）→ 落盘量随之变化 | §3.1/§14 |
| 脱敏 | 统一走 `LogBus` 的 `Redactor`（message+fields），`FileSink` 再对 `Redactor` 未覆盖的部分（error 的 type/message/stack）补一次 | §11 |
| 行格式 | JSONL，键顺序 `seq, ts, level, category, code, message, fields, sessionId`，随后追加 `elapsedMs, thread`（+仅在存在时 `screen`、`error{type,message,stack}`） | §4 |

> **行格式说明**：§4 的示例是那 8 个键；这里在示例之后**追加** `elapsedMs/thread/screen/error`。理由是落盘副本要承担「事后回溯」（§1 的多出口定位），`elapsedMs` 是卡顿定位字段（§4）、`thread` 是线程归因、`error` 是崩溃/失败堆栈（§11 明确保留堆栈）。追加键不破坏 JSONL 读取（`jq`），若评审要求严格等于示例，删掉这 4 处 append 即可。

$ adb shell wc -l …/logs/iptv-20260922.log  # → 3（879 B，恢复后新事件已续写）

## 6. 未做项与需要 god 裁的口径

1. **份数上限 12 是默认值，不是文档写死的**：§6 只写了「2 MB / 7 天 / 50 MB」。取值理由：12 × 2 MB = 24 MB，给单个话痨日一个硬上限，且永远不与 50 MB 预算打架。若要求严格照文档，只需改 `LogFilePolicy.DEFAULT_MAX_FILE_COUNT`。
2. **默认级别口径冲突**：§3.1 的「默认落盘」列是 INFO+，§6 的开关行写「默认开，WARN+」。本实现按 §3.1（INFO+，因为级别表是系统性表述），文件出口不再自带级别过滤，而是接收 `LogBus` 放行的事件。建议文档批次统一为 INFO+。
3. **「每次刷新结束」清理钩子未接**：刷新管线是 P2-4，尚未存在；`FileSink.cleanupNow()` 已就绪（设备页「清理旧日志」按钮即用它）。
4. **开关/级别未持久化**：§14 要求存 DataStore，设置页是 P2-8；当前是进程内开关（设备页可切），冷启动回到默认值。
5. **`CrashSink`（L4）与导出包二次 `Redactor`（L8/P3）未做**：本次只到 L3；崩溃文件命名/保留 5 份见 §5/§9 的后续卡片。
6. **计数是进程内计数**：设备页的「写入/轮转/删除/写失败」在冷启动后归零；跨进程的真相是磁盘上的文件（清单与大小）。
7. **`elapsedMs/thread/screen/error` 是 §4 示例之外追加的键**（见 §2 说明），需要评审确认。
