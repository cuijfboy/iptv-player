## 4. 频道号编辑与 D12 优先级（派单项 2，规则写清）

**规则（本轮实现口径）**：`channel.channel_no` 一列即"该频道显示的号"，优先级按 docs/01 D12：

1. **用户编辑**（最高）——`setChannelNo(id, n)` 写入该列；
2. **源 `tvg-chno`**——导入/刷新时由解析器写入该列（P2-1 已如此）；
3. **自动编号**——列为空时，`ChannelNumberAssigner` 按**列表渲染顺序**取最小未占用正整数。

**"删除编辑后回落"**：`setChannelNo(id, null)` 清空该列。
- 立即：列空 ⇒ 落到**自动编号**（第 3 档）；
- 下一次导入/刷新：源再次供 `tvg-chno`，`upsertAll` 的 `existing.channelNo ?: incoming.channelNo` 会把空列填回 ⇒ 落到**源号**（第 2 档）。

**三态单测**：`ChannelNumberAssignerTest` 新增两条——一条把三档放在一份列表里逐档验证 `number` 与 `source`（`USER_EDIT` / `SOURCE_TVG_CHNO` / `AUTO`）；一条验证"删除用户编辑后依次回落到源号、自动号"。持久化侧另在 `ChannelManagementPersistenceTest` 验证"清空后为 null、再导入回填为源号"。

**已知限制（详见 §9.1）**：§5.1 的 `channel` 表只有一个 `channel_no` 列、**没有"谁写的"标记列**，所以"用户编辑"和"源 `tvg-chno`"共用一列，UI 无法把某个已存的号标成"编辑"。这是 P2-1 就报给 god 的同一处（`worker-dev-a-11` 记忆 §8②）。

## 5. 列表页操作入口，遥控可达（派单项 3）

一个频道一个动作对话框，四条遥控路径都能到达，全程不需要触摸屏：

| 入口 | 键位 |
|---|---|
| 打开动作 | **长按 OK/Enter**（`setOnLongClickListener`）或 **MENU 键**（行内 `setOnKeyListener`） |
| 选择动作 | 对话框 `setItems` 的项本身可获焦，上下键移动、OK 选中 |
| 编辑号 | 对话框内 `EditText`（数字键盘，系统输入法遥控可操作），保存校验 > 0 |
| 取消 | 返回键关对话框（docs/02 §8.1 返回键层级不变） |

动作六项：加入/取消收藏、隐藏/取消隐藏、上移、下移、编辑频道号、清除频道号。

配套两个列表级开关（页头，DPAD_UP 可达）：
- **只看收藏** ⇒ `ChannelFilter.favoritesOnly`；
- **显示隐藏** ⇒ `ChannelFilter.includeHidden`（否则"隐藏"是无回头路的：被隐藏的行不满足 `includeHidden=false`，就再也点不到）。

移动范围**限于本分组**（docs/02 §5.1 / §8.1：`group_key` 是组身份，跨组不移动）；`reorder` 重写该组整段 `sort_order`（一次事务）。

## 6. 台标加载（派单项 4）

- **加载库**：Coil **2.7.0**（Views 线，仓库无 Compose），新增到 `gradle/libs.versions.toml` 与 `:feature:channels`。Coil 自带 OkHttp 取回器，复用仓库已有的 OkHttp **4.12.0**，不引入第二套 HTTP 栈。
- **磁盘缓存**：`ChannelLogoLoader` 建一个进程级 `ImageLoader`，`DiskCache` 目录 `cacheDir/channel-logos`，上限 **64 MB**；`respectCacheHeaders(false)`，让离线冷启动也能用缓存里的台标。
- **占位**：底层仍是 P1-2 的初始字母方块（`channel_logo_initial`），Coil 把真图绘到上层 `ImageView`；失败时清空上层 ⇒ 占位自然露出，**不崩、不裂**。
- **不阻塞列表**：`load()` 异步、行复用自动取消在途请求；`crossfade(false)` 去掉逐行动画。
- **失败按事件码记录**：`ChannelLogoLoader.bind` 的 `onError` 回调到 `BrowseActivity`，用**已注册**的 `NET_REQ_FAIL`（`category=NET`，`fields: kind=logo / screen= / url=`）记一条。

**URL 与缓存键策略**（`LogoPolicy`，纯 Kotlin、可单测）：
- `normalize`：空/纯空白 ⇒ `null`（不发起请求）；非 `http(s)` 协议（相对路径、`file://`、`htp://` 拼写错误）⇒ `null`；`http://` 无主机 ⇒ `null`；其余原样返回（`HTTP://` 大小写不敏感）。
- `cacheKey`：去 **fragment** 的 URL。fragment 不改变服务端字节，却是不同的字符串；按原串做键会把同一张图抓两遍、存两份。键显式传给 Coil 的 `memoryCacheKey` / `diskCacheKey`。

## 9. 规则说明（哪些是本轮**定**的，哪些是**沿用**的）

### 9.1 D12 的持久化限制（**本轮最重要的口径**）

§5.1 的 `channel` 表只有 `channel_no` 一列、没有来源标记列，所以 D12 的前两档**在库里无法区分**。本轮取"安全的一半"：编辑被尊重、再次编辑仍最高优先、清空后回落（自动→源号）。**代价**：列表不显示"编辑 / 源"标签（无法区分，就不能瞎标）。

**建议的正解**（须走 arch 提案 → god 批准 → docs/02 版本递增，本轮无权做）：加一列 `channel_no_user`（或一张用户编辑表），`channel_no` 归源侧、`channel_no_user` 归用户侧，则三档可完全区分、清空后立即回落源号。这与 `worker-dev-a-11`（P2-1）报的 §8② 是同一处。

### 9.2 排序键变更（P1-2 明确留给 P2-2 改）

`ChannelSorter` 的比较键由「分类 → group_key → **频道号** → 手工顺序 → 名 → id」改为「分类 → group_key → **手工顺序** → 频道号 → 名 → id」。原因：**"移动"是显示顺序编辑**，若频道号在前，被移动的频道下次重建列表就弹回原位（真实播放列表绝大多数带号）。所有行默认 `sort_order = 0`，无手工顺序时仍落到频道号 ⇒ **默认观感不变**。P1-2 记录 §12 已写明"列表排序键是本包自定，P2-2 可改一处"。

### 9.3 事件码

台标失败复用 **`NET_REQ_FAIL`**（`kind=logo` 区分）。**没有新增事件码**：`core:common` 的 `EventCodesTest` 把注册表长度钉在 50 并注明"与 docs/03 §3.3 表一致"，加码就需要回写 `docs/03`，而本轮不改 `docs/01–04`。若要独立可观测，建议 arch/god 批一条 `UI_LOGO_FAIL` 并回写 docs/03（50 → 51）。

### 9.4 Coil 版本与依赖守护

Coil 是三方库，不触碰 §3.2 的模块守护；`verifyModuleDependencies` 仍 OK。`:feature:channels` 允许声明三方库（守护只约束 `:core:*` 项目依赖）。
