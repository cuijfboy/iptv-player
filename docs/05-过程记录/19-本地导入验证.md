## 2. 导入方式（为什么是「显式路径」而不是 SAF）

**选的是显式路径**（题面允许二选一，选简单可靠的那个）。两个目录都在 **App 自己的外部私有目录**里：

```
放文件：/sdcard/Android/data/ilab.iptv.player/files/playlists/     ← 也支持 .m3u8 / .txt
留拷贝：/sdcard/Android/data/ilab.iptv.player/files/imports/       ← last-import.json + 清单拷贝
```

四条理由：

1. **不需要任何存储权限**——是 App 自己的目录，绕开了 scoped storage 与 `PERMISSION` 失败类；
2. **`adb push` 直接可用**，这正是 QA 的姿势（P1-8 已实测该目录 `shell` 用户可读可写：`13-P1-8日志落盘验证.md`）；
3. **不依赖 TV 上是否存在 DocumentsUI**（`ACTION_OPEN_DOCUMENT` 在 Android TV 上并非必然可用，属无法预先证实的风险，而本轮又不能用真机验证它）；
4. 评审 R-27 提的 `takePersistableUriPermission` 那一套属于「设置页订阅源管理」，留给 P2-6 正篇，不必在这一轮先把权限面打开。

**代价（如实写）**：用户无法从任意路径（U 盘、下载目录）挑文件，只能放进上面这个目录。UI 的「没有找到文件」提示里直接给出了目录和 `adb push` 命令，所以这条路是可发现的、不需要看文档就能走。

**另有一条上限**：单个文件超过 §4.4 `PipelineLimits.maxBytes`（8 MB）按「不像是播放列表」拒绝，错误文案写明实际大小。理由是别的位置都有这个字节上限（Fetch 阶段），本地导入若没有，就会成为唯一能把内存吃掉的入口。口径复用既有常量，没有另立数字。

**落库语义（本轮自定的最小口径）**：导入的清单**替换**当前频道表（`ChannelStore.replaceAll`），内置 `demo.invalid` 夹具只在「没有导入过」和「恢复失败」时出现。理由：夹具本来就是合成表，真机上出不了画面，混排只会让 QA 分不清哪条是真的。多份清单并存/合并属 P2-4+P2-6 正篇。

## 4. QA 怎么用（端到端步骤）

> 前提：设备已装本轮（或之后含本功能的）包；`adb` 可用；电视在线（`adb connect <电视内网 IP>:5555`）。

**4.1 推一份清单进去**

```bash
# 首次：App 没跑过时目录还不存在，先建目录（跑过一次 App 后目录已存在，可跳过）
adb shell mkdir -p /sdcard/Android/data/ilab.iptv.player/files/playlists

# 推文件（M3U / TXT 都行）
adb push my-list.m3u /sdcard/Android/data/ilab.iptv.player/files/playlists/

# 确认推到了
adb shell ls -l /sdcard/Android/data/ilab.iptv.player/files/playlists/
```

**4.2 在电视上导入**

1. 打开 App → 进入「频道表」页（`BrowseActivity`）；
2. 用遥控器按 **上** 键把焦点移到「导入播放列表」按钮，按 OK；
3. 弹窗列出文件（`名字 · 大小 · 修改时间`）——选 `my-list.m3u`，按 OK；
4. 屏幕下方 Toast 显示：`已导入 my-list.m3u：N 个频道 / M 条流（m3u）`；
5. 列表**当场刷新**，头部统计行（频道/分组/流）变成导入的数字；点任一频道应能进播放页。

**4.3 验证证据（建议逐条取证）**

```bash
# ① 事件：解析成功 + 归一化数字（provider 形如 local:my-list.m3u）
adb logcat -d | grep -E "SRC_PARSE_OK|SRC_DEDUPE" | tail -5

# ② 拷贝与记录真的落盘了
adb shell ls -l /sdcard/Android/data/ilab.iptv.player/files/imports/
adb shell cat /sdcard/Android/data/ilab.iptv.player/files/imports/last-import.json

# ③ 重启后仍可用（这是本卡的关键验收点）
adb shell am force-stop ilab.iptv.player
adb shell am start -n ilab.iptv.player/.MainActivity
# 进频道表页：头部统计应仍是导入的数字（不是内置夹具的 658）；再看一眼日志：
adb logcat -d | grep "remembered import restored" | tail -2

# ④ 失败分支（可选，证明坏文件不会冲空列表）
adb shell "echo 'not a playlist' > /sdcard/Android/data/ilab.iptv.player/files/playlists/junk.m3u"
# 再走一遍 4.2：应弹 Toast「清单里没有可用频道（共 N 行…）」，且列表不变
```

**判据**：① 头部数字 = 导入清单的真实频道数（不再是 658）；② `imports/` 下有 `last-import.json` 与同名拷贝；③ 重启后编号不变；④ 坏文件被拒且原列表仍在。
