**`BUG-20260922-014` 的复现实验（3 条独立证据，逐条可重跑）**：

1. 电视上跑 `nc <host> 80` 手工发 `GET`（含 `Host` / `Connection: close`）→ **`HTTP/1.1 200 OK`**（`东丰` = `stream5.jlntv.cn`、`嘉峪关综合` = `play.kankanlive.com`、`泸县新闻综合` = `lxfile.lxxcb.cn` 三条都是）。
2. 同一时刻 QA 机器上 `curl` 同一 URL → `200 / 206`。
3. 从电视发**同样的请求但换 header**（`Accept-Encoding: gzip`、`User-Agent: ExoPlayerLib/1.6.1`、`User-Agent: Dalvik/…BRAVIA…`、`Connection: keep-alive`、一个连接连发两次、`HTTP/1.0`、无 header）→ **全部 200**。

即「请求内容」不是变量，**变量在 App 的 HTTP 栈**。重试同一频道 2 次仍稳定复现 605（`evidence/P1G/item1-retry.csv`）。
**未定因**：该网段所有域名都解析到 198.18.0.0/15（fake-IP），HTTP 实际经 `iLabRouter` 中转；不排除中转件对 App 侧连接（HttpURLConnection/Media3）与裸 socket 有不同处理。**本轮不给出根因**，建议在正常网络复跑这 4 条以定性；这直接决定这条算「应用缺陷」还是「环境限制」。

> **对判据的影响**：即便按最宽的口径（把 4 条源侧失效全部剔除），起播成功率仍是 **75% < 90%**；按原样（20 条）是 **60% < 90%**。**两种口径都不达标**，所以第 1 项判 ❌，结论不依赖对 `BUG-014` 的定性。

### 2.5 长稳（**45 min 采样，不是 2 h 验收**）

### 2.7 导入入口（`TESTABLE-1`）——**不通过**

**现象**：`/sdcard/Android/data/ilab.iptv.player/files/playlists/` 里放好 `real-list.m3u`（151,265 B，`adb push` 成功）后，进频道表页 → 上键到「导入播放列表」→ OK：弹窗只有**标题 + 提示文案 + 「取消」**，**没有任何候选文件行**（复现 2 次，另外在 as-shipped 包上复现 1 次）。用户无法选中文件，导入走不下去。

**对照**（证明弹窗本身会渲染、而且是「有文件」的那条分支）：目录里**没有**文件时，同一个入口弹出的是「没有找到可用文件。把 .m3u / .m3u8 / .txt 播放列表放到 …」+「知道了」——即 `browse_import_empty` 分支，显示正常。

**根因（已定位到平台源码）**：`BrowseActivity.openImportPicker()` 用的是
`AlertDialog.Builder(...).setMessage(hint).setItems(labels){…}`。
AOSP `AlertController.setupContent()`（`com/android/internal/app/AlertController.java`，Android 36.1 源码，本机 `$ANDROID_HOME/sources/android-36.1/…`）里 `mListView` 只在 **`mMessage == null`** 的分支被挂进 `contentPanel`：
```java
if (mMessage != null) { mMessageView.setText(mMessage); … }
else { … if (mListView != null) { scrollParent.addView(mListView, …) } else { contentPanel.setVisibility(GONE); } }
```
所以 **`setMessage` + `setItems` 同时用时，item 列表被静默丢弃**——与真机现象逐条吻合（标题在、message 在、按钮在、list 不在）。

**影响（比一个弹窗大）**：`RoomCatalogSeeder` 是生产启动的唯一播种路径（`channel` 表为空才播种内置夹具），而 `ChannelCatalogLoader`（会恢复「上次导入」的那条路）**没有 Hilt 注解、只给测试用**。也就是说：**导入 UI 一坏，产品在电视上就再没有任何途径把真频道弄进来**——内置夹具是 `p12.demo.invalid` 合成表，出不了画面。QA 实测确认：即便按 `imports/last-import.json` 的格式手工写好「记住的导入」+ 拷贝，重启后列表仍是夹具。

**建议修法**（属 dev/arch，本轮不改功能代码）：把提示文案从 `setMessage` 挪到 `setTitle`（或作为列表首行/中性按钮旁的一行说明），只保留 `setItems`；或改用 `setAdapter`/`setSingleChoiceItems`。修完请把「导入成功 + 重启后仍是导入表」补成真机用例。
