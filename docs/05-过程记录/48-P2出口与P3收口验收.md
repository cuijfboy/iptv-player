## 2. 【S1 · 阻断 · 新】NEW-20260922-003：刷新一起就跑崩（前台服务通知渠道缺失）

**现象**：向导第 2 步（更新）自动起更新、或任何手动刷新后约 1 s，**App 进程崩溃并闪回桌面**。

**系统侧证据**（`evidence/P2Gv3/crash-notification-channel.txt`，设备本地时间 13:45:23）：

```
E NotificationService: No Channel found for pkg=ilab.iptv.player, channelId=refresh, id=12023 …
E AndroidRuntime: FATAL EXCEPTION: main
E AndroidRuntime: android.app.RemoteServiceException: Bad notification for startForeground
W ActivityTaskManager:   Force finishing activity ilab.iptv.player/.feature.wizard.WizardActivity
I ActivityManager: Process ilab.iptv.player (pid …) has died: fg  TOP
```

**根因（读码可复算）**：刷新的前台通知用 `RefreshNotifications.CHANNEL_ID = "refresh"`（`RefreshWorker.postForeground` → `setForeground(RefreshNotifications.foregroundInfo(...))`），而 `RefreshNotifications.ensureChannel()` **全仓没有任何调用点**（`rg -n "ensureChannel"` 只命中 `RefreshNotifications` 的定义与播放侧的 `PlaybackService.onCreate`）。渠道不存在时 `startForeground` 必然抛 `RemoteServiceException`，异常在**主线程**抛出，`RefreshWorker` 里那层 `try/catch`（注释写着「失败不致命」）拦不到 → 进程直接死。

**影响**：

1. **首启向导正常路径走不完**：第 1 步主按钮「使用内置源并继续」= 进第 2 步 + 自动起更新 ⇒ 按下即崩（本轮 3 次复现：13:24、13:34、13:45）；
2. **定时刷新线整条失效**：06:00 的每日刷新走同一条路径，同样崩；
3. **崩溃循环**：崩后 WorkManager 以 30 min 线性退避重排（`dumpsys jobscheduler`：`Minimum latency: +29m2s981ms`、`Backoff: policy=0 initial=+30m0s0ms`），到期再崩一次；
4. **刷新管线真机从未跑完**：全天日志 `SRC_REFRESH_DONE` = **0**、`SERVICE_REFRESH_STOP` 仅 1 次。

**复现**（最短路径）：`adb shell pm clear ilab.iptv.player` → `am start -n ilab.iptv.player/.MainActivity` → `input keyevent 23`（第 1 步主按钮）。

> 26 号文档 §6.3 曾把「跑动中通知渠道 `refresh`（IMPORTANCE_LOW、无声无振动）」列为待验项，真机从未验过；本轮首次命中。

## 6. A3 刷新断点续跑 —— ❌ **未执行（被 NEW-3 阻断）**

## 10. 观察项（非缺陷级，未定性）

1. **批量隐藏后浏览页页头计数与列表不一致**：`全选 658 → 隐藏选中` 后页头显示 `频道 275 / 分组 2 / 流 276` 而列表区空白；同一时刻向导侧读到的可见频道数 = **0**（§3.5）。两个「频道数」不一致，建议 dev 核对批量隐藏后的页面计数来源。
2. **换台/起播类判据在本构建不可判**：内置示例表的流地址是假域名 `p12.demo.invalid`，任何起播/换台/故障转移成功率都拿不到有效数据；要判这类项必须先用正式入口导入一份真清单。
3. **第 2 步焦点**：更新进行中该面板没有可聚焦的主按钮，焦点落在 `ScrollView`（`uiautomator` 里 `focused=true` 是容器），需按一次 DOWN 才落到「中断更新」。
4. **批量动作弹窗的空选择态**：`已选 0 台` 时 MENU 打开的弹窗，DPAD OK 与坐标点击都没有触发「全选」（先标记一行再开弹窗则正常）；本轮靠「先标记一行」绕过。
5. **诊断面板的 `uiautomator` 不可用**：面板实时日志在跑，`uiautomator dump` 报 `ERROR: could not get idle state` 并**回落到上一屏的陈旧树**（本轮所有面板读数改用截图 + 导出包）。
