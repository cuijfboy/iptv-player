## 2. 【S1 · 阻断】NEW-1 首启向导第 1 步按钮出屏

**现象**：`pm clear` 后冷启动 → `MainActivity` 正确路由到 `WizardActivity`（`mCurrentFocus=…WizardActivity`）→ 第 1 步「选择源」渲染出标题、提示、17 个内置源清单，**但 4 个按钮（使用内置源并继续 / 导入本地清单 / 添加订阅 / 跳过选源）不在任何位置**：

- 截图（1920×1080）里清单结束于 y≈1011，其下无按钮；`uiautomator dump` 只有 9 个节点，**无任何 Button**；
- `input keyevent 20`（DOWN）×6、`keyevent 23`（OK）**屏幕逐像素不变**（`cmp` 两张 PNG 完全相同），无焦点节点（全部 `focused="false"`）；
- 唯一可达键是 `BACK`：按一次直接退到桌面（Flauncher），符合提示「按返回键退出向导（下次启动还会出现）」。

**根因（读布局 + 实测尺寸）**：`feature/wizard/res/layout/activity_wizard.xml` 的根 `LinearLayout` 是 `match_parent` + 纵向，三步面板都 `wrap_content` 且**没有 ScrollView**。第 1 步面板里 17 行内置源 `TextView`（≈715 px）把容器撑满父高度剩余空间（实测容器 bounds `[96,231][1824,1016]`），其后 4 个按钮被**裁掉**。屏幕只有 540 dp 高，面板需要 ≈734 dp。

**影响**：这是**唯一的首启入口**。全新安装的用户按任何键都进不了频道表，只能退回桌面；由于 `wizard-completed` 只在走完/升级时才写，**每次启动都会重新进向导** → 新装用户被锁死在向导页。

**复现**：`adb shell pm clear ilab.iptv.player` → `adb shell am start -n ilab.iptv.player/.MainActivity` → 观察第 1 步（`evidence/P2Gv2/A6-route1-wizard.png`、`A6-wizard-after-OK.png`）。

**建议**：给三步面板套一个 `ScrollView`（或把内置源清单收成一行摘要 + 「查看全部」二级页），并保证 `wizard_source_continue` 在首屏可达；1280×720 只会更严重。

## 3. B. P3 收口逐项

### 3.1 B7 · BUG-016（EPG 触发时机 + 新鲜度闸门）—— 主修复成立，时效不达标

**时间线（设备本地时间，同一安装会话）**：

| 时刻 | 事件 | 关键字段 |
|---|---|---|
| 12:17:47 | `WORK_SCHEDULE{job:epg, trigger:FIRST_RUN}` | `decision=DEFER, reason=catalog_empty, channels=0, matched=0, programmed=0` |
| 12:17:47 | `WORK_RUN{job:epg}` | `decision=DEFER, reason=catalog_empty, deferrals=0`（**未发起任何网络请求**） |
| 12:17:49 | `DB_UPSERT` + `SRC_PARSE_OK{provider:p1-2-fixture}` | 种子写入 `channels=658, streams=670` |
| 12:51:08 | `WORK_RUN{job:epg, attempt:1}` | 30 min 线性 backoff 到期后才真正开跑 |
| 12:51:12 | `EPG_FETCH_OK` ×4 | 4 源全部 200 |
| 12:51:12 | `EPG_COVERAGE` | `matched=141, withProgrammes=134, emptyBinding=7, total=571` |
| 12:51:12 | `WORK_RUN{result:success}` | `coverageMatched=141, coverageWithProgrammes=134` |
| 12:53:xx（冷启动） | `WORK_SCHEDULE{trigger:FIRST_RUN}` | `decision=SKIP, reason=fresh, lastFetchAtMs=…468240, ageMs=253913, minIntervalMs=21600000, matched=141, programmed=134` |

- **「不再白跑」成立（v1 的核心症状消失）**：v1 是 `decision=RUN` → `EPG_COVERAGE{matched=0,total=0}` 白拉 26.3 s；本轮目录为空时是 `DEFER(catalog_empty)` 且 **0 次网络请求**，播种完成后 `attempt=1` 才拉。
- **「播种完成后自动跑出节目单」成立，但慢 30 min**：`lastFetchAt=null` → 冷启动不会再白跑，可拉取只发生在 WorkManager 的**线性 30 min backoff 到期时**。`dumpsys jobscheduler` 证实 EPG 作业 `Minimum latency: +25m29s…`（backoff policy=0 initial=+30m0s）。修复文档 46 §2.2(c) 承诺「若期间又冷启动…通常几秒」，**实测不成立**：其间发生过 4 次冷启动（每次都只写 `WORK_SCHEDULE`），作业仍等到 12:51 才跑。
- **6 h 新鲜窗 ✅**：guide 非空后，任何非手动触发都 `SKIP(reason=fresh, minIntervalMs=21600000)`。
- **30 min 空 guide 退避未复现**：需要「一次拉取结束后 guide 仍为空」的时刻，本轮该电视上 4 个 EPG 源均可用、匹配到 141 个频道，没有出现该状态；该分支只有单测覆盖。

**判定**：BUG-016 **关闭**（两条根因——触发早于目录、fresh 只看时间——都在真机成立）；时效差距另立 **NEW-2（S3）**。
