## 7. C · 观察项取证

### 7.1 观察 ①：批量隐藏进行中「页头计数 vs 列表」不一致 —— **复现**

`全选 658 → 隐藏选中` 后**同刻**截屏：页头 **`频道 281 / 分组 2 / 流 282`**，而列表区仍在渲染 295 台的「地方/其他」分组行（行可见、勾选框在）。待批量写结束（隔 3–8 s）页头收敛为 `频道 0 / 分组 0 / 流 0`，与空列表**一致**。

⇒ 与 54 号 §5.1 的推断吻合：`ChannelListViewModel.batchSetHidden()` 逐台 658 次独立写、逐次触发 Room 失效重查，页头/帧统计在**中间态**被渲染。**非缺陷级**（最终态自洽），但建议给批量隐藏加仓储级批写（一次事务、一次重发），并把页头计数与列表锁在同一帧状态。

### 7.2 观察 ②：`已选 0 台` 时批量弹窗的「全选」—— **两项读数（本轮未复现“无效”）**

- 读数 A（弹窗标题）：**`先标记至少一个频道（OK 标记）`**；
- 读数 B（列表项数）：**3**（`全选` / `清空选择` / `取消`）。

随后点「全选」→ 重新开 MENU 标题变为 **`频道管理器 · 已选 658 台`**（全选**生效**）。⇒ v3 记录的「点了没反应」本轮**未复现**；真正的问题只剩**文案误导**（标题让人以为必须先标记，而 `全选` 一直可用）。建议：把标题在 `selected == 0` 时改为「未选中（可『全选』或按 OK 逐台标记）」。**非缺陷级**。
