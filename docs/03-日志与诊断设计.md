## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **日志是接口，不是补丁** | `:core:common` 定义 `Logger` 门面，`:core:log` 提供实现；业务模块只依赖门面 |
| **事件码优先** | 每条关键日志带稳定 `code`（如 `PLAY_PREPARE_TIMEOUT`），可统计、可检索、可写进排查手册 |
| **结构化** | 携带 `fields: Map<String, Any?>`，而不是拼字符串；便于过滤/聚合/导出成 JSONL |
| **多出口** | logcat（开发）+ 内存环（App 内实时看）+ 文件（事后回溯）+ 崩溃（致命）+ 指标（性能） |
| **不拖慢主路径** | 日志写入异步化（单线程 + 有界队列），队列满时丢弃低级别而非阻塞 |
| **脱敏默认开启** | token/密码类查询参数、设备标识一律打码，导出包可直接分享 |
| **可动态调级** | 设置页可切换日志级别与文件开关，无需重新打包 |

## 2. 分层与依赖

```
业务模块（source / epg / player / data / feature …）
        │ 只依赖接口
        ▼
:core:common   Logger · LogEvent · LogLevel · LogCategory · EventCodes
        ▲
        │ 实现（Hilt 绑定）
:core:log      LogBus(多路分发) ──▶ LogcatSink
                                 ├─▶ MemoryRingSink   (App 内实时查看)
                                 ├─▶ FileSink         (轮转落盘)
                                 ├─▶ CrashSink        (未捕获异常/ANR)
                                 └─▶ MetricBridge     (关键事件 → metric 表)
```

**为什么这样分**：避免"日志实现依赖数据库/UI，而它们又依赖日志"的循环依赖；`:core:log` 只依赖 `:core:common`。

**注入方式**：Hilt `@IntoSet` 收集所有 `LogSink`，`LogBus` 构造注入 → 新增出口零改动（扩展点 E8）。

## 3. 级别 · 分类 · 事件码

### 3.1 级别

| 级别 | 用途 | 默认落盘 |
|---|---|---|
| VERBOSE | 逐条流/逐片段的细节 | ❌（仅 logcat，debug 构建） |
| DEBUG | 流程节点（阶段开始/结束、数量统计） | ❌（debug 构建落盘） |
| INFO | 用户可感知的状态变化（刷新完成、切换频道） | ✅ |
| WARN | 可自愈的异常（单源失败、EPG 缺失、一次重试成功） | ✅ |
| ERROR | 功能受损（播放失败、刷新整体失败、DB 写入失败） | ✅ |
| FATAL | 崩溃 | ✅ + 崩溃文件 |

> **级别过滤只有一处（卡 `DOC-4` 裁决，2026-09-22）**：各 `Sink` **不做**级别过滤，唯一旋钮是 `LogBus.minLevel`（默认 `INFO`，见 §14）。上表「默认落盘」列描述的是 `LogBus` 放行**之后**的结果，不是 `FileSink` 自己的过滤；`LogcatSink` / `MemoryRingSink` 收到的也是同一批事件。

### 3.2 分类

`APP` · `UI` · `NET` · `SOURCE` · `VALIDATE` · `EPG` · `DB` · `PLAYER` · `SERVICE` · `WORK` · `PERF`

### 3.3 事件码规范

格式：`<域>_<对象>_<结果>`；全大写下划线；**稳定不随文案变化**（文案可改，码不可改）。

| 事件码 | 级别 | 触发点 | 关键字段 |
|---|---|---|---|

| `PLAY_STALL` | WARN | 卡顿 | stalledMs、positionMs |
| `PLAY_SWITCH_CHANNEL` | INFO | 换台 | from→to、costMs |
| `PLAY_END` | INFO | 播放结束 | 时长、failoverCount、原因 |
| `PLAY_ENGINE_INIT` / `_RELEASE` | DEBUG | 引擎生命周期 | engine、capabilities |

| `PERF_EPG_GRID` | DEBUG | EPG 网格 | fps、drawnBlocks、scrollMs |

> **`EPG_MATCH_MISS` 与 `EPG_MATCH_HIT` 的相对顺序（卡 `DOC-11`，`d56dc88`）**：一次 EPG 导入的顺序如实是 **MISS 全部先于 HIT**——`MISS` 在**逐源匹配阶段**当场打（某台在某源没匹配上就打一条，带 `provider`），`HIT` 则**全部留到择优定夺之后**才统一打（这样才能在一行里同时给出 `programmesInWindow` 与 `chosen`）。因此同一频道可能既出现在某源的 `MISS` 里、又出现在另一源的 `HIT` 里（多源场景正常）。字段与事件码数量不变（仍 50）。

> **事件码常数集中在 `EventCodes.kt`**，禁止在业务代码里写字面量字符串。

> **`SRC_FETCH_*` 与 `SRC_PARSE_*` 的分工（2026-09-22 口径）**：`SRC_FETCH_FAIL` 只表示清单**取回**失败（网络/HTTP/超限）；取回成功但**解析**失败记 `SRC_PARSE_FAIL`。解析失败此前用 `SRC_FETCH_FAIL` 兜底的做法**已取消**（原因：兜底码会把"源不通"和"源格式变了"混成同一类，排查手册无法分流）。

> **本表条数**：含 `/` 配对展开共 **50 个**事件码（2026-09-22 登记 `SRC_PARSE_FAIL` 后由 45 → 46；同日卡 `DOC-9` 补 P1-7 的 4 个码后由 46 → 50）。`EventCodes.kt` 的 `ALL` 集合与 `EventCodesTest` 的条数断言**已同步 50**（dev-a-19，`eb353da`；双向核对见 [`05-过程记录/28-关键路径事件码.md`](./05-过程记录/28-关键路径事件码.md) §8）。

## 4. 结构化事件模型

```kotlin
data class LogEvent(
    val seq: Long,                       // 单调序号，用于排序/去重
    val ts: Long,                        // 墙钟毫秒
    val elapsedMs: Long,                 // 进程启动以来毫秒（定位卡顿）
    val level: LogLevel,
    val category: LogCategory,
    val code: String,                    // 事件码
    val message: String,                 // 人类可读（已脱敏）
    val fields: Map<String, Any?> = emptyMap(),
    val error: Throwable? = null,
    val thread: String,                  // 线程名
    val screen: String? = null,          // 当前页面（UI 场景）
    val sessionId: String,               // 一次刷新/一次播放的关联 ID
)
```

**关联 ID（sessionId）** 是排查的关键：一次刷新从 `SRC_REFRESH_START` 到 `SRC_REFRESH_DONE`、一次播放从 `PLAY_PREPARE_START` 到 `PLAY_END` 共享同一 `sessionId`，诊断页可按会话折叠查看。

**日志导出为 JSONL**（每行一个 JSON 对象），便于用 `jq` 分析：

```jsonl
{"seq":1024,"ts":1758400000000,"level":"INFO","category":"PLAYER","code":"PLAY_FIRST_FRAME","message":"first frame","fields":{"channelId":12,"streamId":88,"costMs":2450,"vcodec":"video/avc","acodec":"audio/mp4a-latm"},"sessionId":"play-7f3a","elapsedMs":84213,"thread":"main","screen":"player"}
{"seq":1025,"ts":1758400000120,"level":"WARN","category":"SOURCE","code":"SRC_FETCH_FAIL","message":"fetch failed","fields":{"provider":"demo","ms":1500},"sessionId":"refresh-91c2","elapsedMs":84333,"thread":"log-dispatch-0","error":{"type":"java.io.IOException","message":"timeout","stack":"…"}}
```

> **行格式是超集（卡 `DOC-4` 裁决，2026-09-22）**：落盘行的**必填键与顺序**为 `seq, ts, level, category, code, message, fields, sessionId, elapsedMs, thread`；`screen`（仅 UI 场景）与 `error`（仅事件带 throwable 时，内含 `type`/`message`/`stack`）为**可选键，不存在时整键省略**。即上例在原 8 键示例之后**追加** `elapsedMs/thread`（`elapsedMs` 是卡顿定位字段、`thread` 是线程归因），`error` 保留堆栈（§11）。实现见 `core/log/…/file/LogJsonLine.kt`，追加键不破坏 `jq` 等 JSONL 读取。

| Sink | 内容 | 容量/策略 | 依赖 | 状态（2026-09-22） |
|---|---|---|---|---|
| `LogcatSink` | `Log.i(TAG, ...)`，TAG=`IPTV/<category>` | 级别由 `LogBus` 统一过滤（默认 `INFO+`，见 §3.1） | 无 | ✅ 已实现（L1） |
| `MemoryRingSink` | 最近 **2000** 条（可配），供 App 内诊断页 | 固定数组 + 覆盖写，O(1) | 无 | ✅ 已实现（L1） |
| `FileSink` | `files/logs/iptv-yyyyMMdd.log`（JSONL） | 单文件 ≤ 2 MB，**份数 ≤ 12（只约束更早日期）**，保留 7 天 / ≤ 50 MB，删除优先级见 §6 | 无 | ✅ 已实现（L3，P1-8） |
| `CrashSink` | `files/logs/crash-<ts>.txt` | 保留最近 5 份 | 无 | ⏳ 目标终态（L4） |
| `MetricBridge` | 关键事件 → `metric` 表（起播耗时、故障转移次数…） | 由 code 白名单触发 | Room（延迟初始化，避免循环依赖） | ⏳ 目标终态（L7） |

> **实现状态是「当前」不是「终态」**：`LogcatSink` / `MemoryRingSink`（L1）/ `FileSink`（L3，P1-8）三个已落地并经真机自证；`CrashSink`（L4）、`MetricBridge`（L7）仍是目标形态，交付阶段见 §13。级别过滤**不在任何 Sink 内**（§3.1 note）。

**写入管线**：`LogBus.write()` → 有界队列（容量 1024，`offer` 失败即丢弃 VERBOSE/DEBUG）→ 单后台线程分发到各 Sink；**永不阻塞调用线程**。`flush()` 在崩溃/退出时同步等待（带 500 ms 上限）。

## 6. 落盘与轮转

| 项 | 值 |
|---|---|
| 路径 | `/sdcard/Android/data/ilab.iptv.player/files/logs/`（无需存储权限，adb 可 pull） |
| 格式 | JSONL（UTF-8），行内已脱敏 |
| 轮转 | **按天 + 按大小两种触发**：跨天新建当天文件 `iptv-yyyyMMdd.log`；当前文件超过 2 MB 即整段改名为段文件 `iptv-yyyyMMdd.<n>.log`（段号取当天最大值 +1，不覆盖），最新事件始终落在基础文件 |
| 轮转判断 | 以**磁盘上的真实文件大小**为准——每次写前 `stat` 一次，不是只看进程内计数；脚本或上一次会话写大的文件同样会被轮转 |
| 保留 | 7 天 / 总量 50 MB / **份数上限 12**；**删除优先级 = 过期 → 更早日期 → 当天段文件（最后）** |
| 清理 | 启动后首次写入 + 每次轮转后；设置页可「立即清理」（`cleanupNow()`） |
| 写失败降级 | 写失败**不崩、不空转**：计数 + 记原因 + **60 s 内退避不再重试**，窗口过后自动重试并自愈；文件出口降级不影响其他 Sink，也不阻塞调用线程 |
| 开关与级别 | 文件开关默认**开**（§14）；级别**不在 `FileSink` 过滤**——唯一旋钮是 `LogBus.minLevel`（默认 `INFO`，§3.1），落盘量随之变化 |

> **保留与删除优先级（卡 `DOC-5`，对齐 BUG-011 修复，2026-09-22）**：`LogFilePolicy.cleanupPlan()`（`363ca58`）三趟按序执行，**删除优先级 = ① 过期 → ② 更早日期 → ③ 当天段文件（最后）**：
> - **① 过期**：文件名日期比今天早**超过 7 天**的先删。过期只看文件名里的 `yyyyMMdd`，`lastModified` 只当同日排序的 tie-breaker（拷来的文件不能因此续命）。
> - **② 超份数**：份数上限 **12** 只从**更早日期**里删，当天文件不参与。
> - **③ 超总量**：只有总量超过 **50 MB** 才删；最旧日期先删，**当天段文件永远排最后**。
>
> **保护**：正在追加的**活跃 base 文件**与**当天 base 文件名**（`iptv-yyyyMMdd.log`）**永不进删除候选**——即使 sink 尚未 open、设备页点了「立即清理」也一样（当天 base 是下一次 append 的落点，看着不活跃）。**当天段文件不受份数上限约束**，只受 50 MB 总量约束（单文件 2 MB 是轮转阈值，不是删除条件）。份数与总量都按**本 sink 拥有的全部文件（含活跃文件）**计；`crash-*.txt` 等外来文件不参与。
>
> **份数上限 12 与写失败退避的由来（卡 `DOC-4`，2026-09-22）**：12 由 god 批准为默认（`LogFilePolicy.DEFAULT_MAX_FILE_COUNT`）——**自 BUG-011 修复起它只约束「更早日期」**，当天段文件改由 50 MB 总量约束（见上条），所以一个话痨日不会被自己的份数上限削掉正要 pull 的证据；写失败「计数 + 记原因 + 60 s 退避自愈」是 P1-8 **已实现的契约**（`FileSink.DEFAULT_DEGRADED_RETRY_MS = 60_000`），自 DOC-4 起写进设计，不再当默认值藏着。清理钩子的「每次刷新结束」一项属 P2-4（刷新管线尚未存在），当前由启动 / 轮转触发 + 设置页手动触发。

## 9. 崩溃与 ANR 捕获

| 项 | 做法 |
|---|---|
| Java 崩溃 | `Thread.setDefaultUncaughtExceptionHandler` → 写 `crash-<ts>.txt`（线程名、堆栈、内存、**最近 200 条内存环日志快照**、当前页面）→ 转发给默认处理器 |
| 协程异常 | `CoroutineExceptionHandler` 全局兜底 → `CRASH`/`ERROR` 事件 |
| ANR | 主线程 `Looper` 看门狗：每 5 s 打点，超 5 s 未响应则记录主线程堆栈（轻量、可关闭） |

| 不引入第三方 | 上述逻辑 ≈150 行自研，避免为崩溃上报引入依赖（也可后续接 ACRA，Apache-2.0） |

## 11. 脱敏规范（强制）

| 对象 | 规则 |
|---|---|
| URL 查询参数 | `token` `key` `pwd` `pass` `sign` `auth` `secret` `expire` → 值替换 `***` |

## 12. 排查手册（症状 → 事件码 → 处置）

| 症状 | 先看什么 | 常见根因 | 处置 |
|---|---|---|---|
| 频道列表为空 | `SRC_FETCH_*` `SRC_PARSE_FAIL` `SRC_REFRESH_DONE` `DB_UPSERT` | 全部源拉取失败 / 被墙 / 解析格式变化 | 检查 `NET_REQ_FAIL.host`（取回失败）或 `SRC_PARSE_FAIL.err`（取回成功但格式变了）；加源或改订阅 URL |
| 有台无节目单 | `EPG_MATCH_MISS` `EPG_COVERAGE` | tvg-id 不匹配 / EPG 源缺失该台 | 手动绑定；补别名表；换 EPG 源 |
| 黑屏/一直转圈 | `PLAY_PREPARE_FAIL`（errCategory） | 403 防盗链 / 源失效 / 编码不支持 | 看 `httpStatus`；补 UA/Referer；切备胎 |
| 播放几秒后断 | `PLAY_STALL` `PLAY_FAILOVER` | token 过期 / 并发限制 / 丢包 | 自动切源已生效；考虑动态刷新清单 |
| 只有画面没声音 | `PLAY_FIRST_FRAME.acodec` | AC3/EAC3 未透传 | 换 AAC 源（lite）；启用软解/兜底引擎 |
| 换台很慢 | `PLAY_FIRST_FRAME.costMs` 分布 | 缓冲策略过保守 / 源本身慢 | 调 `LoadControl`；降权慢源 |
| 界面卡顿 | `UI_FRAME_JANK` `PERF_EPG_GRID` | 列表未虚拟化 / 网格绘制过重 | 检查绘制块数；开启硬件层；减少文本布局 |
| 刷新跑不完 | `SRC_REFRESH_DONE.interrupted` | 时间预算触发/被系统杀死 | 看 `SERVICE_REFRESH_STOP`；调小并发或缩短预算 |
| 数据丢失 | `DB_FAIL` `APP_START` | 迁移失败 / 存储满 | 看 schema 版本与可用空间；导出诊断包 |
| 应用被杀 | `APP_STOP` 缺失 + 无崩溃文件 | 系统内存回收 / 环境屏冻结 | 确认前台服务已启动；减少后台并发 |
