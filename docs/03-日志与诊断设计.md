# 03 · 日志与诊断设计

> 目标：**问题可定位、状态可观测、故障可回溯**——不接 adb 也能在电视上自查，接 adb 能一键拿出完整证据包。
> 相关：[01 需求与可行性](./01-需求与可行性.md) · [02 技术架构设计](./02-技术架构设计.md) · [04 开发计划与验收](./04-开发计划与验收.md)

---

## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **日志是接口，不是补丁** | `:core:common` 定义 `Logger` 门面，`:core:log` 提供实现；业务模块只依赖门面 |
| **事件码优先** | 每条关键日志带稳定 `code`（如 `PLAY_PREPARE_TIMEOUT`），可统计、可检索、可写进排查手册 |
| **结构化** | 携带 `fields: Map<String, Any?>`，而不是拼字符串；便于过滤/聚合/导出成 JSONL |
| **多出口** | logcat（开发）+ 内存环（App 内实时看）+ 文件（事后回溯）+ 崩溃（致命）+ 指标（性能） |
| **不拖慢主路径** | 日志写入异步化（单线程 + 有界队列），队列满时丢弃低级别而非阻塞 |
| **脱敏默认开启** | token/密码类查询参数、设备标识一律打码，导出包可直接分享 |
| **可动态调级** | 设置页可切换日志级别与文件开关，无需重新打包 |

## 2. 分层与依赖

```
业务模块（source / epg / player / data / feature …）
        │ 只依赖接口
        ▼
:core:common   Logger · LogEvent · LogLevel · LogCategory · EventCodes
        ▲
        │ 实现（Hilt 绑定）
:core:log      LogBus(多路分发) ──▶ LogcatSink
                                 ├─▶ MemoryRingSink   (App 内实时查看)
                                 ├─▶ FileSink         (轮转落盘)
                                 ├─▶ CrashSink        (未捕获异常/ANR)
                                 └─▶ MetricBridge     (关键事件 → metric 表)
```

**为什么这样分**：避免"日志实现依赖数据库/UI，而它们又依赖日志"的循环依赖；`:core:log` 只依赖 `:core:common`。

**注入方式**：Hilt `@IntoSet` 收集所有 `LogSink`，`LogBus` 构造注入 → 新增出口零改动（扩展点 E8）。

## 3. 级别 · 分类 · 事件码

### 3.1 级别

| 级别 | 用途 | 默认落盘 |
|---|---|---|
| VERBOSE | 逐条流/逐片段的细节 | ❌（仅 logcat，debug 构建） |
| DEBUG | 流程节点（阶段开始/结束、数量统计） | ❌（debug 构建落盘） |
| INFO | 用户可感知的状态变化（刷新完成、切换频道） | ✅ |
| WARN | 可自愈的异常（单源失败、EPG 缺失、一次重试成功） | ✅ |
| ERROR | 功能受损（播放失败、刷新整体失败、DB 写入失败） | ✅ |
| FATAL | 崩溃 | ✅ + 崩溃文件 |

### 3.2 分类

`APP` · `UI` · `NET` · `SOURCE` · `VALIDATE` · `EPG` · `DB` · `PLAYER` · `SERVICE` · `WORK` · `PERF`

### 3.3 事件码规范

格式：`<域>_<对象>_<结果>`；全大写下划线；**稳定不随文案变化**（文案可改，码不可改）。

| 事件码 | 级别 | 触发点 | 关键字段 |
|---|---|---|---|
| `APP_START` / `APP_STOP` | INFO | 进程生命周期 | 版本、ABI、SDK、内存 |
| `UI_SCREEN_OPEN` | DEBUG | 页面进入 | screen、from |
| `UI_FRAME_JANK` | WARN | 帧耗时超阈值 | screen、frames、p95ms |
| `NET_REQ_OK` / `NET_REQ_FAIL` | DEBUG/WARN | 统一 HTTP 出口 | host、status、ms、bytes、retry |
| `NET_CHARSET_FALLBACK` | DEBUG | UTF-8→GB18030 回退 | host |
| `SRC_FETCH_OK` / `SRC_FETCH_FAIL` | INFO/WARN | 每个聚合源 | provider、entries、ms、err |
| `SRC_PARSE_OK` | DEBUG | 解析完成 | provider、m3u/txt、entries、skipped |
| `SRC_DEDUPE` | INFO | 去重完成 | raw、unique、perSource |
| `SRC_REFRESH_START` / `SRC_REFRESH_DONE` | INFO | 刷新整体 | 候选数、通过数、耗时、中断原因 |
| `SRC_REFRESH_SKIP` | DEBUG | 增量跳过 | checkedRecently、failedRecently |
| `VAL_SHALLOW_OK` / `_FAIL` | DEBUG | 轻量校验 | detail、segStatus、variant、ms |
| `VAL_DEEP_OK` / `_FAIL` | DEBUG | 深度校验 | vcodec、acodec、w/h、err、ms |
| `SRC_SCORE` | DEBUG | 评分 | url 摘要、总分、各维度分 |
| `SRC_SELECT` | INFO | 甄选 | channels、primary、backup、dropped |
| `EPG_FETCH_OK` / `_FAIL` | INFO/WARN | EPG 源 | provider、bytes、programmes |
| `EPG_PARSE_OK` | DEBUG | 解析完成 | channels、programmes、skipped、ms |
| `EPG_MATCH_HIT` / `EPG_MATCH_MISS` | DEBUG/INFO | 匹配结果 | channelId、strategy、epgId |
| `EPG_COVERAGE` | INFO | 覆盖率统计 | matched、total、byGroup |
| `DB_UPSERT` / `DB_FAIL` | DEBUG/ERROR | 写库 | table、rows、ms、err |
| `PLAY_PREPARE_START` | INFO | 起播开始 | channelId、streamId、engine、attempt |
| `PLAY_FIRST_FRAME` | INFO | 首帧到达 | **costMs**、vcodec、acodec、w/h |
| `PLAY_PREPARE_FAIL` | WARN | 起播失败 | errCategory、httpStatus、attempt |
| `PLAY_FAILOVER` | WARN | 故障转移 | from→to、reason、attempt |
| `PLAY_STALL` | WARN | 卡顿 | stalledMs、positionMs |
| `PLAY_SWITCH_CHANNEL` | INFO | 换台 | from→to、costMs |
| `PLAY_END` | INFO | 播放结束 | 时长、failoverCount、原因 |
| `PLAY_ENGINE_INIT` / `_RELEASE` | DEBUG | 引擎生命周期 | engine、capabilities |
| `SERVICE_REFRESH_START` / `_STOP` | INFO | 前台服务 | type、budgetMs |
| `WORK_SCHEDULE` / `WORK_RUN` | DEBUG/INFO | WorkManager | name、constraints、result |
| `PERF_STARTUP` | INFO | 冷启动 | totalMs、dbMs、epgMs |
| `PERF_EPG_GRID` | DEBUG | EPG 网格 | fps、drawnBlocks、scrollMs |
| `CRASH` / `ANR` | FATAL | 崩溃捕获 | 线程、堆栈、最近日志快照 |

> **事件码常数集中在 `EventCodes.kt`**，禁止在业务代码里写字面量字符串。

## 4. 结构化事件模型

```kotlin
data class LogEvent(
    val seq: Long,                       // 单调序号，用于排序/去重
    val ts: Long,                        // 墙钟毫秒
    val elapsedMs: Long,                 // 进程启动以来毫秒（定位卡顿）
    val level: LogLevel,
    val category: LogCategory,
    val code: String,                    // 事件码
    val message: String,                 // 人类可读（已脱敏）
    val fields: Map<String, Any?> = emptyMap(),
    val error: Throwable? = null,
    val thread: String,                  // 线程名
    val screen: String? = null,          // 当前页面（UI 场景）
    val sessionId: String,               // 一次刷新/一次播放的关联 ID
)
```

**关联 ID（sessionId）** 是排查的关键：一次刷新从 `SRC_REFRESH_START` 到 `SRC_REFRESH_DONE`、一次播放从 `PLAY_PREPARE_START` 到 `PLAY_END` 共享同一 `sessionId`，诊断页可按会话折叠查看。

**日志导出为 JSONL**（每行一个 JSON 对象），便于用 `jq` 分析：

```jsonl
{"seq":1024,"ts":1758400000000,"level":"INFO","category":"PLAYER","code":"PLAY_FIRST_FRAME","message":"first frame","fields":{"channelId":12,"streamId":88,"costMs":2450,"vcodec":"video/avc","acodec":"audio/mp4a-latm"},"sessionId":"play-7f3a"}
```

## 5. Sink 体系

| Sink | 内容 | 容量/策略 | 依赖 |
|---|---|---|---|
| `LogcatSink` | `Log.i(TAG, ...)`，TAG=`IPTV/<category>` | debug 全量；release `INFO+` | 无 |
| `MemoryRingSink` | 最近 **2000** 条（可配），供 App 内诊断页 | 固定数组 + 覆盖写，O(1) | 无 |
| `FileSink` | `files/logs/iptv-yyyyMMdd.log`（JSONL） | 单文件 ≤ 2 MB，保留 7 天 / ≤ 50 MB | 无 |
| `CrashSink` | `files/logs/crash-<ts>.txt` | 保留最近 5 份 | 无 |
| `MetricBridge` | 关键事件 → `metric` 表（起播耗时、故障转移次数…） | 由 code 白名单触发 | Room（延迟初始化，避免循环依赖） |

**写入管线**：`LogBus.write()` → 有界队列（容量 1024，`offer` 失败即丢弃 VERBOSE/DEBUG）→ 单后台线程分发到各 Sink；**永不阻塞调用线程**。`flush()` 在崩溃/退出时同步等待（带 500 ms 上限）。

## 6. 落盘与轮转

| 项 | 值 |
|---|---|
| 路径 | `/sdcard/Android/data/ilab.iptv.player/files/logs/`（无需存储权限，adb 可 pull） |
| 格式 | JSONL（UTF-8），行内已脱敏 |
| 轮转 | 按天 + 单文件 2 MB 双阈值 |
| 保留 | 7 天或总量 50 MB，先删最旧 |
| 清理 | 启动时 + 每次刷新结束；设置页可"立即清理" |
| 开关 | 设置 → 诊断 → "写入日志文件"（默认开，WARN+；可切 DEBUG/VERBOSE） |

**adb 取日志（开发期）**

```bash
adb connect 192.168.x.x:5555
adb logcat -s 'IPTV/*:V'                       # 实时分类日志
adb shell run-as ilab.iptv.player ls files/logs  # 调试签名可用
adb pull /sdcard/Android/data/ilab.iptv.player/files/logs ./tv-logs
```

## 7. 诊断面板（设置 → 诊断）

一个页面回答"它现在到底怎么样"：

### 7.1 运行概览

| 区块 | 内容 |
|---|---|
| 设备 | 型号、Android 版本、**ABI**、内存/存储、屏幕刷新率 |
| 应用 | 版本、构建类型、数据库 schema 版本、日志级别 |
| 数据 | 频道总数 / 分组分布 / 隐藏数 / 收藏数；流总数 / 主源数 / 备胎数 |
| **源健康** | 上次刷新时间与耗时；候选→通过→入选漏斗；失败原因 Top10；各源条目数与成功率 |
| **EPG** | 各 EPG 源状态、覆盖率（matched/total）、节目条数、窗口范围 |
| **播放** | 累计播放次数、平均起播耗时（P50/P95）、故障转移次数与原因分布、失败频道 Top10 |
| **性能** | 冷启动耗时、列表/网格 fps（P50/P95）、内存峰值 |

### 7.2 实时日志

- 内存环日志实时滚动（默认 INFO+），支持：级别过滤、分类过滤、**事件码/关键字搜索**、暂停/继续、自动滚屏开关；
- 点击单条 → 展开 `fields` 与堆栈（若有）；
- "按会话查看"：以 `sessionId` 折叠一次刷新/一次播放的全过程。

### 7.3 操作

- 复制全部日志到剪贴板（TV 上可用遥控操作，便于拍屏/粘贴到别处）；
- **一键导出诊断包**（见 §8）；
- 立即清理日志 / 重置统计。

## 8. 一键导出诊断包

```
导出路径：files/export/iptv-diag-<yyyyMMdd-HHmmss>.zip
├── meta.json            # 版本、构建、设备（ABI/SDK/内存/存储）、导出时间、设置快照（脱敏）
├── logs/iptv-*.log      # 最近 7 天 JSONL（已脱敏）
├── logs/crash-*.txt     # 崩溃记录（若有）
├── stats.json           # §7.1 的全部统计（机器可读）
├── timeline.json        # 最近 100 次播放：频道/源/起播耗时/结果/failover 次数
├── db-dump/             # 关键表 CSV（channel / stream / source / epg_source / metric.summary）
└── README.txt           # 说明本包内容与脱敏规则
```

- 导出过程在后台协程执行，UI 显示进度；完成后提示路径；
- **不含**播放 URL 全文（仅保留 host + hash 前缀）、不含 token、不含账号信息；
- **导出器必须经 `Redactor` 二次过滤（W7）**：库内（`play_history` / `stream` 表）保留原文，**导出包一律脱敏**；过滤发生在导出管线入口，不依赖各导出器自觉；
- 取包方式：`adb pull`（开发期）或设置页"分享/复制路径"（用户手动处理）；
- 可选（P4）：局域网 HTTP 上传到用户自填地址 —— **默认关闭，且不作为运行前提**（ADR-001）。

## 9. 崩溃与 ANR 捕获

| 项 | 做法 |
|---|---|
| Java 崩溃 | `Thread.setDefaultUncaughtExceptionHandler` → 写 `crash-<ts>.txt`（线程名、堆栈、内存、**最近 200 条内存环日志快照**、当前页面）→ 转发给默认处理器 |
| 协程异常 | `CoroutineExceptionHandler` 全局兜底 → `CRASH`/`ERROR` 事件 |
| ANR | 主线程 `Looper` 看门狗：每 5 s 打点，超 5 s 未响应则记录主线程堆栈（轻量、可关闭） |
| 下次启动提示 | 检测到未上报崩溃 → 首页/设置页显示"上次运行异常已记录"，一键导出 |
| 不引入第三方 | 上述逻辑 ≈150 行自研，避免为崩溃上报引入依赖（也可后续接 ACRA，Apache-2.0） |

## 10. 性能埋点

| 指标 | 采集方式 | 落库 |
|---|---|---|
| 冷启动耗时 | `Process.getStartUptimeMillis()` → 首帧 | `metric:perf_startup` |
| 起播耗时 | `PLAY_PREPARE_START` → `PLAY_FIRST_FRAME` | `metric:play_start` + `play_history.start_cost_ms` |
| 换台耗时 | `PLAY_SWITCH_CHANNEL.costMs` | `metric:channel_switch` |
| 列表/网格帧率 | `FrameMetricsAggregator`（debug）或 Choreographer 采样 | `metric:ui_fps` |
| 刷新各阶段耗时 | 流水线阶段计时 | `metric:refresh_stage` |
| DB 查询耗时 | DAO 包装计时（DEBUG 级） | `metric:db_query` |
| 内存峰值 | `Debug.MemoryInfo` / `Runtime` 采样 | `metric:mem` |

> 指标写入遵循"抽样 + 上限"：每类保留最近 1000 条，避免 metric 表膨胀（由 P2 的清理任务负责）。

## 11. 脱敏规范（强制）

| 对象 | 规则 |
|---|---|
| URL 查询参数 | `token` `key` `pwd` `pass` `sign` `auth` `secret` `expire` → 值替换 `***` |
| URL 路径 | 仅保留 `scheme://host` + 路径的 hash 前 8 位；完整 URL 只在内存中使用 |
| 设备标识 | 序列号 / Android ID / MAC / 精确内网 IP → `<redacted>` |
| 用户输入 | 订阅 URL 存库但在日志/导出中脱敏 |
| 崩溃堆栈 | 保留（必要），但过滤其中的 URL 参数 |

实现：`Redactor.redact(url)` 单一入口，`LogBus` 在写入前统一处理（**不能依赖调用方自觉**）；**导出管线**（§8）在打包前再调用一次 `Redactor`，形成"库内原文 / 导出脱敏"的明确边界（W7）。

## 12. 排查手册（症状 → 事件码 → 处置）

| 症状 | 先看什么 | 常见根因 | 处置 |
|---|---|---|---|
| 频道列表为空 | `SRC_FETCH_*` `SRC_REFRESH_DONE` `DB_UPSERT` | 全部源拉取失败 / 被墙 / 解析格式变化 | 检查 `NET_REQ_FAIL.host`；加源或改订阅 URL |
| 有台无节目单 | `EPG_MATCH_MISS` `EPG_COVERAGE` | tvg-id 不匹配 / EPG 源缺失该台 | 手动绑定；补别名表；换 EPG 源 |
| 黑屏/一直转圈 | `PLAY_PREPARE_FAIL`（errCategory） | 403 防盗链 / 源失效 / 编码不支持 | 看 `httpStatus`；补 UA/Referer；切备胎 |
| 播放几秒后断 | `PLAY_STALL` `PLAY_FAILOVER` | token 过期 / 并发限制 / 丢包 | 自动切源已生效；考虑动态刷新清单 |
| 只有画面没声音 | `PLAY_FIRST_FRAME.acodec` | AC3/EAC3 未透传 | 换 AAC 源（lite）；启用软解/兜底引擎 |
| 换台很慢 | `PLAY_FIRST_FRAME.costMs` 分布 | 缓冲策略过保守 / 源本身慢 | 调 `LoadControl`；降权慢源 |
| 界面卡顿 | `UI_FRAME_JANK` `PERF_EPG_GRID` | 列表未虚拟化 / 网格绘制过重 | 检查绘制块数；开启硬件层；减少文本布局 |
| 刷新跑不完 | `SRC_REFRESH_DONE.interrupted` | 时间预算触发/被系统杀死 | 看 `SERVICE_REFRESH_STOP`；调小并发或缩短预算 |
| 数据丢失 | `DB_FAIL` `APP_START` | 迁移失败 / 存储满 | 看 schema 版本与可用空间；导出诊断包 |
| 应用被杀 | `APP_STOP` 缺失 + 无崩溃文件 | 系统内存回收 / 环境屏冻结 | 确认前台服务已启动；减少后台并发 |

## 13. 验收标准（P0 起逐步达成）

| # | 标准 | 阶段 |

## 14. 动态调级与开关

| 开关 | 位置 | 默认 | 说明 |
|---|---|---|---|
| 日志级别 | 设置 → 诊断 | `INFO` | 可切 DEBUG/VERBOSE（电视上现场排查用） |
| 文件日志 | 设置 → 诊断 | 开 | 关闭可省 IO |
| 内存环大小 | 设置 → 诊断（高级） | 2000 | 512–10000 |
| ANR 看门狗 | 设置 → 诊断（高级） | 开 | 关可省开销 |
| 性能埋点 | 设置 → 诊断（高级） | 开 | 关可省开销 |
| 日志清理 | 设置 → 诊断 | – | 立即清理 / 重置统计 |

> 所有开关持久化在 DataStore，随诊断包导出（`meta.json`）。
