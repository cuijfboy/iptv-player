## 5. 升级计划

### 方式
统一采用 **ADB 覆盖安装**：`adb install -r <apk>` —— 保留应用数据与登录态（前提：APK 签名与现装版本一致）。
下载包必须选 **armeabi-v7a 或 universal**（本机仅 32 位 ABI）。

### 待升级清单与下载源

| 应用 | 目标版本 | 下载文件 |
|---|---|---|
| VLC | 3.7.1 | https://get.videolan.org/vlc-android/3.7.1/VLC-Android-3.7.1-armeabi-v7a.apk |
| Moonlight | 12.2 | https://github.com/moonlight-stream/moonlight-android/releases/download/v12.2/app-nonRoot-release.apk |
| Jellyfin Android TV | 0.19.10 | https://github.com/jellyfin/jellyfin-androidtv/releases/download/v0.19.10/jellyfin-androidtv-v0.19.10-release.apk |
| Nova Video Player | 6.4.64 | https://github.com/nova-video-player/aos-AVP/releases/download/v6.4.64/org.courville.nova-2669737-6.4.64-20260912.1301-armeabi-v7a-release.apk |

### 执行顺序（风险从低到高）
1. VLC 3.5.4 → 3.7.1
2. Moonlight 12.1 → 12.2
3. Nova 6.4.36 → 6.4.64
4. Jellyfin 0.17.3 → 0.19.10（跨版本最多，放最后）

### 升级前备份（只读，不影响电视）
- 记录每个包的当前 `versionName/versionCode` 与签名摘要
- 用 `adb pull` 导出当前 APK 到本机 `tv-audit/backup/`，便于失败回滚
- 应用数据（Kodi 媒体库、Jellyfin 服务器配置、TiviMate 订阅等）默认保留在 `/data/data`，覆盖安装不会清除；若遇签名冲突需卸载重装则会丢失，届时先单独确认

### 风险与回滚
- **签名不一致** → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，只能卸载重装（丢数据）。这些包是 GitHub 官方发布，正常情况下签名一致。
- **Jellyfin 0.17→0.19** 跨版本，首次启动可能需要重新登录/同步；服务器端配置在 NAS 上，不受影响。
- **Nova 6.4.36→6.4.64** 升级后可能需要重新扫描媒体库。
- **Kodi / SmartTube / FLauncher** 不动，风险为零。
- 任一升级失败：立即 `adb install -r` 回滚到已备份的旧 APK。

### 不做的操作
- 不 root、不解锁 bootloader、不刷固件、不动系统分区、不卸载任何系统应用。
