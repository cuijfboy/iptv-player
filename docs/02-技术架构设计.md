# 02 · 技术架构设计

> 本文档定义 **分层、模块边界、接口契约、扩展点与并发/错误模型**。
> 目标：**分层合理 · 模块解耦 · 易扩展 · 可测试 · 可观测**。
> 相关：[01 需求与可行性](./01-需求与可行性.md) · [03 日志与诊断设计](./03-日志与诊断设计.md) · [04 开发计划与验收](./04-开发计划与验收.md)

---

## 1. 设计目标与原则

| 原则 | 落地手段 |
|---|---|
| **单向依赖** | 依赖只允许由外向内：`feature → domain ← data → platform`；domain/model 不依赖 Android |
| **依赖倒置** | domain 定义**端口（interface）**，data/platform 提供**适配器（implementation）** |
| **纯策略可测** | 选台、评分、故障转移、匹配等**决策逻辑为纯 Kotlin**，零 Android 依赖，可直接单测 |
| **平台能力隔离** | 播放器、数据库、网络、XML 解析被封装在平台模块，替换实现不影响上层 |
| **可插拔扩展** | 源、校验器、评分规则、播放引擎、EPG 源、日志 Sink 全部以"集合 + 接口"方式注册 |
| **异常不跨边界** | 模块间用 `AppResult<T>` 传递失败，禁止异常穿透模块边界 |
| **可观测内建** | 每个关键路径都有**事件码**；日志是架构的一等公民，而非事后补丁 |
| **可中断/可恢复** | 长任务（源刷新、EPG 导入）持久化进度，随时可被杀掉并续跑 |
| **性能预算前置** | UI/刷新/播放都有量化指标与埋点，回归可度量 |

## 2. 分层模型

```
┌──────────────────────────────────────────────────────────────────────────┐
│ L4 表现层 Presentation                                                    │
│   :app  ·  :feature:channels  :feature:player  :feature:epg               │
│   :feature:settings  :feature:wizard  ·  :core:ui  ·  :core:design        │
│   职责：View / Fragment / Activity / ViewModel / UiState（单向数据流）      │
│   规则：只调用 domain 的 UseCase；不直接触碰 Room / OkHttp / ExoPlayer      │
└───────────────────────────┬──────────────────────────────────────────────┘
                            │ 依赖 UseCase + 领域模型
┌───────────────────────────▼──────────────────────────────────────────────┐
│ L3 领域层 Domain                                                          │
│   :core:domain（纯 Kotlin）  ·  :core:model（纯 Kotlin）                   │
│   职责：UseCase / 领域模型 / 仓储端口(Port) / 纯策略(选源·评分·故障转移)     │
│   规则：零 Android 依赖；不出现 okhttp / room / media3 类型                 │
└───────────────────────────┬──────────────────────────────────────────────┘
                            │ 依赖倒置：domain 定义接口
┌───────────────────────────▼──────────────────────────────────────────────┐
│ L2 数据层 Data                                                            │
│   :core:data（仓储实现）  :core:database（Room）  :core:network（OkHttp）   │
│   职责：Repository 实现、DTO↔Entity↔Domain 映射、缓存与事务                 │
└───────────────────────────┬──────────────────────────────────────────────┘
                            │ 使用平台能力
┌───────────────────────────▼──────────────────────────────────────────────┐
│ L1 平台层 Platform                                                        │
│   :core:source（采集/解析/校验）  :core:epg（XMLTV）  :core:player（播放）   │
│   职责：将 Android/第三方能力适配为可替换的引擎实现                          │
└───────────────────────────┬──────────────────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────────────────┐
│ L0 基础设施 Common（被所有层依赖，自身不依赖任何业务）                       │
│   :core:common（AppResult/Logger 接口/Dispatcher/Clock/事件码）             │
│   :core:log（日志实现：内存环 + 文件 + logcat + 崩溃）                       │
└──────────────────────────────────────────────────────────────────────────┘
```

**关键解耦点**：*`FailoverPolicy` / `StreamSelector` / `ScoringRule` 是**纯 Kotlin 策略**（L3），`PlayerEngine` 是**平台适配器**（L1）*。因此"何时切源"可以脱离 Android 单测，"怎么播"可以整体替换（Media3 ⇄ libVLC ⇄ 未来引擎）。

**守护规则（CI 强制）**：

1. `:core:domain` / `:core:model` / `:core:common` 为 **`java-library`（Kotlin JVM）**，源码中出现 `android.` / `androidx.` 导入即 CI 失败；
2. `:feature:*` **不得**依赖 `:core:database` / `:core:network` / `core:source` / `core:epg`（只能经 domain 端口）；
3. 禁止循环依赖；用 Gradle 约定插件 + `dependency-analysis` 任务在 CI 校验。

**数据量估算**：频道 ≈ 1k、流 ≈ 5k、节目（7 天窗）≈ 10–30 万 → SQLite 完全胜任；节目表按 `[now-6h, now+48h]` 滚动窗口修剪，避免无限增长。

## 6. 关键流程设计

### 6.1 源刷新流水线（F1/F2，**全程本机**）

```
 Fetch ─▶ Parse ─▶ Normalize ─▶ Dedupe ─▶ Cap ─▶ Shallow ─▶ Deep ─▶ Score ─▶ Select ─▶ Persist
  (N源)   (M3U/TXT)  (URL/名称)  (url_hash) (4000) (可达性)  (可解码) (100分) (主+备)  (Room)
```

| 阶段 | 并发 | 超时 | 说明 | 事件码 |
|---|---|---|---|---|
| Fetch | 4 | 15 s/源，8 MB | 并行拉取；UTF-8 → GB18030 回退；失败不阻塞其他源 | `SRC_FETCH_OK/FAIL` |
| Parse | 串行 | – | M3U（`#EXTINF`/`#EXTVLCOPT`）与 TXT（`#genre#`、`名,url`）双格式 | `SRC_PARSE` |
| Normalize | 并行 | – | URL 规范化（scheme/host 小写、去默认端口、去 fragment）；名称全角→半角/去空白 | – |
| Dedupe | 串行 | – | 按 `url_hash` 去重；**按源交错**保留多样性 | `SRC_DEDUPE` |
| Shallow | 12 | 6 s | 清单可达 + master 变体（前 4）+ **直播边沿分片**（末片→首片） | `VAL_SHALLOW_*` |
| Deep | 6 | 12 s | Media3 `Probe` 解出真实 vcodec/acodec/分辨率 | `VAL_DEEP_*` |
| Score | 串行 | – | 100 分模型（下表） | `SRC_SCORE` |
| Select | 串行 | – | 每频道：最高分为主、次高分（≥55）为备胎，最多 3 条 | `SRC_SELECT` |
| Persist | 串行 | – | Room 事务批量 upsert；保留历史健康度 | `DB_UPSERT` |

**评分模型（100 分，可插拔 `ScoringRule`）**

| 维度 | 权重 | 规则 |
|---|---|---|
| 可用性 | 35 | 判定可播放即得 |
| 稳定性 | 25 | 按轮询失败率线性扣；媒体序号不前进再扣 10 |
| 设备兼容 | 20 | H.264=20；H.265=12；AV1=4；AC3/EAC3 −5；>1080p −3 |
| 画质/码率 | 10 | 1080p=10；720p=8；480p=5 |
| 防盗链 | 5 | 无需特殊头=5；需要则 3（并记录 UA/Referer） |
| 分片成功 | 2 | 边沿分片 2xx 加分 |

**增量与可恢复（关键设计）**

| 规则 | 值（可配置） | 说明 |
|---|---|---|
| 健康流 TTL | 24 h | 未过期则跳过复检 |
| 失败流 TTL | 6 h | 失败源更快重试 |
| 全量复扫 | 7 d | 兜底发现新增/变更 |
| 时间预算 | 20 min/次 | 超时优雅收尾并保存进度 |
| 断点续跑 | 每条结果即时落库 | 进程被杀后重入自动跳过已完成项 |
| **播放避让** | 播放中并发减半或暂停 | 不与播放抢带宽/CPU |
| 充电/网络约束 | WorkManager | 定时任务默认"非计量网络 + 充电（可选）" |

### 6.2 播放与故障转移状态机（F3/F4）

```
        ┌──────────┐  prepare()   ┌───────────┐  first frame  ┌──────────┐
        │  IDLE    │─────────────▶│ PREPARING │──────────────▶│ PLAYING  │
        └──────────┘              └─────┬─────┘               └────┬─────┘
             ▲                          │ error/timeout            │ stall(N s)
             │ release()                ▼                          ▼
        ┌────┴─────┐   give up     ┌───────────┐  switch stream  ┌──────────┐
        │ RELEASED │◀──────────────│ FAILOVER  │────────────────▶│ BUFFERING│
        └──────────┘               └───────────┘                 └──────────┘
```

`FailoverPolicy`（纯 Kotlin）决策输入 → 输出：

| 错误类别 | 判定 | 动作 |
|---|---|---|
| 4xx（403/404/410） | 源失效 | 立即 `SwitchTo(next)`，永久降权 |
| 超时 / 连接重置 | 瞬时 | `RetrySame`（≤1 次）→ 失败则 `SwitchTo(next)` |
| 解码失败 / 不支持编码 | 设备不兼容 | `SwitchTo(next)`，并标记该 codec 组合负面 |
| 缓冲停滞 ≥ N 秒 | 卡顿 | `Backoff(1s)` → `SwitchTo(next)` |
| 候选耗尽 | – | `GiveUp` + 提示"该频道暂时不可用" |

**看门狗**：独立协程，采样 `playbackPosition / bufferedPosition / isLoading`，静止超过阈值即触发上层决策；**换台时复用同一个 `PlayerEngine` 实例**（`stop() + prepare()`），降低起播耗时。

### 6.3 EPG 流程（F6）

```
EpgProvider.fetch() ─▶ 流式 Pull 解析（XmlPullParser） ─▶ 时间窗过滤 ─▶ ChannelMatcher 链 ─▶ Room 事务写入 ─▶ now/next 查询
     (可 gzip)            (不整文件入内存)              [now-6h,+48h]    id→name→fuzzy→alias→manual
```

- **匹配链可插拔**（E5）：① `tvg-id` 精确 → ② 归一化名称精确 → ③ 前缀/包含模糊 → ④ 人工别名表 → ⑤ 用户手动绑定（存 `epg_match='MANUAL'`，永不被覆盖）。
- **覆盖率可观测**：`EpgCoverage(matched, total, byGroup)` 写入诊断面板；P3 目标 ≥60%。
- **失败降级**：EPG 拉取失败保留旧数据，UI 只显示频道名，不阻塞播放。

## 7. 播放引擎设计（`:core:player`）

| 项 | 设计 |
|---|---|
| 主引擎 | **Media3 ExoPlayer 1.11.1**（`media3-exoplayer` + `-hls` + `-ui` + `-session` + 可选 `-exoplayer-rtsp`） |
| 抽象 | `PlayerEngine` 接口 + `PlayerEngineFactory`；引擎实现互不感知 |
| 直播调优 | `DefaultLoadControl`（小缓冲：起播 1.5 s / 目标 5 s）+ `setLiveConfiguration(targetOffsetMs = 3s)` 追边沿 |
| 缓存 | 可选 `SimpleCache`（直播场景收益有限，默认关闭，配置可开） |
| 容错 | `LoadErrorHandlingPolicy` 自定义重试；`Player.Listener.onPlayerError` 上报 |
| 音频 | 优先设备透传 AC3/EAC3（`AudioCapabilities` 探测）；P0 实测决定是否引入软解 |
| 显示 | `AspectRatioFrameLayout` FIT/FILL/ZOOM/FIXED_4_3 + 过扫描微调 |
| 系统 | `MediaSession`（media3-session）+ 音频焦点 + `setWakeMode` + 屏幕常亮 |
| 资源 | **单实例复用**；`release()` 于 `onStop`/`onDestroy`；避免多实例并存 |
| 可选兜底 | `:core:player-vlc`（libVLC 3.7.6，仅 `armeabi-v7a`，LGPL）→ **P0 后再定** |

## 8. UI 架构（Views + Leanback）

### 8.1 导航结构

```
WizardActivity（仅首次）
      │
      ├─▶ BrowseActivity ──┬─▶ ChannelListFragment（分组 Tab + 列表）
      │                    ├─▶ EpgGridFragment（时间网格）
      │                    └─▶ SettingsActivity ─▶ DiagnosticsFragment / LogViewFragment
      └─▶ PlayerActivity（全屏）
```

- **Activity 边界**：播放独立 Activity（生命周期清晰、避免与浏览页互相拖累）。
- **单向数据流**：`ViewModel` 暴露 `StateFlow<UiState>`，View 只渲染 + 发事件；`UiState` 为不可变 data class。

### 8.2 焦点与遥控（TV 核心）

| 关注点 | 做法 |
|---|---|
| 焦点可见性 | 焦点态用**缩放 + 描边 + 高亮**三重反馈；禁用系统默认高亮（`defaultFocusHighlightEnabled=false`）后自绘 |
| 焦点路由 | 显式 `nextFocusUp/Down/Left/Right`；列表用 `LinearLayoutManager` + `focusSearch` 兜底 |
| 按键映射 | `KEYCODE_DPAD_UP/DOWN`=换台；`KEYCODE_0..9`=跳台（带 2 s 缓冲）；`KEYCODE_MEDIA_*`=播放控制；`KEYCODE_BACK`=层级回退 |
| 过扫描安全区 | 5% 边距（`dimens` 统一），所有可点元素落在安全区内 |
| 10-foot 规范 | 正文 ≥ 18sp、标题 ≥ 28sp、焦点态最小 48dp 命中区 |
| Leanback 使用 | `BrowseSupportFragment`/`ListRow` 用于分组与卡片；列表虚拟化依赖 `RecyclerView`（658+ 台必须虚拟化） |

### 8.3 EPG 时间网格（自绘，性能关键）

- **自定义 `View` + `Canvas`**：二维虚拟化，**只绘制可视矩形内的节目块**；
- 横向 = 时间轴（`OverScroller` 惯性滚动），纵向 = 频道（与左侧频道栏联动）；
- 当前时间红线；节目块点击 → 详情/切台；`StaticLayout` 缓存文本布局；避免滚动中触发布局；
- 调试期用 `FrameMetricsAggregator` 采集帧耗时，写入 `metric` 表并在诊断页展示。

### 8.4 性能预算

| 指标 | 目标 |
|---|---|
| 频道列表滚动 | ≥ 50 fps |
| EPG 网格滚动 | ≥ 50 fps |
| 冷启动到可看 | ≤ 5 s |
| 换台（同引擎复用） | 平均 ≤ 3 s |
| 播放内存增量 | ≤ 150 MB |

## 10. 并发与线程模型

| 场景 | 调度器 | 并发上限 | 说明 |
|---|---|---|---|
| UI | `Dispatchers.Main.immediate` | – | 只做渲染与事件分发 |
| 网络（源/EPG） | `Dispatchers.IO` | Fetch 4 / Shallow 12 | `Semaphore` 背压 |
| 深度探测（Media3） | `Dispatchers.IO` + 专用单线程池 | 6 | Media3 实例较重，限制总量 |
| 解析（M3U/XMLTV） | `Dispatchers.Default` | CPU 核数 | 大文件流式，避免整文件入内存 |
| 数据库 | Room 自带执行器 | – | 批量事务写入 |
| 播放 | **单线程 confined dispatcher** | 1 | 引擎状态机串行化，避免竞态 |
| 看门狗 | `Dispatchers.Default` | 1 | 定时采样，超阈值发事件 |

**规则**：所有 `Dispatcher` 通过 `DispatcherProvider` 注入（可测）；长任务必须响应 `CancellationException`；不允许在 `GlobalScope` 起协程。

## 11. 错误处理与降级

| 层 | 责任 |
|---|---|
| platform | 把技术异常转成 `AppError`（带事件码），不抛给上层 |
| domain | 决策（重试/切换/放弃），不关心具体实现 |
| data | 事务一致性；写失败不破坏已有数据 |
| presentation | 把 `AppError.code` 映射为用户可读文案；**绝不**直接显示堆栈 |

**降级矩阵**

| 故障 | 降级行为 |
|---|---|
| EPG 不可用 | 隐藏节目信息，只显示频道名；播放不受影响 |
| 源刷新失败 | 保留上次数据，提示"使用缓存数据" |
| 某源全部候选不可用 | 频道标记 ⚠️，仍可尝试播放（可能临时恢复） |
| 播放引擎不支持该流 | 切备胎；若配置了 libVLC 则切换引擎 |
| 存储写入失败 | 内存态继续可用，下次启动重试 |

## 12. 安全与合规

- `usesCleartextTraffic="true"`（IPTV 源大量明文 HTTP）；
- **不内置源地址**；仅内置"源清单地址"，且可在设置中关闭；
- **日志脱敏**：URL 查询串中的 `token`/`key`/`pwd`/`sign` 等字段一律替换为 `***`（见 03 文档 §11）；
- 密钥口令不入库（ADR-003）；仓库公开，文档不含序列号/MAC/内网 IP；
- 若引入 libVLC（LGPL-2.1）：独立模块 + 动态链接 + 保留声明；**不引入 GPL/AGPL 代码**。
