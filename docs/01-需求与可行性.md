## 1. 需求复述

### 1.1 一句话

做一个**面向客厅 Sony Android TV 的开源 IPTV 播放器**：能**自动收集并定期刷新直播源**、能**流畅播放**、并有**遥控器友好的 TV 交互界面**；工程为 Android Studio 标准 Gradle 多模块项目，全部代码位于本仓库。

### 1.2 功能需求

| # | 需求 | 验收要点 | 阶段 |
|---|---|---|---|
| F1 | **播放源自动收集** | 从多个公开聚合列表（M3U / TXT）拉取候选频道；支持用户手动订阅 URL 或导入本地文件 | P1 |
| F2 | **播放源自动刷新** | 定时（WorkManager）+ 手动触发；两阶段校验（轻量可达 → 真实可解码）；评分排序；每频道主源 + 备胎；**增量、可断点续跑、可中断** | P2 |
| F3 | **视频播放** | 全屏直播；HLS(.m3u8) / HTTP-TS 为主，兼容 RTSP/RTMP；起播快、缓冲可调、卡顿自动重连 | P1 |
| F4 | **自动故障转移** | **分组验收（2026-09-21 god 批准）**：**有备胎组**——主源失败/超时/长时间无进度 → **5 s 内**切同频道备胎；**无备胎组**——`RetrySame`（≤1 次）→ **按需单频道复检**（`ResolveFresh`）→ **明确提示**"该频道暂时不可用"。连续失败降权。（依据：实测基线 417/579 频道只有 1 条流，"无备胎"是常态而非例外） | P1 |
| F5 | **频道浏览与切换** | 分组、列表、台标、收藏/隐藏/排序；遥控上/下换台、数字键跳台 | P1–P2 |
| F6 | **EPG 节目单** | XMLTV 拉取解析；按 tvg-id + 名称 + 别名匹配；now/next + 时间网格 | P2–P3 |
| F7 | **播放器 UI 交互** | 信息条（频道/台标/now-next/进度）、播放设置（宽高比/音轨/缓冲）、自动淡出、返回键层级一致 | P2–P3 |
| F8 | **设置与首启向导** | 源订阅管理、EPG 源管理、刷新策略、播放参数、诊断入口；首启「一键更新 → 开看」 | P2 |
| F9 | **持久化** | 频道/流/节目/订阅/设置/收藏/播放历史落库，冷启动即用 | P2 |
| F10 | **后台与系统集成** | 前台服务防冻结；MediaSession（遥控播放键）；保持屏幕常亮；网络变化重试 | P2–P3 |
| F11 | **工程化** | Android Studio 标准 Gradle 多模块；CI；签名 APK；`adb install -r` 升级 | P0 |
| F12 | **可观测 / 可排查** | 分级分类日志、落盘轮转、App 内诊断面板、一键导出诊断包、崩溃捕获、性能埋点 | **贯穿全程** |

### 1.3 明确不做（本期）

- ❌ **不内置任何频道源地址**：App 出厂不带源，源由公开聚合列表 + 用户订阅获得。
- ❌ 不做 DRM 绕过、付费内容、账号体系。
- ❌ 不做 DVB / UDP-IGMP 组播（运营商专网协议，普通局域网不可达）。
- ❌ **不依赖任何电视之外的服务端能力**（见 ADR-001）。
- ⏳ 录制、回看（catchup）、PiP、多设备分发 → P4 可选。

### 1.4 交付物

1. 可 `adb install` 到 Sony 电视的签名 Android TV APK（包名 `ilab.iptv.player`）；
2. Android Studio 可直接打开的 Gradle 多模块工程；
3. 文档：需求/架构/日志诊断/计划 + 背景资料；
4. 单元测试与测试夹具（fixtures）。

## 4. 可行性评估

### 4.1 总判断：**高可行**

三个先天优势（同类项目不具备）：

1. **源已在本机实测甄选**——不是"抄一份列表"，而是"这批源曾在这台电视上验证过可解码"，并带编码/分辨率/音轨元数据；
2. **每频道自带备胎与评分**——故障转移的数据结构现成，只差播放侧切换逻辑；
3. **设备约束已全部踩明**——ABI、内存、屏保冻结、明文 HTTP、AC3 风险，避免返工。

### 4.2 架构硬约束（ADR-001）：**App 运行期完全自给自足**

> **决策**：App 的所有核心功能（源采集、校验、EPG、播放、存储）**必须完全在电视本机完成**，不得依赖任何局域网服务器、云端服务或 CI 产物作为**运行前提**。
>
> **理由**：目标设备之外不具备可靠的能力支持；引入外部依赖会让"电视开机即用"变成"服务器挂了就看不了"。
>
> **推论**：
> - Mac/服务器侧 Python 管线**不进入运行路径**，仅作开发期参考（可选，见 ADR-002）；
> - "订阅源"是**用户可选的增强路径**（用户自己填 URL），不是默认前提；默认体验 = 内置聚合源清单 + 本机刷新；
> - EPG 同理：默认从公共 EPG 源直连拉取，不需要自建服务。

**ADR-002：Mac 侧 Python 管线的处置** → **不作为运行时依赖，仅作开发期可选工具**。若保留，置于 `tools/dev-pipeline/`，并在 README 明确标注"App 运行不依赖；仅用于离线调参/生成测试夹具"。

### 4.3 风险分级

| 等级 | 风险 | 对策 | 验证时点 |
|---|---|---|---|
| 🔴 高 | **AC3/EAC3 无声**（国内源常见） | P0 实测透传；不行则优先 AAC 源（lite 列表）+ Jellyfin ffmpeg 软解 + libVLC 兜底 | P0 |
| 🔴 高 | **构建链从零**（无 gradle / 无系统 JDK / 无 cmdline-tools） | P0 先跑通「空工程 → APK → adb 安装」 | P0 |
| 🟠 中 | **EPG 覆盖率仅 9%** | 多 EPG 源 + tvg-id 优先 + 别名表 + 用户手填；P3 目标 ≥60% | P3 |
| 🟠 中 | **3 GB 内存 / 老 SoC 卡顿** | Views + 虚拟化列表 + 自绘 EPG 网格 + 限制并发 + 播放器单实例 | P0/P3 |
| 🟠 中 | **换台速度**（HLS 物理下限 1.5–3 s） | 播放器复用 + 直播缓冲调优 + 失败快跳 + 数字键直跳 | P1 |
| 🟡 低 | 公共源随时失效 | 故障转移 + 周期复检 + 降权淘汰 | P2 |
| 🟡 低 | 32 位 ABI 限制可选库 | 纯 JVM 库优先（Media3 无 native） | P0 |
| 🟡 低 | 合规/版权 | App 不内置源；保留声明 | 持续 |
| 🟠 中 | **公开仓库泄露隐私** | 文档脱敏（序列号/MAC/内网 IP）；密钥不进仓（见 ADR-003） | 立即 |

**ADR-003：密钥策略** → 新建签名密钥，**密钥文件保存在仓库内**（`keystore/release.jks`，口令置于 `local.properties`/`gradle.properties` 且**不提交**，示例见 `keystore/README.md`）。因仓库为公开，**口令绝不入库**；如需 CI 签名，用 GitHub Secrets。
