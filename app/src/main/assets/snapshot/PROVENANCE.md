# 内置快照来源说明（channels.m3u）

卡：`SNAPSHOT-1`（内置快照：TV 验证过的清单打进 APK + 首启播种）。执行：temp `worker-stanley-snapshot`（Stanley），2026-09-22。
同目录的 `channels.m3u` 是 APK **出厂即带**的频道清单；首启（频道表为空）由 `RoomCatalogSeeder`
经 `DataModule` 播种进 Room，用户手动导入或联网刷新**不会被它覆盖**。

## 1. 内容

| 项 | 值 |
|---|---|
| 频道数 | **189**（一行一频道、一条流；按 `(name_key, group_key)` 无合并、无重复名） |
| 分组 | 央视 33 · 卫视 27 · 体育/赛事 2 · 港澳台 3 · 地方/其他 124 |
| 行属性 | 每行 `tvg-id` / `tvg-name` / `tvg-chno`（1..189）/ `group-title` / 显示名 |
| 排序 | 央视 → 卫视 → 体育 → 港澳台 → 地方，组内按频道名 |

## 2. 来源

- 原始清单：`dsh/iptv-repo/out/validated.m3u`（P2 交付的 658 条流 / 571 个频道，采集于 2026-09-21）。
- 该清单的聚合来源与上游站点清单见 `docs/05-过程记录/50-NET1网络策略专项.md` 与 `55-G7-1打包与集成测试.md` §6。
- 本快照是它的**子集**：只保留在电视上实测能起播、且首帧成本可接受的频道；并做了跨 host 去重与同名去重。

## 3. 电视实测（这是「能播」证据的来源）

| 项 | 值 |
|---|---|
| 设备 | Sony BRAVIA 4K VH21（Android 12 / API 31），`<TV-LAN-IP>:5555` |
| 日期 | 2026-09-22 |
| 手段 | `spike` 夹具 `PlaybackSpikeActivity`（与应用同一引擎族：Media3 `ExoPlayer` + `media3-exoplayer-hls`，TV 本机解码），逐 URL 起播并记录首帧成本/失败码 |
| 候选量 | 240 个 URL（`validated.m3u` 中 Mac 侧 `curl` 返回 200/206 的条目，按 host 轮转取样） |
| 单样本超时 | 第一轮 5 s（200 个）；补充轮 8 s（40 个）；另对第一轮失败的 42 条用 12 s **复测**（见下） |
| 结果 | **196 个在电视上出画面**（首帧中位 ~0.9 s，p90 ~4.0 s） |
| 本文件收录判据 | 电视实测 **outcome=ok 且首帧 ≤ 5000 ms**；再按显示名去重 |

**复测（用于归因，不改变收录判据）**：第一轮 5 s 超时的 42 条，用 12 s（应用自身的起播超时线）
复测后 **33 条能出画面**，但首帧 0.7–10.0 s ⇒ 这些是「**源慢**」而非「源死」；余 9 条 12 s 仍失败
（4 条超时、5 条 `ERROR_CODE_IO_BAD_HTTP_STATUS`，同一 URL 在 Mac 上返回 200）。

## 4. 已知失效或不可用（未收录）

- **`hlsztemgsplive.miguvideo.com:8080`（105 条）**：URL 里的 `msisdn` 令牌已过期，返回非标准状态码
  （Mac 侧 `curl` 605 / 电视侧 `ERROR_CODE_IO_BAD_HTTP_STATUS`）。
- **境外 CDN（`*.cloudfront.net`、`*.amagi.tv`、`*.akamaized.net` 等）**：电视侧多次超时或返回坏状态码，
  同一 URL 在 Mac 上可达 ⇒ 属**电视所在网络路径**问题，不是播放器问题。
- **Mac 侧本就不可达**（`000`/`403`/`404`/`418`，21 条）：未进入候选。

## 5. 没验证的事（不要当已验证）

- 长期稳定性：只测了「起播出画面」，没有跑长稳、没有跟踪单流在数小时后的失效。
- 地理位置/运营商变化：这些源多为地方台直链，换网络后可用性会变。
- 收录快照时每条流的首帧成本只测了 1 次（未做多次取中位）。
